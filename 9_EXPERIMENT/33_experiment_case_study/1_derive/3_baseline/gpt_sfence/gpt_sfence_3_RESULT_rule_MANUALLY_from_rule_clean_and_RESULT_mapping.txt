RULE 1: If SFENCE.VMA is executed in S-mode or M-mode when mstatus.TVM is 0, the instruction does not trap for lack of privilege.
RULE 2: If SFENCE.VMA is executed in U-mode, the instruction raises an illegal-instruction exception.
RULE 3: If SFENCE.VMA is executed in S-mode when mstatus.TVM is 1, the instruction raises an illegal-instruction exception.
RULE 6: If SFENCE.VMA is executed with rs1 = x0 and rs2 = x0, all previous stores already visible to the executing hart are ordered before all subsequent implicit address-translation memory references by that hart.
RULE 7: If SFENCE.VMA is executed with rs1 != x0 and rs2 = x0, all previous stores already visible to the executing hart are ordered before subsequent implicit address-translation memory references by that hart for the virtual address contained in rs1.
RULE 8: If SFENCE.VMA is executed with rs1 = x0 and rs2 != x0, all previous stores already visible to the executing hart are ordered before subsequent implicit address-translation memory references by that hart for address translations associated with the ASID contained in rs2.
RULE 9: If SFENCE.VMA is executed with rs1 != x0 and rs2 != x0, all previous stores already visible to the executing hart are ordered before subsequent implicit address-translation memory references by that hart for the virtual address contained in rs1 and the ASID contained in rs2.
RULE 13: If SFENCE.VMA is executed, its ordering effect applies only to subsequent implicit address-translation memory references made by the executing hart.
RULE 16: If SFENCE.VMA is executed, the instruction does not by itself order previous stores before subsequent explicit memory accesses.
RULE 18: If SFENCE.VMA is executed with a value in rs1 that is not a valid virtual address, the instruction does not raise an exception solely because of that invalid virtual-address value.
RULE 19: If SFENCE.VMA is executed with a value in rs2 whose bits exceed the implemented ASID width, those unimplemented ASID bits are ignored for the ASID-selective effect of the instruction.
RULE 20: If SFENCE.VMA is executed with rs2 != x0, the ASID used for the ASID-selective effect is the implemented ASID field value contained in rs2.
RULE 33: If SFENCE.VMA is executed while virtualization is active in VS-mode, the instruction raises a virtual-instruction exception unless permitted by the hypervisor virtualization controls.
