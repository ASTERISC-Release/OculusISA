You are given one KLEE extracted implementation path and its path summary for one RISC-V architectural feature.

Task:
Convert the given path into one or more atomic architectural rules.

Input format:
The input contains:

* Path number
* Path name
* Path condition
* Path outcome
* Natural language path summary

Important:
Use ONLY the given path and path summary.
Do NOT use external knowledge.
Do NOT use known bugs.
Do NOT infer unrelated behavior.

Rule requirements:
Each rule should become a single testable statement.
Each rule should be a separate atomic rule that expresses one architectural behavior or one event -> outcome relationship.
Each rule needs to be clear and detailed.
Extract ONLY explicit, testable, normative rules about architectural behavior.
A rule MUST describe behavioral semantics, not naming, encoding, or syntax.
Rules must describe architectural cause -> effect semantics, meaning event -> architectural outcome.
Each rule must include the architectural condition and the architectural outcome.
Each rule must be testable using architectural observations such as trap cause, CSR state, register state, or trap versus no trap behavior.
Each rule must begin with the word "RULE".

Output format:
Output only the rule or rules.
Do not give any introduction.
Do not give headings.
Do not give bullet points.
Do not include explanations.

Example output:
RULE: When a CY, IR, or HPMn bit in the mcountinhibit register is clear, the corresponding mcycle, minstret, or mhpmcountern register increments as usual.

Now convert the following path into rule form:

[PASTE ONE PATH HERE]
