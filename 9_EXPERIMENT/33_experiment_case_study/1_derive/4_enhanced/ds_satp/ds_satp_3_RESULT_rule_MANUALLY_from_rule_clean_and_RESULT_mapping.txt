RULE 2: If the current privilege mode is S-mode and mstatus.TVM is 1, an attempt to read or write satp raises an illegal-instruction exception.
RULE 3: If the current privilege mode is S-mode and mstatus.TVM is 0, read and write accesses to satp are permitted.
RULE 4: If the current privilege mode is VS-mode (V=1) and hstatus.VTVM is 1, an attempt to access satp (which accesses vsatp) raises a virtual-instruction exception.
RULE 6: If a write to satp specifies an unsupported MODE value, the entire write has no effect and no fields in satp are modified.
RULE 7: The number of implemented ASID bits (ASIDLEN) can be determined by writing all ones to the ASID field of satp and reading back; the bits that read as one indicate implemented writable bits, with the least-significant bits implemented first.
RULE 8: The maximum ASIDLEN is 9 when the MODE field is Sv32, and 16 when the MODE field is Sv39, Sv48, or Sv57.
RULE 9: The satp register is considered active when the effective privilege mode is S-mode or U-mode.
RULE 11: Changing satp.MODE from Bare to a paged mode or vice versa takes effect immediately, without requiring an SFENCE.VMA instruction.
RULE 12: Changing satp.ASID takes effect immediately, without requiring an SFENCE.VMA instruction.
RULE 13: When V=1, the vsatp CSR substitutes for satp; instructions that normally read or modify satp access vsatp instead.
RULE 15: When V=1, a write to satp (i.e., vsatp) with an unsupported MODE value is ignored; no write to vsatp is effected.
RULE 19: When satp.MODE is Bare, supervisor virtual addresses equal supervisor physical addresses, and no additional memory protection beyond PMP is applied.
