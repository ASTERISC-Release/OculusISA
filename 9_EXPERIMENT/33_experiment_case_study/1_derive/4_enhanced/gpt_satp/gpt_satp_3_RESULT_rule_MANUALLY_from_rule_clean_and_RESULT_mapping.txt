RULE 1: If a CSR instruction attempts to access satp while executing in U-mode with virtualization mode V=0, the instruction raises an illegal-instruction exception.
RULE 2: If a CSR instruction accesses satp while executing in M-mode, the access is permitted by the CSR privilege rules.
RULE 7: If virtualization mode V=1 and an instruction in VS-mode attempts to access CSR satp while hstatus.VTVM=1, the instruction raises a virtual-instruction exception.
RULE 11: If virtualization mode V=1, the HS-level satp retains its value while vsatp substitutes for satp.
RULE 13: If virtualization mode V=1 and a write to CSR satp attempts to write an unsupported MODE value, the write is ignored and no write to vsatp is effected.
RULE 15: If a permitted write to satp specifies an unsupported MODE value, the entire write has no effect and no field of satp is modified.
RULE 17: If satp.MODE=Bare, supervisor virtual addresses are equal to supervisor physical addresses.
RULE 18: If satp.MODE=Bare, satp provides no memory protection beyond physical memory protection.
RULE 25: If ASIDLEN is greater than zero, satp.ASID[ASIDLEN-1:0] is writable.
RULE 27: If Sv32 is the selected translation mode, the maximum architecturally defined ASID length is 9 bits.
RULE 28: If Sv39, Sv48, or Sv57 is the selected translation mode, the maximum architecturally defined ASID length is 16 bits.
RULE 31: If the effective privilege mode is neither S-mode nor U-mode, an address-translation algorithm execution must not begin using a value of satp.
RULE 34: If S-mode instruction fetch implicitly reads satp, the implicit read returns the same value that an explicit CSR read of satp would return in a sufficient privilege mode.
RULE 37: If satp.ASID changes, the change takes effect immediately without requiring an SFENCE.VMA.
RULE 80: If satp.MODE is read-only zero, the sstatus.SUM field is read-only zero.
