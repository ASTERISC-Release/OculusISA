RULE 1: If a CSR instruction attempts to access satp while executing in U-mode with virtualization mode V=0, the instruction raises an illegal-instruction exception.
RULE 2: If a CSR instruction accesses satp while executing in M-mode, the access is permitted by the CSR privilege rules.
RULE 3: If a CSR instruction attempts to read satp while executing in S-mode and mstatus.TVM=1, the instruction raises an illegal-instruction exception.
RULE 4: If a CSR instruction attempts to write satp while executing in S-mode and mstatus.TVM=1, the instruction raises an illegal-instruction exception.
RULE 5: If a CSR instruction reads satp while executing in S-mode and mstatus.TVM=0, the read is permitted by the CSR privilege rules.
RULE 6: If a CSR instruction writes satp while executing in S-mode and mstatus.TVM=0, the write is permitted by the CSR privilege rules and is subject to the WARL behavior of satp.
RULE 7: If virtualization mode V=1 and an instruction in VS-mode attempts to access CSR satp while hstatus.VTVM=1, the instruction raises a virtual-instruction exception.
RULE 8: If virtualization mode V=1 and an instruction in VS-mode reads CSR satp while hstatus.VTVM=0, the instruction reads vsatp instead of the HS-level satp.
RULE 9: If virtualization mode V=1 and an instruction in VS-mode writes CSR satp while hstatus.VTVM=0, the instruction writes vsatp instead of the HS-level satp.
RULE 10: If virtualization mode V=1 and an instruction in VU-mode attempts to access CSR satp, the instruction raises a virtual-instruction exception.
RULE 11: If virtualization mode V=1, the HS-level satp retains its value while vsatp substitutes for satp.
RULE 12: If virtualization mode V=1, the HS-level satp does not affect machine behavior except where the specification explicitly documents such an effect.
RULE 13: If virtualization mode V=1 and a write to CSR satp attempts to write an unsupported MODE value, the write is ignored and no write to vsatp is effected.
RULE 14: If a permitted CSR instruction writes satp, the MODE, ASID, and PPN fields are modified as one atomic CSR update.
RULE 15: If a permitted write to satp specifies an unsupported MODE value, the entire write has no effect and no field of satp is modified.
RULE 16: If a permitted write to a WARL field of satp specifies an unsupported value, the write does not raise an exception solely because the value is unsupported.
RULE 17: If satp.MODE=Bare, supervisor virtual addresses are equal to supervisor physical addresses.
RULE 18: If satp.MODE=Bare, satp provides no memory protection beyond physical memory protection.
RULE 19: If SXLEN=32 and satp.MODE=Sv32, supervisor and user virtual addresses are translated using the Sv32 page-based virtual-memory scheme.
RULE 20: If SXLEN=64 and satp.MODE=Sv39, supervisor and user virtual addresses are translated using the Sv39 page-based virtual-memory scheme.
RULE 21: If SXLEN=64 and satp.MODE=Sv48, supervisor and user virtual addresses are translated using the Sv48 page-based virtual-memory scheme.
RULE 22: If SXLEN=64 and satp.MODE=Sv57, supervisor and user virtual addresses are translated using the Sv57 page-based virtual-memory scheme.
RULE 23: If an implementation supports satp.MODE=Sv48, the implementation also supports satp.MODE=Sv39.
RULE 24: If an implementation supports satp.MODE=Sv57, the implementation also supports satp.MODE=Sv48.
RULE 25: If ASIDLEN is greater than zero, satp.ASID[ASIDLEN-1:0] is writable.
RULE 26: If a bit position in satp.ASID is not implemented, writing one to that bit and then reading satp does not return one for that ASID bit.
RULE 27: If Sv32 is the selected translation mode, the maximum architecturally defined ASID length is 9 bits.
RULE 28: If Sv39, Sv48, or Sv57 is the selected translation mode, the maximum architecturally defined ASID length is 16 bits.
RULE 29: If the effective privilege mode is S-mode, satp is active for address translation.
RULE 30: If the effective privilege mode is U-mode, satp is active for address translation.
RULE 31: If the effective privilege mode is neither S-mode nor U-mode, an address-translation algorithm execution must not begin using a value of satp.
RULE 32: If satp is active, an address-translation algorithm execution may begin using the current value of satp.
RULE 33: If a translation began while satp was active and satp later becomes inactive without a matching SFENCE.VMA, the translation is permitted to complete using the value of satp with which it began.
RULE 34: If S-mode instruction fetch implicitly reads satp, the implicit read returns the same value that an explicit CSR read of satp would return in a sufficient privilege mode.
RULE 35: If satp.MODE changes from Bare to a page-based mode, the change takes effect immediately without requiring an SFENCE.VMA.
RULE 36: If satp.MODE changes from a page-based mode to Bare, the change takes effect immediately without requiring an SFENCE.VMA.
RULE 37: If satp.ASID changes, the change takes effect immediately without requiring an SFENCE.VMA.
RULE 38: If software writes satp, the write does not order prior page-table updates before subsequent address translations.
RULE 39: If software writes satp, the write does not invalidate address-translation cache entries.
RULE 40: If satp.MODE=Sv32, the root page table physical address used by the translation algorithm is satp.PPN × 4096.
RULE 41: If satp.MODE=Sv39, satp.MODE=Sv48, or satp.MODE=Sv57, the root page table physical address used by the translation algorithm is satp.PPN × 4096.
RULE 42: If satp.MODE=Sv32, the address-translation algorithm uses two page-table levels and 4-byte PTE accesses.
RULE 43: If satp.MODE=Sv39, the address-translation algorithm uses three page-table levels and 8-byte PTE accesses.
RULE 44: If satp.MODE=Sv48, the address-translation algorithm uses four page-table levels and 8-byte PTE accesses.
RULE 45: If satp.MODE=Sv57, the address-translation algorithm uses five page-table levels and 8-byte PTE accesses.
RULE 46: If satp.MODE=Sv39 and a 64-bit instruction fetch address or load/store effective address has bits 63 through 39 not all equal to bit 38, address translation raises a page-fault exception for the original access type.
RULE 47: If satp.MODE=Sv48 and a 64-bit instruction fetch address or load/store effective address has bits 63 through 48 not all equal to bit 47, address translation raises a page-fault exception for the original access type.
RULE 48: If satp.MODE=Sv57 and a 64-bit instruction fetch address or load/store effective address has bits 63 through 57 not all equal to bit 56, address translation raises a page-fault exception for the original access type.
RULE 49: If a paged translation controlled by satp accesses a PTE and that PTE access violates a PMA or PMP check, the translation raises an access-fault exception corresponding to the original access type.
RULE 50: If a paged translation controlled by satp reads a PTE with V=0, the translation raises a page-fault exception corresponding to the original access type.
RULE 51: If a paged translation controlled by satp reads a PTE with R=0 and W=1, the translation raises a page-fault exception corresponding to the original access type.
RULE 52: If a paged translation controlled by satp reads a PTE with any reserved bit or reserved encoding set, the translation raises a page-fault exception corresponding to the original access type.
RULE 53: If a paged translation controlled by satp reaches a non-leaf PTE when no lower page-table level remains, the translation raises a page-fault exception corresponding to the original access type.
RULE 54: If a paged translation controlled by satp reaches a valid non-leaf PTE and a lower page-table level remains, the next page-table base address is PTE.PPN × 4096.
RULE 55: If a paged translation controlled by satp reaches a leaf PTE for a superpage and the PTE physical page number is insufficiently aligned for that superpage size, the translation raises a page-fault exception corresponding to the original access type.
RULE 56: If a paged translation controlled by satp fails the privilege check determined by the PTE U bit, the effective privilege mode, mstatus.SUM, and mstatus.MXR, the translation raises a page-fault exception corresponding to the original access type.
RULE 57: If a paged translation controlled by satp fails the Shadow Stack Memory Protection check, the translation raises an access-fault exception.
RULE 58: If a paged translation controlled by satp fails the access-permission check determined by the PTE R, W, and X bits, the translation raises a page-fault exception corresponding to the original access type.
RULE 59: If a paged translation controlled by satp finds PTE.A=0 and the Svade extension is implemented, the translation raises a page-fault exception corresponding to the original access type.
RULE 60: If a paged translation controlled by satp is for a store, finds PTE.D=0, and the Svade extension is implemented, the translation raises a page-fault exception corresponding to the original access type.
RULE 61: If a paged translation controlled by satp must update a PTE A or D bit and the required store to the PTE would violate a PMA or PMP check, the translation raises an access-fault exception corresponding to the original access type.
RULE 62: If a paged translation controlled by satp must update a PTE A bit and the PTE comparison succeeds, the implementation atomically sets the PTE A bit before completing the memory access.
RULE 63: If a paged translation controlled by satp is for a store, must update a PTE D bit, and the PTE comparison succeeds, the implementation atomically sets the PTE D bit before completing the store.
RULE 64: If a paged translation controlled by satp attempts an atomic PTE A or D bit update and the PTE comparison fails, the translation restarts from the PTE-read step.
RULE 65: If a paged translation controlled by satp succeeds, the physical page offset equals the virtual page offset.
RULE 66: If a successful paged translation controlled by satp is a superpage translation, the lower translated physical page-number bits are copied from the corresponding virtual page-number bits.
RULE 67: If a successful paged translation controlled by satp reaches a leaf PTE, the upper translated physical page-number bits are copied from the corresponding PTE physical page-number bits.
RULE 68: If a paged translation controlled by satp performs implicit accesses to address-translation data structures, each implicit access is performed using the PTE width of the selected translation mode.
RULE 69: If an implementation performs implicit reads of translation data structures for satp, it must read only data structures pointed to by the current satp value or by a subsequent valid translation data-structure entry.
RULE 70: If an implicit address-translation access for satp is performed speculatively, that speculative access must not raise an exception.
RULE 71: If a speculative paged translation controlled by satp updates PTE state, it must not set a PTE dirty bit.
RULE 72: If a speculative paged translation controlled by satp would create an address-translation cache entry invalidated by an SFENCE.VMA executed since the speculative translation began, that cache entry must not be created.
RULE 73: If an address-translation cache entry is used to satisfy an implicit PTE read for a translation controlled by satp, the entry must either match the ASID loaded from satp for that translation or be associated with a global mapping.
RULE 74: If an address-translation cache is used, the cache must appear private to the hart, and the meaning of an ASID from satp is local to that hart.
RULE 75: If software modifies an in-memory translation for a virtual address and ASID without executing a subsuming SFENCE.VMA, a subsequent translation controlled by satp may use any translation for that virtual address and ASID that was valid at any time since the last subsuming SFENCE.VMA.
RULE 76: If a previous translation for a virtual address used a virtual-address width different from the width currently selected by satp.MODE and no subsuming SFENCE.VMA has occurred, a subsequent translation for the same virtual address and ASID may use that previous translation.
RULE 77: If a previous global translation for a virtual address used a virtual-address width different from the width currently selected by satp.MODE and no subsuming SFENCE.VMA has occurred, a subsequent translation for the same virtual address may use that previous global translation regardless of the current ASID.
RULE 78: If SFENCE.VMA executes while virtualization mode V=0, the instruction applies to memory-management data structures controlled by the HS-level satp.
RULE 79: If SFENCE.VMA executes while virtualization mode V=1, the instruction applies to memory-management data structures controlled by vsatp rather than the HS-level satp.
RULE 80: If satp.MODE is read-only zero, the sstatus.SUM field is read-only zero.
RULE 81: If satp.MODE=Bare and the effective privilege mode is less privileged than M-mode, a shadow stack instruction raises a store/AMO access-fault exception.
RULE 82: If menvcfg.PBMTE=1, the Svpbmt extension is available for S-mode address translation through page tables pointed to by satp.
RULE 83: If menvcfg.PBMTE=0, S-mode address translation through page tables pointed to by satp behaves as though the Svpbmt extension were not implemented.
