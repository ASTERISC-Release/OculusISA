Bug criteria:
Report a bug only when all of the following are true:

1. The QEMU source code shows a concrete implementation behavior.
2. Your pretrained RISC-V specification knowledge gives a concrete expected architectural behavior.
3. The implementation behavior conflicts with the expected architectural behavior.
4. The mismatch is architecturally observable through trap versus no trap behavior, trap cause, CSR state, register state, memory state, or address-translation behavior.
5. A minimal RISC-V assembly test could expose the mismatch.

Do not report a bug when:
The source code is incomplete.
The relevant helper function is missing.
The behavior depends on code not included in the input.
The behavior is implementation-defined.
The behavior is unspecified.
The behavior is only a performance issue.
The behavior only affects internal QEMU state with no architectural observation.
The source code is conservative but architecturally allowed.
The expected behavior is not clear from your pretrained RISC-V knowledge.
