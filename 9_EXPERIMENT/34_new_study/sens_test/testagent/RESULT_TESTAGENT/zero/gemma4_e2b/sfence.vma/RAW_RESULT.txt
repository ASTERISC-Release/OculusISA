# Test Case Rule: RULE 1: When TVM=1, attempting to execute an SFENCE.VMA instruction while executing in S-mode raises an illegal-instruction exception.
##### ASSEMBLY #####
li x10, 1
csrw mstatus, 20, 1
call machine_to_supervisor
addi x1, x0, 0
sret
call machine_to_supervisor
sret
sret
# Result: mcause = 2

# Test Case Rule: RULE 2: When TVM=0, attempting to execute an SFENCE.VMA instruction is permitted in S-mode.
##### ASSEMBLY #####
li x10, 0
csrw mstatus, 20, 0
call machine_to_supervisor
addi x1, x0, 0
sret
call machine_to_supervisor
addi x1, x1, 0x1000000000000000
sret
csrr t0, x1, 0
sfence.vma x1, x1
sret
# Result: x1 = 0

# Test Case Rule: RULE 3: If the value held in rs1 of an SFENCE.VMA instruction is not a valid virtual address, no exception is raised by the SFENCE.VMA instruction.
##### ASSEMBLY #####
call machine_to_supervisor
addi x1, x0, 0x1000000000000000
sret
call machine_to_supervisor
addi x1, x0, 0x1000000000000000
sfence.vma x1, x1
sret
# Result: x1 = 0x1000000000000000

# Test Case Rule: RULE 4: For an SFENCE.VMA instruction where rs2 ≠ x0, bits SXLEN-1:ASIDMAX of the value held in rs2 are reserved for future standard use.
##### ASSEMBLY #####
addi x1, x0, 1
addi x2, x0, 0x1000000000000000
sret
call machine_to_supervisor
sfence.vma x1, x2
sret
# Result: x1 = 0

# Test Case Rule: RULE 5: Changing satp.MODE from Bare to other modes and vice versa takes effect immediately, without the need to execute an SFENCE.VMA instruction.
