REGISTER: mseccfg
SUMMARY: The mseccfg CSR is a machine‑mode 64‑bit read/write register that configures security controls such as enabling user or supervisor access to the seed CSR (USEED, SSEED), PMP locking and mode‑specific behavior (RLB, MML, MMWP), pointer‑masking (PMM), and extension enable bits (MLPE). In Machine mode the register imposes no restrictions on seed CSR accesses, whereas in User or Supervisor modes a read‑write seed CSR is allowed only if the corresponding USEED or SSEED bit is set; any other seed‑CSR access or access from lower privilege modes triggers an illegal‑instruction exception. The RLB bit determines whether locked PMP rules can be modified, and when MML is set PMP entries become sticky and mode‑specific (M‑mode‑only or S/U‑mode‑only), causing illegal‑instruction or access‑fault exceptions for disallowed accesses. Pointer‑masking is controlled by the PMM field, MLPE enables Zicfilp in M‑mode, and writes to undefined fields or attempts to read/write mseccfg from non‑machine modes also raise illegal‑instruction exceptions (mcause = 2).

REGISTER: mstatus
SUMMARY: The mstatus CSR holds the machine‑mode architectural state, including global interrupt enables, current and previous privilege modes (MPP, MPP, MPIE, MIE, etc.), virtualization controls (V, MPV, MPRV), memory‑access modifiers (MXR, SUM, TSR, TVM, TW), endianness fields (MBE, SBE, UBE), XLEN configuration (SXL, UXL), and the dirty‑state bits for floating‑point, vector, and other extensions (FS, VS, XS) summarized by the read‑only SD bit. It is readable and writable only in machine mode; any access from a lower privilege and any attempt to execute or access vector or floating‑point instructions or CSRs when the corresponding VS or FS field is Off also raise an illegal‑instruction exception. Executing an instruction that can modify extension state automatically changes the relevant status field from Initial or Clean to Dirty, and a Dirty VS or FS forces SD = 1 (otherwise SD reflects any dirty extension). Trap entry and return instructions (xRET, MRET, SRET) update the privilege‑mode fields, interrupt‑enable bits, and virtualization fields as defined, while bits such as TSR, TVM, and TW impose additional legality restrictions on SRET, satp access, and user‑mode instruction fetches.

REGISTER: satp
SUMMARY: The satp CSR controls supervisor virtual‑memory translation by holding a MODE field that selects the translation scheme (or Bare), an ASID field identifying the address space, and a PPN field pointing to the root page‑table physical page. MODE is read‑only zero when the implementation does not support any translation mode; otherwise it is a WARL field, ASID is writable up to the implementation‑defined ASIDLEN bits, and PPN is writable only when a supported MODE is selected. The register is readable and writable in S‑mode unless the mstatus TVM bit is set, in which case any S‑mode read, write, or execution of SFENCE.VMA/SINVAL.VMA causes an illegal‑instruction exception; M‑mode (and HS‑mode) may always access it, while U‑mode accesses are illegal. Writes of an unsupported MODE are ignored, and changes to MODE or ASID take effect immediately without requiring SFENCE.VMA or imposing ordering constraints on page‑table updates.

REGISTER: scounteren
SUMMARY: scounteren is a supervisor‑read/write CSR that enables U‑mode execution to read the cycle (CY), time (TM), instruction‑retired (IR), and hardware performance‑monitor (HPM) counters. A cleared bit for a given counter causes an illegal‑instruction exception when that counter is accessed in U‑mode, while a set bit permits access only if the corresponding bit in mcounteren is also set; read‑only‑zero bits raise an exception on the counter read itself. Accessing scounteren from M‑mode or HS‑mode never raises an exception, whereas U‑mode accesses raise illegal‑instruction unless the V bit is 1, in which case reads and writes succeed and return the previously written value. Writes to any scounteren bit are reflected on subsequent reads in M‑mode.
