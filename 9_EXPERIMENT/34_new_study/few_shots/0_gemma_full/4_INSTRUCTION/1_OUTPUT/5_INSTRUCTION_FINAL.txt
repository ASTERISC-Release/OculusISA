INSTRUCTION: CSRRWI
FORMAT: csrrwi rd, csr, zimm5
RULE 1: If the CSRRWI instruction is executed, then the specified CSR is updated with the immediate value and the previous value of the CSR is written to the destination register.
RULE 2: The CSRRWI instruction updates the specified CSR using an XLEN-bit value obtained by zero-extending the 5-bit unsigned immediate field encoded in the rs1 field.
RULE 3: The CSRRWI instruction reads the old value of the CSR, zero-extends it to XLEN bits, and writes it to integer register rd.
RULE 4: If the destination register rd is x0, the CSRRWI instruction shall not read the CSR and shall not cause any side effects that might occur on a CSR read.
RULE 5: If the CSRRWI instruction is executed with rd not equal to x0, then the destination register rd shall contain the value of the specified CSR prior to the write.
RULE 6: The CSRRWI instruction shall write to the specified CSR regardless of whether the destination register rd is x0.
RULE 7: If the CSRRWI instruction writes to a CSR, then all fields within that CSR that are defined to have side effects upon being written must trigger those side effects.
RULE 8: If the CSRRWI instruction's rd field is set to a register r other than x0, then r is updated with the original value of the CSR.

INSTRUCTION: FCVT.W.D
FORMAT: fcvt.w.d rd, fs1, rm
RULE 1: FCVT.W.D converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 2: FCVT.W.D rounds the result according to the rm field.
RULE 3: FCVT.W.D sign-extends the 32-bit result when executed on an RV64 system.
RULE 4: If the input value for FCVT.W.D is outside the range of representable signed 32-bit integers, then the result is the same as the behavior for FCVT.int.S for the same out-of-range input.

INSTRUCTION: SFENCE.VMA
FORMAT: sfence.vma rs1, rs2
RULE 1: An SFENCE.VMA instruction executed in S-mode while TVM=1 must raise an illegal-instruction exception.
RULE 2: If an SFENCE.VMA instruction is executed in S-mode while TVM=0, then it must execute without raising an exception.
RULE 3: If the value held in rs1 is not a valid virtual address, the SFENCE.VMA instruction has no effect and no exception is raised.
RULE 4: An attempt to execute SFENCE.VMA in U-mode always raises an illegal-instruction exception.
RULE 5: An attempt to execute SFENCE.VMA in S-mode or HS-mode when mstatus.TVM=1 raises an illegal-instruction exception.
RULE 6: An attempt to execute SFENCE.VMA in VU-mode raises a virtual-instruction exception.
RULE 7: An attempt to execute SFENCE.VMA in VS-mode when hstatus.VTVM=1 raises a virtual-instruction exception.
RULE 8: An attempt to execute SFENCE.VMA in VS-mode while VTVM=1 MUST raise a virtual-instruction exception.
RULE 9: Attempts to execute the SFENCE.VMA instruction in VU-mode raise a virtual-instruction exception.
RULE 10: Attempts to execute the SFENCE.VMA instruction in VS-mode raise a virtual-instruction exception when hstatus.VTVM=1.

INSTRUCTION: VLE32FF.V
FORMAT: vle32ff.v vd, (rs1), vm
RULE 1: The VLE32FF.V instruction executes as a regular load, except that it will only take a trap caused by a synchronous exception on element 0.
RULE 2: If element 0 of the VLE32FF.V instruction raises an exception, the vector length vl is not modified and the trap is taken.
RULE 3: If an element greater than 0 of the VLE32FF.V instruction raises an exception, the corresponding trap is not taken and the vector length vl is reduced to the index of the element that would have raised the exception.
RULE 4: If vstart = 0 and vl > 0, the VLE32FF.V instruction must process at least one element.
RULE 5: When the VLE32FF.V instruction takes a trap due to an interrupt, implementations should not reduce vl and should instead set a vstart value.
RULE 6: When the VLE32FF.V instruction would trigger a debug data-watchpoint trap on an element after the first, implementations should not reduce vl but instead should trigger the debug trap.
