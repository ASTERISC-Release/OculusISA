RULE 1: If a shadow stack instruction raises an access-fault, page-fault, or guest-page-fault exception, then the reported exception cause is a store/AMO access fault, a store/AMO page fault, or a store/AMO guestpage fault.
RULE 2: If a shadow stack instruction is executed, the reported instruction type is always as though it were a store or AMO.
RULE 3: If a shadow stack instruction accesses a page that is not designated as a shadow stack page and is not marked as read-only, then a store/AMO access-fault exception is invoked.
RULE 4: If a shadow stack instruction accesses a read-only page, then a store/AMO page-fault exception will be triggered.
RULE 5: If a shadow stack instruction attempts to access a page marked read-write, read-writeexecute, read-execute, or execute-only, then a store/AMO access-fault exception is invoked.
RULE 6: If a shadow stack instruction accesses memory that is not idempotent, then a store/AMO access-fault exception is invoked.
RULE 7: If a shadow stack instruction accesses memory, and the PMP does not provide read-write permissions or the accessed memory is not idempotent, then a store/AMO access-fault exception is raised.
RULE 8: If an SSPUSH / C.SSPUSH / SSPOPCHK / C.SSPOPCHK instruction is executed and the virtual address in ssp is not XLEN aligned, then a store/AMO access-fault exception is caused.
RULE 9: If a shadow stack instruction accesses memory and the G-stage page table does not have read-write permission for the accessed memory, then a store/AMO guest-page-fault exception is raised.
RULE 10: If the SSAMOSWAP.W/D instruction is executed, then the PMA of the accessed memory range must provide AMOSwap level support.
