RULE 1: Instruction execution of SFENCE.VMA causes implicit reads and writes to memory-management data structures.
RULE 2: Executing an SFENCE.VMA instruction guarantees that any previous stores already visible to the current RISC-V hart are ordered before certain implicit references by subsequent instructions in that hart to the memory-management data structures.
RULE 3: Executing an SFENCE.VMA instruction invalidates entries in the address-translation cache associated with a hart.
RULE 4: Executing an SFENCE.VMA instruction flushes any local hardware caches related to address translation.
RULE 5: If rs1 equals x0 and rs2 equals x0, the SFENCE.VMA instruction orders all reads and writes made to any level of the page tables for all address spaces and invalidates all address-translation cache entries for all address spaces.
RULE 6: If rs1 equals x0 and rs2 is not equal to x0, the SFENCE.VMA instruction orders all reads and writes made to any level of the page tables, but only for the address space identified by integer register rs2, and invalidates all address-translation cache entries matching the address space identified by integer register rs2, except for entries containing global mappings.
RULE 7: If rs1 is not equal to x0 and rs2 equals x0, the SFENCE.VMA instruction orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for all address spaces, and invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 8: If rs1 is not equal to x0 and rs2 is not equal to x0, the SFENCE.VMA instruction orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for the address space identified by integer register rs2, and invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 and that match the address space identified by integer register rs2, except for entries containing global mappings.
RULE 9: If the value held in rs1 is not a valid virtual address, the SFENCE.VMA instruction has no effect and raises no exception.
RULE 10: If the implementation makes satp .MODE read-only zero (always Bare), attempting to execute an SFENCE.VMA instruction may raise an illegal-instruction exception.
RULE 11: No SFENCE.VMA is required after enabling or disabling pointer masking.
