RULE 1: When mstateen0 .CTR is 0 and the privilege mode is less privileged than M-mode, an attempt to access sctrctl, vsctrctl, sctrdepth, or sctrstatus raises an illegal-instruction exception.
RULE 2: When mstateen0 .CTR is 0 and the privilege mode is less privileged than M-mode, an attempt to access sireg* when siselect is in the range 0x200 through 0x2FF raises an illegal-instruction exception.
RULE 3: When mstateen0 .CTR is 0 and the privilege mode is less privileged than M-mode, an attempt to access vsireg* when vsiselect is in the range 0x200 through 0x2FF raises an illegal-instruction exception.
RULE 4: When mstateen0 .CTR is 0 and the privilege mode is less privileged than M-mode, execution of the SCTRCLR instruction raises an illegal-instruction exception.
RULE 5: When hstateen0 .CTR is 0, VS-mode accesses to supervisor CTR state (sctrctl, sctrstatus, sireg* (vsireg*)) raise a virtual-instruction exception.
RULE 6: When mstateen0 .CTR is 1 and hstateen0 .CTR is 1, VS-mode accesses to supervisor CTR state behave as described in Section 7.2 and Section 11.2.
RULE 7: When mstateen0 .CTR is 1 and hstateen0 .CTR is 0, VS-mode accesses to supervisor CTR state and VSmode execution of SCTRCLR raise a virtual-instruction exception.
RULE 8: When siselect holds a value in the range 0x40-0x5F and menvcfg .CDE = 0, an attempt to access any sireg* raises an illegal-instruction exception.
RULE 9: When siselect holds a value in the range 0x40-0x5F and menvcfg .CDE = 0, an attempt to access sireg3 or sireg6 raises an illegal-instruction exception.
RULE 10: When siselect holds a value in the range 0x40-0x5F and menvcfg .CDE = 0, an attempt to access sireg4 or sireg5 when XLEN = 64 raises an illegal-instruction exception.
RULE 11: When siselect holds a value in the range 0x40-0x5F and siselect = 0x41, an attempt to access sireg* raises an illegal-instruction exception.
RULE 12: When siselect holds a value in the range 0x40-0x5F and the counter selected by siselect is not delegated to S-mode (the corresponding bit in mcounteren = 0), an attempt to access sireg* raises an illegal-instruction exception.
RULE 13: If any extension upon which the underlying counter state depends for a given siselect and sireg* combination is not implemented, an attempt from M or S mode to access the given state through sireg* raises an illegal-instruction exception.
RULE 14: If the H extension is implemented, attempts from VS-mode or VU-mode to directly access vsiselect or vsireg* raise a virtual-instruction exception.
RULE 15: If the H extension is implemented, an attempt from VS-mode to access any sireg* (really vsireg*) raises a virtual-instruction exception if menvcfg .CDE = 0.
RULE 16: If the H extension is implemented, an attempt from VS-mode to access any sireg* (really vsireg*) raises a virtual-instruction exception if menvcfg .CDE = 1.
RULE 17: When attempted access to sctrdepth from VS-mode or VU-mode, a virtual-instruction exception is raised, unless CTR state enable access restrictions apply.
RULE 18: When CTR is active (current privilege mode enabled for recording and not frozen), qualified control transfers update the Entry Registers at logical entry 0.
RULE 19: When CTR is active, recorded transfers update the ctrsource .V bit to 1.
RULE 20: When CTR is active, qualified control transfers push older entries down the stack; the record previously in logical entry 0 moves to logical entry 1, the record in logical entry 1 moves to logical entry 2, and so on.
RULE 21: If the CTR buffer is full, the oldest recorded entry is lost.
RULE 22: When an SCTRCLR instruction is executed, all CTR Entry Registers are zeroed, and the CTR cycle counter and CCV are zeroed.
RULE 23: After SCTRCLR, any subsequent read of ctrsource, ctrtarget, or ctrdata that precedes the next qualified control transfer will return the value 0.
RULE 24: The first recorded transfer following SCTRCLR will have ctrdata .CCV=0.
RULE 25: When the optional x ctrctl .RASEMU bit is implemented and set to 1, indirect and direct calls are recorded as normal.
RULE 26: When x ctrctl .RASEMU is set to 1, function returns pop the most recent call by decrementing the WRPTR then invalidating the WRPTR entry (by setting ctrsource.V=0).
RULE 27: When x ctrctl .RASEMU is set to 1, co-routine swaps affect both a return and a call, overwriting logical entry 0 and not modifying WRPTR.
RULE 28: When x ctrctl .RASEMU is set to 1, other transfer types are inhibited.
RULE 29: When x ctrctl .RASEMU is set to 1, transfer type filtering bits and external trap enable bits are ignored.
RULE 30: When a trap occurs between enabled privilege modes, it is recorded as normal.
RULE 31: When a trap occurs from a disabled privilege mode to an enabled privilege mode, ctrsource .PC is 0.
RULE 32: When a trap occurs from an enabled mode to a disabled mode (external trap), it is not recorded by default.
RULE 33: When a trap return occurs between enabled privilege modes, it is recorded as normal, and ctrtarget .PC is 0.
RULE 34: When a trap return occurs from a disabled mode to an enabled mode, it is not recorded.
RULE 35: External trap recording depends on the external trap enable bits for the target mode and all intervening modes.
RULE 36: For records of external traps, ctrtarget .PC is 0.
RULE 37: If external trap recording is implemented, mctrctl .MTE and sctrctl .STE must be implemented, while vsctrctl .STE must be implemented if the H extension is implemented.
RULE 38: When an interrupt i traps to S-mode, it occurs if either the current privilege mode is S and SIE is set, or the current privilege mode has less privilege than S-mode, and bit i is set in both sip and sie.
RULE 39: Interrupts to S-mode take priority over any interrupts to lower privilege modes.
RULE 40: When reading or writing any implemented field of sip/sie, or writing any writable field of sip/sie, effects a read or write of the homonymous field of mip/mie.
