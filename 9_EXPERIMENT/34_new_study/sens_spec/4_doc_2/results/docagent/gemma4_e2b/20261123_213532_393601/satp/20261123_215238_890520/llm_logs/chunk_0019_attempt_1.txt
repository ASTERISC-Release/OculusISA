RULE 1: If satp .MODE is read-only zero (always Bare), the implementation may make FIOM read-only zero.
RULE 2: PBMTE controls whether the Svpbmt extension is available for use in S-mode and G-stage address translation, which involves page tables pointed to by satp or hgatp.
RULE 3: When PBMTE is set to 1, Svpbmt is available for S-mode and G-stage address translation.
RULE 4: When PBMTE is set to 0, the implementation behaves as though Svpbmt were not implemented.
RULE 5: If Svpbmt is not implemented, PBMTE is read-only zero.
RULE 6: For implementations with the hypervisor extension, henvcfg .PBMTE is read-only zero if menvcfg .PBMTE is zero.
RULE 7: ADUE controls whether hardware updating of PTE A/D bits is enabled for S-mode and G-stage address translations when the Svadu extension is implemented.
RULE 8: When ADUE is set to 1, hardware updating of PTE A/D bits is enabled during S-mode address translation, and the implementation behaves as though the Svade extension were not implemented for S-mode address translation.
RULE 9: When ADUE is set to 0, the implementation behaves as though Svade were implemented for S-mode and G-stage address translation.
RULE 10: If the Svadu extension is not implemented, ADUE is read-only zero.
RULE 11: After changing menvcfg .PBMTE, executing an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 suffices to synchronize address-translation caches with respect to the altered interpretation of page-table entries' PBMT fields, when the hypervisor extension is implemented.
