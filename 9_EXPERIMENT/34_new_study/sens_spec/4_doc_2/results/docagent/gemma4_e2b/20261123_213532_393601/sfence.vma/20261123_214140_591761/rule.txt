RULE 1: SFENCE.VMA does not order store operations relative to other instructions that order stores such as FENCE.I
RULE 2: If executing in S-mode and TVM is 1, then executing SFENCE.VMA results in an illegal-instruction exception
RULE 3: If executing in S-mode and TVM is 0, then executing SFENCE.VMA is permitted
RULE 4: If menvcfg.ADUE is changed, executing SFENCE.VMA with rs1 = x0 and rs2 = x0 synchronizes address-translation caches with respect to the altered interpretation of page-table entries' A/D bits.
RULE 5: When PMP settings are modified, M-mode software must execute SFENCE.VMA with rs1 = x0 and rs2 = x0 after the PMP CSRs are written.
RULE 6: Instruction execution of SFENCE.VMA causes implicit reads and writes to memory-management data structures.
RULE 7: Executing an SFENCE.VMA instruction guarantees that any previous stores already visible to the current RISC-V hart are ordered before certain implicit references by subsequent instructions in that hart to the memory-management data structures.
RULE 8: Executing an SFENCE.VMA instruction invalidates entries in the address-translation cache associated with a hart.
RULE 9: Executing an SFENCE.VMA instruction flushes any local hardware caches related to address translation.
RULE 10: If rs1 equals x0 and rs2 equals x0, the SFENCE.VMA instruction orders all reads and writes made to any level of the page tables for all address spaces and invalidates all address-translation cache entries for all address spaces.
RULE 11: If rs1 equals x0 and rs2 is not equal to x0, the SFENCE.VMA instruction orders all reads and writes made to any level of the page tables, but only for the address space identified by integer register rs2, and invalidates all address-translation cache entries matching the address space identified by integer register rs2, except for entries containing global mappings.
RULE 12: If rs1 is not equal to x0 and rs2 equals x0, the SFENCE.VMA instruction orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for all address spaces, and invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 13: If rs1 is not equal to x0 and rs2 is not equal to x0, the SFENCE.VMA instruction orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for the address space identified by integer register rs2, and invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 and that match the address space identified by integer register rs2, except for entries containing global mappings.
RULE 14: If the value held in rs1 is not a valid virtual address, the SFENCE.VMA instruction has no effect and raises no exception.
RULE 15: If the implementation makes satp .MODE read-only zero (always Bare), attempting to execute an SFENCE.VMA instruction may raise an illegal-instruction exception.
RULE 16: No SFENCE.VMA is required after enabling or disabling pointer masking.
RULE 17: When executed in order (but not necessarily consecutively) by a single hart, the sequence SFENCE.W.INVAL, SINVAL.VMA, and SFENCE.INVAL.IR has the same effect as a hypothetical SFENCE.VMA instruction in which the values of rs1 and rs2 for the SFENCE.VMA are the same as those used in the SINVAL.VMA, reads and writes prior to the SFENCE.W.INVAL are considered to be those prior to the SFENCE.VMA, and reads and writes following the SFENCE.INVAL.IR are considered to be those subsequent to the SFENCE.VMA.
RULE 18: The SINVAL.VMA instruction invalidates any address-translation cache entries that an SFENCE.VMA instruction with the same values of rs1 and rs2 would invalidate.
RULE 19: If bit FIOM is set to one in henvcfg, FENCE instructions executed when V=1 are modified so the requirement to order accesses to device I/O implies also the requirement to order main memory accesses.
RULE 20: When V=0, SFENCE.VMA orders stores only to HS-level address-translation structures with subsequent HS-level address translations, when the virtual-address argument is an HS-level virtual address and the ASID argument is an HS-level ASID.
RULE 21: When V=1, SFENCE.VMA orders stores only to the VS-level address-translation structures with subsequent VS-stage address translations for the same virtual machine, when the virtual-address argument is a guest virtual address within the current virtual machine, the ASID argument is a VS-level ASID within the current virtual machine, and hgatp.VMID is the same as when SFENCE.VMA executed.
RULE 22: If the instruction SFENCE.VMA is executed, the execution occurs in Supervisor mode.
