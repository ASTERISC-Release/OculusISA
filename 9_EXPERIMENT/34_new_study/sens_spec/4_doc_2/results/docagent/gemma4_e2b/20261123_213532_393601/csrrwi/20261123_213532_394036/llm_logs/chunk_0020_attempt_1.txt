RULE 1: When attempting to access an `mireg*` while `miselect` holds a number in an allocated and implemented range, the resulting behavior is defined by the extension.
RULE 2: Ordinarily, each `mireg` will access register state, access read-only 0 state, or raise an illegal-instruction exception.
RULE 3: Values of `miselect` with the most-significant bit set are designated only for custom use.
RULE 4: Values of `miselect` with the most significant bit clear are designated only for standard use and are reserved until allocated to a standard architecture extension.
RULE 5: When attempting to access `sireg*` from M-mode or S-mode, if `siselect` holds a value that is not implemented at supervisor level, the behavior is unspecified.
RULE 6: Ordinarily, each `sireg` will access register state, access read-only 0 state, or, unless executing in a virtual machine, raise an illegal-instruction exception.
RULE 7: Widths of `siselect` and `sireg*` are the current XLEN rather than SXLEN.
RULE 8: When attempting to access `vsireg*` from M-mode or HS-mode, or accessing `sireg*` (really `vsireg*`) from VS-mode, if `vsiselect` holds a value that is not implemented at HS level, the behavior is unspecified.
RULE 9: Ordinarily, each `vsireg` will access register state, access read-only 0 state, or raise an exception (either an illegal-instruction exception or, for select accesses from VS-mode, a virtual-instruction exception).
RULE 10: Widths of `vsiselect` and `vsireg*` are the current XLEN rather than VSXLEN.
RULE 11: If Smstateen is implemented together with Smcsrind, when `mstateen0 [60]=0`, an attempt to access `siselect`, `sireg*`, `vsiselect`, or `vsireg*` from a privilege mode less privileged than M-mode results in an illegal-instruction exception.
RULE 12: If Smstateen is implemented together with Smcsrind, when `mstateen0 [60]=1`, all attempts from VS-mode or VU-mode to directly access `vsiselect` or `vsireg*`, and for all attempts from VU-mode to access `siselect` or `sireg*`, result in a virtual-instruction exception.
RULE 13: If the hypervisor extension is implemented, the bit `hstateen0 [60]` controls access to only `siselect` and `sireg*` (really `vsiselect` and `vsireg*`), which is the state potentially accessible to a virtual machine executing in VS or VU-mode.
RULE 14: If `hstateen0 [60]=0` and `mstateen0 [60]=1`, all attempts from VS or VU-mode to access `siselect` or `sireg*` raise a virtual-instruction exception, regardless of the value of `vsiselect` or any other `mstateen` bit.
