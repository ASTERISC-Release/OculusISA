RULE 1: If the rounding mode field of the instruction is 111, then executing FCVT.W.D with source register rs1 and control and status register frm results in a conversion operation that writes the result to destination register rd and sets the Invalid Operation (NV) and Inexact (NX) accrued exception flags.
RULE 2: When FCVT.W.D is executed, it converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 3: When FCVT.D.W is executed, it converts a signed 32-bit integer in integer register rs1 to a double-precision floating-point number in floating-point register rd.
RULE 4: When FCVT.L.D is executed, it converts a double-precision floating-point number in floating-point register rs1 to a 64-bit integer in integer register rd.
RULE 5: When FCVT.D.L is executed, it converts a signed 64-bit integer in integer register rs1 to a double-precision floating-point number in floating-point register rd.
RULE 6: When FCVT.W[U].D is executed on RV64, it sign-extends the 32-bit result when converting a 32-bit integer in rs1 to a double-precision floating-point number in rd.
RULE 7: All floating-point to integer and integer to floating-point conversion instructions round according to the rm field.
RULE 8: When FCVT.D.W[U] is executed, the result is exact and is unaffected by the rounding mode.
RULE 9: When FCVT.WU.D, FCVT.LU.D, FCVT.D.WU, or FCVT.D.LU are executed, they convert to or from unsigned integer values.
RULE 10: If the effective address of a Zilsd load instruction is a multiple of 8 bytes, the word access is guaranteed to be atomic and will not cause a misaligned trap.
RULE 11: If the effective address of a Zilsd load instruction is a multiple of 4 bytes but not 8 bytes, the word access is guaranteed to be atomic but may cause a misaligned trap.
RULE 12: If the effective address of a Zilsd load instruction is not a multiple of 4 bytes, the load instruction may cause a misaligned trap.
RULE 13: If the effective address of a Zclsd store instruction is a multiple of 8 bytes, the doubleword store is guaranteed to be atomic and will not cause a misaligned trap.
RULE 14: If the effective address of a Zclsd store instruction is a multiple of 4 bytes but not 8 bytes, the doubleword store is guaranteed to be atomic but may cause a misaligned trap.
RULE 15: If the effective address of a Zclsd store instruction is not a multiple of 4 bytes, the store instruction may cause a misaligned trap.
RULE 16: If the Zicfilp extension is enabled and the ELP state is LP_EXPECTED, and the PC is not 4-byte aligned, the LPAD instruction causes a software-check exception with x tval set to "landing pad fault (code=2)".
RULE 17: If the Zicfilp extension is enabled and the ELP state is LP_EXPECTED, and the LPL is not zero and does not match the expected landing pad label in bits 31:12 of the x7 register, the LPAD instruction causes a software-check exception with x tval set to "landing pad fault (code=2)".
RULE 18: If the LPAD instruction executes when the ELP state is LP_EXPECTED, the ELP is updated to NO_LP_EXPECTED if no software-check exception is caused.
RULE 19: If the Zicfiss extension is enabled, and the SSPOPCHK instruction executes, and the value loaded from the address in ssp does not match the value in rs1, a software-check exception (cause=18) is raised with x tval set to "shadow stack fault (code=3)".
RULE 20: If the SSPOPCHK instruction executes, and the value loaded from the shadow stack matches the value in rs1, the ssp is incremented by XLEN/8.
RULE 21: If the SSPOPCHK instruction executes and a software-check exception is not raised, the ssp is incremented by XLEN/8.
RULE 22: If the SSPOPCHK instruction executes and a software-check exception is raised, the ssp is not incremented.
RULE 23: If the instruction FCVT.W.D is executed, the double-precision conversion of the operands specified by rs2 and rs1 is performed, and the result is written to rd.
