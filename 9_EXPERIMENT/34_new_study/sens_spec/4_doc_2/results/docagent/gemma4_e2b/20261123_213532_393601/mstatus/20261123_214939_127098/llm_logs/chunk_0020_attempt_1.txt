RULE 1: Upon reset, all writable bits of the machine-level mstateen CSRs are initialized by the hardware to zeros.
RULE 2: If machine-level software sets any writable mstateen bits to nonzero, it must initialize the matching hstateen CSRs, if they exist, by writing zeros to them.
RULE 3: If any mstateen bits that are set to one have matching bits in the sstateen CSRs, machine-level software must also initialize those sstateen CSRs by writing zeros to them.
RULE 4: Software should ensure that all writable bits of sstateen CSRs are initialized to zeros when an OS at supervisor level is first entered.
RULE 5: Bit 63 of each mstateen CSR controls access to the matching sstateen and hstateen CSRs.
RULE 6: Bit 63 of each mstateen CSR may be read-only zero only if the hypervisor extension is not implemented and the matching supervisor-level sstateen CSR is all read-only zeros.
RULE 7: The C bit of mstateen0, hstateen0, or sstateen0 controls access to any and all custom state.
RULE 8: If misa.F = 1, the FCSR bit of mstateen0 is read-only zero.
RULE 9: If misa.F = 0 and the FCSR bit of a controlling stateen0 CSR is zero, all floating-point instructions cause an illegal-instruction exception.
RULE 10: The IMSIC bit in mstateen0 controls access to the IMSIC state, including CSRs stopei and vstopei, provided by the Ssaia extension.
RULE 11: The AIA bit in mstateen0 controls access to all state introduced by the Ssaia extension and not controlled by either the CSRIND or the IMSIC bits of hstateen0.
RULE 12: The CONTEXT bit in mstateen0 controls access to the scontext and hcontext CSRs provided by the Sdtrig extension.
RULE 13: The P1P13 bit in mstateen0 controls access to the hedelegh introduced by Privileged Specification Version 1.13.
RULE 14: Upon reset, mnstatus.NMIE contains the value 0.
RULE 15: Software can set mnstatus.NMIE to 1, but attempts to clear mnstatus.NMIE have no effect.
RULE 16: Counting of cycle and instret events does not occur while executing in an inhibited privilege mode defined by mcyclecfg or minstretcfg.
RULE 17: Instructions that retire in an inhibited mode do not increment instret, unless they are xRET instructions originating from a non-inhibited mode.
RULE 18: If an instruction is emulated by software running in a privileged mode that is inhibited in minstretcfg, the emulation routine must emulate the instret increment.
