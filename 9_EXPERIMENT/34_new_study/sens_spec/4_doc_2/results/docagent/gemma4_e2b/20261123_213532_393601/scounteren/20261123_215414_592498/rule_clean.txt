RULE 1: When the `scounteren` instruction is executed, the supervisor counter is enabled.
RULE 2: If a stateen CSR prevents access to state by less-privileged levels, an attempt in a less-privileged mode to read or write the protected state raises an illegal-instruction exception.
RULE 3: If a stateen CSR prevents access to state by less-privileged levels, an attempt from VS-mode or VU-mode to read or write the protected state raises a virtual-instruction exception.
RULE 4: If `mstateen0[60]` is 1 and `hstateen0[60]` is 0, all attempts from VS-mode or VU-mode to access `siselect` or `sireg*` raise a virtual-instruction exception.
RULE 5: If `menvcfg.CDE` is 1 and `mcounteren[i]` is 1, M-mode can delegate counter i to S-mode.
RULE 6: If `menvcfg.CDE` is 1 and `mcounteren[i]` is 1, the register state associated with counter i can be read or written via `sireg*` when `siselect` holds `0x40+i`.
RULE 7: When `mstateen0.CTR=0` and the privilege mode is less privileged than M-mode, attempts to access `sctrctl`, `vsctrctl`, `sctrdepth`, or `sctrstatus` raise an illegal-instruction exception.
RULE 8: When `mstateen0.CTR=0` and the privilege mode is less privileged than M-mode, attempts to access `sireg*` when `siselect` is in the range 0x200 through 0x2FF raise an illegal-instruction exception.
RULE 9: When `mstateen0.CTR=0` and the privilege mode is less privileged than M-mode, execution of the `SCTRCLR` instruction raises an illegal-instruction exception.
RULE 10: When Supervisor Counter Delegation is enabled and an attempt to access `scountinhibit` is made from VS-mode or VU-mode, a virtual-instruction exception is raised.
RULE 11: When counters are not delegated to S-mode, the bits in `scountinhibit` are read-only zero.
RULE 12: If implementations support Smcdeleg/Ssccfg, Sscofpmf, and the H extension, attempting to read `scountovf` from VS-mode or VU-mode raises a virtual-instruction exception when `menvcfg.CDE=1`.
RULE 13: If `mstateen0.CTR=1` and `hstateen0.CTR=0`, VS-mode accesses to supervisor CTR state or VSmode execution of `SCTRCLR` raise a virtual-instruction exception.
RULE 14: When `mstateen0.CTR=1` and `hstateen0.CTR=1`, VS-mode accesses to supervisor CTR state behave as described in Section 7.2 and Section 11.2.
RULE 15: If CTR is active (current privilege mode is enabled for recording and CTR is not frozen) and a qualified control transfer occurs, the Entry Registers are updated at logical entry 0, and `ctrsource.V` is set to 1.
RULE 16: If the CTR buffer is full, the oldest recorded entry is lost upon a qualified control transfer.
RULE 17: Execution of the `SCTRCLR` instruction zeroes all CTR Entry Registers for all DEPTH values.
RULE 18: Execution of the `SCTRCLR` instruction zeroes the CTR cycle counter and CCV.
RULE 19: A read of `ctrsource`, `ctrtarget`, or `ctrdata` following `SCTRCLR` but preceding the next qualified control transfer returns 0.
RULE 20: The first recorded transfer following `SCTRCLR` will have `ctrdata.CCV=0`.
RULE 21: When `sctrstatus.FROZEN=1`, transfer recording is inhibited.
RULE 22: If `sctrctl.LCOFIFRZ=1` and a local-counter-overflow interrupt (LCOFI) traps to M-mode or S-mode, `sctrstatus.FROZEN` is set by hardware.
RULE 23: If `sctrctl.BPFRZ=1` and a breakpoint exception traps to M-mode or S-mode, `sctrstatus.FROZEN` is set by hardware.
RULE 24: If CTR is active, the `CtrCycleCounter` increments at the same rate as the `mcycle` counter.
RULE 25: When CTR is active, the `CC` field is encoded such that CCE holds 0 if the `CtrCycleCounter` value is less than 4096, otherwise it holds the index of the most significant one bit in the `CtrCycleCounter` value, minus 11, and CCM holds `CtrCycleCounter` bits CCE+10:CCE-1.
RULE 26: Writing to `x ctrctl` or execution of `SCTRCLR` resets the `CtrCycleCounter`, ensuring accumulated cycle counts do not persist across a context switch.
RULE 27: When the CY, TM, IR, or HPMn bit in the scounteren register is clear and execution is in U-mode, attempts to read the cycle, time, instret, or hpmcountern register cause an illegal-instruction exception.
RULE 28: When the CY, TM, IR, or HPMn bit in the scounteren register is set, access to the corresponding counter register is permitted in U-mode.
RULE 29: Any bit in the scounteren register may be read-only zero, causing an exception when reading the corresponding counter while executing in U-mode.
RULE 30: U-mode may access a counter if the corresponding bits in the scounteren register and mcounteren register are both set.
RULE 31: The setting of a bit in mcounteren register does not affect whether the corresponding bit in scounteren register is writable.
RULE 32: The scounteren CSR continues to have its usual function and accessibility when V=1, except when VS-mode and VU-mode substitute for HS-mode and U-mode.
RULE 33: When in VS-mode, attempts to access a non-high-half counter CSR cause a virtual-instruction exception if scounteren is 0 and mcounteren is 1.
RULE 34: When in VS-mode and XLEN=32, attempts to access a high-half counter CSR cause a virtual-instruction exception if scounteren is 0 and hcounteren is 0 and mcounteren is 1.
RULE 35: When in VU-mode, attempts to access a non-high-half counter CSR cause a virtual-instruction exception if scounteren is 0 or hcounteren is 0 and mcounteren is 1.
RULE 36: When in VU-mode and XLEN=32, attempts to access a high-half counter CSR cause a virtual-instruction exception if scounteren is 0 or hcounteren is 0 and mcounteren is 1.
