RULE 1: CSRRWI accesses exactly one CSR, selected by the instruction's csr specifier.
RULE 2: CSRRWI's CSR read, if any, and its CSR write form an atomic update of that single CSR.
RULE 3: On execution without an exception, CSRRWI writes to the addressed CSR the XLEN-bit zero-extension of the 5-bit unsigned immediate uimm[4:0], regardless of rd.
RULE 4: If uimm[4:0] is zero, CSRRWI still writes zero to the addressed CSR and does not suppress the CSR write.
RULE 5: If rd is not x0 and the CSRRWI access completes without exception, CSRRWI reads the addressed CSR.
RULE 6: If rd is not x0 and the CSRRWI access completes without exception, the value written to rd is the XLEN-bit zero-extension of the CSR value read before the CSR write.
RULE 7: If rd is not x0, the explicit CSR read by CSRRWI returns the CSR state before execution of the CSRRWI instruction.
RULE 8: If rd is x0, CSRRWI does not read the addressed CSR.
RULE 9: If rd is x0, CSRRWI does not cause any side effects that might occur on a CSR read.
RULE 10: If rd is not x0, CSRRWI causes any read side effects of the addressed CSR.
RULE 11: If CSRRWI reads a standard CSR, that read has no side effects.
RULE 12: When CSRRWI writes a CSR without an exception, it actions side effects for all fields within the written CSR.
RULE 13: If CSRRWI writes a read/write CSR containing read-only bits, writes to those read-only bits are ignored.
RULE 14: If CSRRWI targets a read-only CSR, it raises an illegal-instruction exception regardless of rd.
RULE 15: If CSRRWI attempts to access a CSR without appropriate privilege level and no virtual-instruction exception condition applies, it raises an illegal-instruction exception.
RULE 16: If CSRRWI attempts a CSR access for which the hypervisor-specific HS-qualified rules require a virtual-instruction exception, it raises a virtual-instruction exception.
RULE 17: The explicit CSR write by CSRRWI suppresses and overrides any implicit writes or modifications to the same CSR by the same instruction.
RULE 18: A CSRRWI CSR access is performed after prior instructions in program order whose behavior modifies or is modified by the addressed CSR state.
RULE 19: A CSRRWI CSR access is performed before subsequent instructions in program order whose behavior modifies or is modified by the addressed CSR state.
RULE 20: Any side effects of the CSRRWI CSR accesses are observed to occur synchronously in program order.
RULE 21: The full consequences of any CSRRWI CSR side effects are observable by the very next instruction.
RULE 22: No consequences of CSRRWI CSR side effects may be observed out-of-order by preceding instructions.
RULE 23: Under RVWMO, a CSRRWI CSR access is weakly ordered by default, so other harts or devices may observe it in an order different from program order.
RULE 24: A CSRRWI CSR access is not ordered with respect to explicit memory accesses unless the CSR access modifies the execution behavior of the instruction that performs the explicit memory access or unless the accesses are ordered by syntactic dependencies or Memory-Ordering PMAs.
RULE 25: For the purposes of FENCE, any CSR read performed by CSRRWI is classified as device input (I).
RULE 26: For the purposes of FENCE, the CSR write performed by CSRRWI is classified as device output (O).
