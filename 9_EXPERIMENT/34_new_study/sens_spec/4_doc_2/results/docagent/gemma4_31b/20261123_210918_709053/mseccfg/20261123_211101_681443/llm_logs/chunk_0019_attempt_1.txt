RULE 1: The mseccfg register exists if any extension that adds a field to mseccfg is implemented.
RULE 2: If no extension that adds a field to mseccfg is implemented, mseccfg is reserved.
RULE 3: When Zkr is implemented and USEED is 0, access to the seed CSR in U-mode raises an illegal-instruction exception.
RULE 4: When Zkr is implemented and USEED is 1, read-write access to the seed CSR from U-mode is allowed.
RULE 5: When Zkr is implemented and USEED is 1, any access to the seed CSR from U-mode other than read-write raises an illegal-instruction exception.
RULE 6: When Zkr is not implemented or U-mode is not implemented, mseccfg.USEED is read-only zero.
RULE 7: When Zkr is implemented and SSEED is 0, access to the seed CSR from S-/HS-mode raises an illegal-instruction exception.
RULE 8: When Zkr is implemented and SSEED is 1, read-write access to the seed CSR from S-/HS-mode is allowed.
RULE 9: When Zkr is implemented and SSEED is 1, any access to the seed CSR from S-/HS-mode other than read-write raises an illegal-instruction exception.
RULE 10: When Zkr is not implemented or S-mode is not implemented, mseccfg.SSEED is read-only zero.
RULE 11: When the H extension and Zkr are implemented, access to the seed CSR from an HS-qualified instruction leads to a virtual-instruction exception in VS and VU modes.
RULE 12: When the H extension and Zkr are implemented, any access to the seed CSR from an HS-qualified instruction other than a read-write access raises an illegal-instruction exception.
RULE 13: In M-mode, the seed CSR is always available via CSR read-write instructions.
RULE 14: In M-mode, an attempted read of the seed CSR without a write raises an illegal-instruction exception.
RULE 15: When Smepmp is implemented and mseccfg.RLB is 1, locked PMP rules may be removed, modified, or edited.
RULE 16: When Smepmp is implemented, mseccfg.RLB is 0, and pmpcfg.L is 1 in any rule or entry, mseccfg.RLB remains 0 and any further modifications to mseccfg.RLB are ignored until a PMP reset.
RULE 17: When Smepmp is implemented and mseccfg.MMWP is set, the default PMP policy for M-mode when accessing memory regions without a matching PMP rule is changed to denied.
RULE 18: When Smepmp is implemented and mseccfg.MMWP is set, it cannot be unset until a PMP reset.
RULE 19: When Smepmp is implemented and mseccfg.MML is set, pmpcfg.L marks a rule as M-mode-only when set and S/U-mode-only when unset.
RULE 20: When Smepmp is implemented and mseccfg.MML is set, a rule where pmpcfg.L is set is enforced on Machine mode and denied in Supervisor or User mode.
RULE 21: When Smepmp is implemented and mseccfg.MML is set, a rule where pmpcfg.L is set remains locked such that modifications to its configuration or address registers are ignored until a PMP reset, unless mseccfg.RLB is set.
RULE 22: When Smepmp is implemented and mseccfg.MML is set, a rule where pmpcfg.L is unset is enforced on Supervisor and User modes and denied on Machine mode.
RULE 23: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule where pmpcfg.L is not set allows M-mode read/write access and S/U-mode read access if pmpcfg.X is not set, or read/write access if pmpcfg.X is set, and the region is not executable.
RULE 24: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule where pmpcfg.L is set allows both M-mode and S/U-mode execute access, and M-mode read access if pmpcfg.X is set, and the region is not writable.
RULE 25: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule where pmpcfg.L is set remains locked such that modifications to its configuration or address registers are ignored until a PMP reset, unless mseccfg.RLB is set.
RULE 26: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule with pmpcfg.LRWX=1111 allows both M-mode and S/U-mode read-only access, and the rule remains locked such that modifications to its configuration or address registers are ignored until a PMP reset, unless mseccfg.RLB is set.
RULE 27: When Smepmp is implemented and mseccfg.MML is set, pmpcfg writes that attempt to add an executable rule that is either M-mode-only or a locked Shared-Region are ignored unless mseccfg.RLB is set.
RULE 28: When Smepmp is implemented and mseccfg.MML is set, executing code with Machine mode privileges is only possible from memory regions with a matching M-mode-only rule or a locked Shared-Region rule with executable privileges.
RULE 29: When Smepmp is implemented and mseccfg.MML is set, executing code from a region without a matching rule or with a matching S/U-mode-only rule is denied.
RULE 30: When Smepmp is implemented and mseccfg.MML is not set, the encoding pmpcfg.RW=01 is reserved.
RULE 31: When Smmpm is implemented, the PMM field enables or disables pointer masking for M-mode according to the values in Table 21.
RULE 32: When Smmpm is not implemented, mseccfg.PMM is read-only zero.
RULE 33: For RV32, mseccfg.PMM is read-only zero.
RULE 34: When Zicfilp is implemented and MLPE is 1, the Zicfilp extension is enabled in M-mode.
RULE 35: When Zicfilp is implemented and MLPE is 0, the hart does not update the ELP state (remains NO_LP_EXPECTED) and the LPAD instruction operates as a no-op in M-mode.
RULE 36: When XLEN=32, mseccfgh is a 32-bit read/write register that aliases bits 63:32 of mseccfg.
RULE 37: When XLEN=64, mseccfgh does not exist.
RULE 38: Upon reset, mseccfg.MML, mseccfg.MMWP, and mseccfg.RLB are set to 0 unless the platform mandates a different reset value.
RULE 39: Upon reset, mseccfg.USEED and mseccfg.SSEED must have defined reset values.
RULE 40: Upon reset, if the Zicfilp extension is implemented, mseccfg.MLPE is reset to 0.
