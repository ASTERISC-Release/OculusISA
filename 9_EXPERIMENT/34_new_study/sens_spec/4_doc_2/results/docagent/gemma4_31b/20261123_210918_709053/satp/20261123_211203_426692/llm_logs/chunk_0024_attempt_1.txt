RULE 1: When V=1, instructions that normally read or modify satp actually access vsatp instead.
RULE 2: When the effective privilege mode is not U or hstatus.HU is not 0, vsatp is considered active for the purposes of the address-translation algorithm.
RULE 3: When vsatp is active and the effective privilege mode is neither VS nor VU, VS-stage page-table entries' A bits must not be set as a result of speculative execution.
RULE 4: When V=0, a write to vsatp with an unsupported MODE value is either ignored or the fields of vsatp are treated as WARL.
RULE 5: When V=1, a write to satp with an unsupported MODE value is ignored and no write to vsatp is effected.
RULE 6: When V=0, vsatp does not directly affect the behavior of the machine, unless a virtual-machine load/store (HLV, HLVX, or HSV) instruction is used or the mstatus.MPRV feature is used to execute a load or store as though V=1.
RULE 7: Whenever the current virtualization mode V is 1, the original virtual address is converted in the first stage by VS-level address translation as controlled by the vsatp register into a guest physical address.
RULE 8: When V=1, if vsatp is zeroed, the VS-stage of two-stage address translation is effectively disabled.
RULE 9: When V=1, an attempt to access satp in VS-mode while hstatus.VTVM=1 causes a virtual-instruction exception.
RULE 10: When V=1 and vsatp.MODE is Bare, and the effective privilege mode is less than M, shadow stack instructions raise a store/AMO access-fault exception.
