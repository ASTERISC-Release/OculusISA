RULE 1: When V=0, SFENCE.VMA orders stores to HS-level address-translation structures with subsequent HS-level address translations.
RULE 2: When V=0, the virtual-address argument to SFENCE.VMA is an HS-level virtual address.
RULE 3: When V=0, the ASID argument to SFENCE.VMA is an HS-level ASID.
RULE 4: When V=1, SFENCE.VMA orders stores to VS-level address-translation structures with subsequent VS-stage address translations for the same virtual machine.
RULE 5: When V=1, the virtual-address argument to SFENCE.VMA is a guest virtual address within the current virtual machine.
RULE 6: When V=1, the ASID argument to SFENCE.VMA is a VS-level ASID within the current virtual machine.
RULE 7: When V=1, the current virtual machine for SFENCE.VMA is identified by the VMID field of CSR hgatp.
RULE 8: When V=1, the effective ASID for SFENCE.VMA is the combination of hgatp.VMID and the VS-level ASID.
RULE 9: When V=1, SFENCE.VMA only orders stores to VS-level address-translation structures for subsequent VS-stage address translations when hgatp.VMID is the same as it was when the SFENCE.VMA executed.
RULE 10: When V=1 and the current privilege mode is VU-mode, executing SFENCE.VMA causes a virtual-instruction exception.
RULE 11: When V=1 and the current privilege mode is VS-mode and hstatus.VTVM=1, executing SFENCE.VMA causes a virtual-instruction exception.
