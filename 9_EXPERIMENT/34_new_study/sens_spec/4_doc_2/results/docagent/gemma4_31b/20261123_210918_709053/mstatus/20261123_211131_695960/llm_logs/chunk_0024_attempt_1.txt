RULE 1: When a trap is taken into M-mode, the mstatus (or mstatush) field MPV is set to the value of the virtualization mode V at the time of the trap.
RULE 2: When a trap is taken into M-mode, the mstatus (or mstatush) field MPP is set to the nominal privilege mode at the time of the trap.
RULE 3: When an MRET instruction is executed, the virtualization mode V is set to the value of mstatus (or mstatush) field MPV, unless mstatus (or mstatush) field MPP is 3, in which case V remains 0.
RULE 4: When a trap is taken into M-mode, the mstatus (or mstatush) field GVA is set to 1 for any trap that writes a guest virtual address to mtval (breakpoint, address misaligned, access fault, page fault, or guest-page fault).
RULE 5: When a trap is taken into M-mode, the mstatus (or mstatush) field GVA is set to 0 for any trap other than those that write a guest virtual address to mtval.
RULE 6: When the hart is in HS-mode, mstatus field TVM=1 prevents access to hgatp or execution of HFENCE.GVMA or HINVAL.GVMA.
RULE 7: When the hart is in HS-mode, mstatus field TVM=1 has no effect on accesses to vsatp or instructions HFENCE.VVMA or HINVAL.VVMA.
RULE 8: When mstatus field MPRV=0, translation and protection for explicit memory accesses behave as normal.
RULE 9: When mstatus field MPRV=1 and mstatus field MPV=0 and mstatus field MPP=0, explicit memory accesses are translated and protected as U-level access with HS-level translation and protection only.
RULE 10: When mstatus field MPRV=1 and mstatus field MPV=0 and mstatus field MPP=1, explicit memory accesses are translated and protected as HS-level access with HS-level translation and protection only.
RULE 11: When mstatus field MPRV=1 and mstatus field MPP=3, explicit memory accesses are translated and protected as M-level access with no translation.
RULE 12: When mstatus field MPRV=1 and mstatus field MPV=1 and mstatus field MPP=0, explicit memory accesses are translated and protected as VU-level access with two-stage translation and protection.
RULE 13: When mstatus field MPRV=1 and mstatus field MPV=1 and mstatus field MPP=1, explicit memory accesses are translated and protected as VS-level access with two-stage translation and protection, and vsstatus.SUM applies instead of the HS-level SUM bit.
RULE 14: When a trap is taken into M-mode, the mstatus (or mstatush) fields MPIE and MIE are written.
RULE 15: When an MRET instruction is executed, mstatus (or mstatush) field MPV is set to 0.
RULE 16: When an MRET instruction is executed, mstatus (or mstatush) field MPP is set to 0.
RULE 17: When an MRET instruction is executed, mstatus (or mstatush) field MIE is set to the value of MPIE.
RULE 18: When an MRET instruction is executed, mstatus (or mstatush) field MPIE is set to 1.
RULE 19: When a trap is taken into privilege mode x, the xPELP bit in mstatus is set to ELP and ELP is set to NO_LP_EXPECTED.
RULE 20: When an MRET instruction is executed and the new privilege mode is y, ELP is set to the value of MPELP in mstatus if yLPE is 1.
RULE 21: When an MRET instruction is executed and the new privilege mode is y, ELP is set to NO_LP_EXPECTED if yLPE is 0.
RULE 22: When an MRET instruction is executed, the MPELP bit in mstatus is set to NO_LP_EXPECTED.
RULE 23: When an SRET instruction is executed and the new privilege mode is y, ELP is set to the value of SPELP in mstatus if yLPE is 1.
RULE 24: When an SRET instruction is executed and the new privilege mode is y, ELP is set to NO_LP_EXPECTED if yLPE is 0.
RULE 25: When an SRET instruction is executed, the SPELP bit in mstatus is set to NO_LP_EXPECTED.
