RULE 1: The `mseccfg` CSR contains a field named `SSEED` used to control access to the `seed` CSR from S or HS modes.
RULE 2: The `mseccfg` CSR contains a field named `USEED` used to control access to the `seed` CSR from U mode.
RULE 3: If the `[s,u]seed` fields in `mseccfg` are implemented as read-only constant values of 0, writing a 1 to `[s,u]seed` and reading back the result allows software to discover that access to the `seed` CSR cannot be enabled in U and S mode.
RULE 4: If the `mseccfg.[s,u]seed` option is set, a security boundary is drawn around the component in relation to Sensitive Security Parameter (SSP) flows, allowing the component to enforce the key lifecycle without the key being passed across the boundary to external code, regardless of whether the component is in M mode.
RULE 5: When the current privilege mode is Machine-mode (M-mode), the `mseccfg` CSR (address 0x747) is accessible for read and write operations.
RULE 6: When the current privilege mode is less than Machine-mode (M-mode), an attempt to access the `mseccfg` CSR (address 0x747) shall raise an illegal-instruction exception.
RULE 7: The mseccfg register exists if any extension that adds a field to mseccfg is implemented.
RULE 8: If no extension that adds a field to mseccfg is implemented, mseccfg is reserved.
RULE 9: When Zkr is implemented and USEED is 0, access to the seed CSR in U-mode raises an illegal-instruction exception.
RULE 10: When Zkr is implemented and USEED is 1, read-write access to the seed CSR from U-mode is allowed.
RULE 11: When Zkr is implemented and USEED is 1, any access to the seed CSR from U-mode other than read-write raises an illegal-instruction exception.
RULE 12: When Zkr is not implemented or U-mode is not implemented, mseccfg.USEED is read-only zero.
RULE 13: When Zkr is implemented and SSEED is 0, access to the seed CSR from S-/HS-mode raises an illegal-instruction exception.
RULE 14: When Zkr is implemented and SSEED is 1, read-write access to the seed CSR from S-/HS-mode is allowed.
RULE 15: When Zkr is implemented and SSEED is 1, any access to the seed CSR from S-/HS-mode other than read-write raises an illegal-instruction exception.
RULE 16: When Zkr is not implemented or S-mode is not implemented, mseccfg.SSEED is read-only zero.
RULE 17: When the H extension and Zkr are implemented, access to the seed CSR from an HS-qualified instruction leads to a virtual-instruction exception in VS and VU modes.
RULE 18: When the H extension and Zkr are implemented, any access to the seed CSR from an HS-qualified instruction other than a read-write access raises an illegal-instruction exception.
RULE 19: In M-mode, the seed CSR is always available via CSR read-write instructions.
RULE 20: In M-mode, an attempted read of the seed CSR without a write raises an illegal-instruction exception.
RULE 21: When Smepmp is implemented and mseccfg.RLB is 1, locked PMP rules may be removed, modified, or edited.
RULE 22: When Smepmp is implemented, mseccfg.RLB is 0, and pmpcfg.L is 1 in any rule or entry, mseccfg.RLB remains 0 and any further modifications to mseccfg.RLB are ignored until a PMP reset.
RULE 23: When Smepmp is implemented and mseccfg.MMWP is set, the default PMP policy for M-mode when accessing memory regions without a matching PMP rule is changed to denied.
RULE 24: When Smepmp is implemented and mseccfg.MMWP is set, it cannot be unset until a PMP reset.
RULE 25: When Smepmp is implemented and mseccfg.MML is set, pmpcfg.L marks a rule as M-mode-only when set and S/U-mode-only when unset.
RULE 26: When Smepmp is implemented and mseccfg.MML is set, a rule where pmpcfg.L is set is enforced on Machine mode and denied in Supervisor or User mode.
RULE 27: When Smepmp is implemented and mseccfg.MML is set, a rule where pmpcfg.L is set remains locked such that modifications to its configuration or address registers are ignored until a PMP reset, unless mseccfg.RLB is set.
RULE 28: When Smepmp is implemented and mseccfg.MML is set, a rule where pmpcfg.L is unset is enforced on Supervisor and User modes and denied on Machine mode.
RULE 29: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule where pmpcfg.L is not set allows M-mode read/write access and S/U-mode read access if pmpcfg.X is not set, or read/write access if pmpcfg.X is set, and the region is not executable.
RULE 30: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule where pmpcfg.L is set allows both M-mode and S/U-mode execute access, and M-mode read access if pmpcfg.X is set, and the region is not writable.
RULE 31: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule where pmpcfg.L is set remains locked such that modifications to its configuration or address registers are ignored until a PMP reset, unless mseccfg.RLB is set.
RULE 32: When Smepmp is implemented and mseccfg.MML is set, a Shared-Region rule with pmpcfg.LRWX=1111 allows both M-mode and S/U-mode read-only access, and the rule remains locked such that modifications to its configuration or address registers are ignored until a PMP reset, unless mseccfg.RLB is set.
RULE 33: When Smepmp is implemented and mseccfg.MML is set, pmpcfg writes that attempt to add an executable rule that is either M-mode-only or a locked Shared-Region are ignored unless mseccfg.RLB is set.
RULE 34: When Smepmp is implemented and mseccfg.MML is set, executing code with Machine mode privileges is only possible from memory regions with a matching M-mode-only rule or a locked Shared-Region rule with executable privileges.
RULE 35: When Smepmp is implemented and mseccfg.MML is set, executing code from a region without a matching rule or with a matching S/U-mode-only rule is denied.
RULE 36: When Smepmp is implemented and mseccfg.MML is not set, the encoding pmpcfg.RW=01 is reserved.
RULE 37: When Smmpm is implemented, the PMM field enables or disables pointer masking for M-mode according to the values in Table 21.
RULE 38: When Smmpm is not implemented, mseccfg.PMM is read-only zero.
RULE 39: For RV32, mseccfg.PMM is read-only zero.
RULE 40: When Zicfilp is implemented and MLPE is 1, the Zicfilp extension is enabled in M-mode.
RULE 41: When Zicfilp is implemented and MLPE is 0, the hart does not update the ELP state (remains NO_LP_EXPECTED) and the LPAD instruction operates as a no-op in M-mode.
RULE 42: When XLEN=32, mseccfgh is a 32-bit read/write register that aliases bits 63:32 of mseccfg.
RULE 43: When XLEN=64, mseccfgh does not exist.
RULE 44: Upon reset, mseccfg.MML, mseccfg.MMWP, and mseccfg.RLB are set to 0 unless the platform mandates a different reset value.
RULE 45: Upon reset, mseccfg.USEED and mseccfg.SSEED must have defined reset values.
RULE 46: Upon reset, if the Zicfilp extension is implemented, mseccfg.MLPE is reset to 0.
RULE 47: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=0, W=0, X=0` results in an inaccessible region causing an access exception for both M-mode and S/U-mode.
RULE 48: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=0, W=0, X=1` results in an access exception for M-mode and an execute-only region for S/U-mode.
RULE 49: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=0, W=1, X=0` results in a shared data region that is read/write for M-mode and read-only for S/U-mode.
RULE 50: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=0, W=1, X=1` results in a shared data region that is read/write for both M-mode and S/U-mode.
RULE 51: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=1, W=0, X=0` results in an access exception for M-mode and a read-only region for S/U-mode.
RULE 52: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=1, W=0, X=1` results in an access exception for M-mode and a read/execute region for S/U-mode.
RULE 53: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=1, W=1, X=0` results in an access exception for M-mode and a read/write region for S/U-mode.
RULE 54: If `mseccfg.MML` is set to 1, a PMP entry with `L=0, R=1, W=1, X=1` results in an access exception for M-mode and a read/write/execute region for S/U-mode.
RULE 55: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=0, W=0, X=0` results in a locked inaccessible region causing an access exception for both M-mode and S/U-mode.
RULE 56: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=0, W=0, X=1` results in a locked execute-only region for M-mode and an access exception for S/U-mode.
RULE 57: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=0, W=1, X=0` results in a locked shared code region that is execute-only for both M-mode and S/U-mode.
RULE 58: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=0, W=1, X=1` results in a locked shared code region that is read/execute for M-mode and execute-only for S/U-mode.
RULE 59: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=1, W=0, X=0` results in a locked read-only region for M-mode and an access exception for S/U-mode.
RULE 60: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=1, W=0, X=1` results in a locked read/execute region for M-mode and an access exception for S/U-mode.
RULE 61: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=1, W=1, X=0` results in a locked read/write region for M-mode and an access exception for S/U-mode.
RULE 62: If `mseccfg.MML` is set to 1, a PMP entry with `L=1, R=1, W=1, X=1` results in a locked shared data region that is read-only for both M-mode and S/U-mode.
RULE 63: If a field in `mseccfg` is `MMWP` or `MML` and it is set to 1, the field is locked and further writes to it are ignored.
RULE 64: If a field in `mseccfg` is `RLB` and it is set to 0, the field is locked and further writes to it are ignored.
RULE 65: When S-mode is implemented and the privilege mode is M, xLPE is determined by the value of mseccfg.MLPE.
RULE 66: When S-mode is not implemented and the privilege mode is M, xLPE is determined by the value of mseccfg.MLPE.
