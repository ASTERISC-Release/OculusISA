RULE 1: If all privilege, virtualization, existence, writability, and CSR-specific access checks pass, CSRRWI performs one atomic access to the addressed CSR.
RULE 2: When CSRRWI executes, its CSR write value is the XLEN-bit value obtained by zero-extending uimm[4:0].
RULE 3: When CSRRWI executes successfully, it writes the zero-extended uimm value to the addressed CSR.
RULE 4: When uimm[4:0] is zero, CSRRWI still performs a CSR write and attempts to write zero to the addressed CSR.
RULE 5: When rd is not x0, CSRRWI reads the addressed CSR's value before performing its explicit write.
RULE 6: When rd is not x0, CSRRWI writes the pre-instruction value read from the addressed CSR, zero-extended to XLEN bits, into rd.
RULE 7: When rd is x0, CSRRWI does not read the addressed CSR.
RULE 8: When rd is x0, CSRRWI does not cause any side effect associated with reading the addressed CSR.
RULE 9: When rd is x0, CSRRWI still writes the addressed CSR.
RULE 10: When rd is not x0 and the addressed CSR has a read side effect, CSRRWI causes that read side effect.
RULE 11: When CSRRWI successfully writes a CSR that has a whole-CSR write side effect, CSRRWI causes that write side effect.
RULE 12: When CSRRWI successfully writes a CSR containing fields with field-write side effects, CSRRWI actions the field-write side effects for every such field in the CSR.
RULE 13: If the value written by CSRRWI creates a CSR-defined condition that causes an architectural event or consequence, that event or consequence occurs as an indirect effect of the write.
RULE 14: When rd is not x0 and the addressed CSR is wider than XLEN, CSRRWI writes the CSR's least-significant XLEN bits into rd.
RULE 15: When the addressed CSR is wider than XLEN, a successful CSRRWI modifies only the CSR's least-significant XLEN bits and leaves its upper bits unchanged.
RULE 16: When CSRRWI writes a read/write CSR containing read-only bits, writes to those read-only bits are ignored.
RULE 17: When an otherwise-permitted CSRRWI writes an unsupported value to a WARL field, no exception is raised solely because that value is unsupported.
RULE 18: When CSRRWI writes an unsupported value to a WARL field, the field assumes an architecturally legal value.
RULE 19: When rd is not x0, the explicit CSR read performed by CSRRWI returns the addressed CSR's state before execution of the instruction.
RULE 20: When CSRRWI explicitly writes a CSR that the same instruction would otherwise modify implicitly, the explicit write suppresses and overrides the implicit modification.
RULE 21: When CSRRWI writes a CSR that is normally updated as a side effect of instruction execution, the explicit write occurs instead of that side-effect update.
RULE 22: When CSRRWI writes instret or its applicable writable alias, the following instruction observes the value explicitly written by CSRRWI without an additional retirement increment from CSRRWI.
RULE 23: When CSRRWI attempts to write a read-only CSR, it raises an illegal-instruction exception with exception code 2.
RULE 24: CSRRWI raises an illegal-instruction exception on a read-only CSR even when rd is x0.
RULE 25: CSRRWI raises an illegal-instruction exception on a read-only CSR even when uimm[4:0] is zero.
RULE 26: When virtualization mode is zero and the current privilege mode is below the minimum privilege required by the addressed CSR, CSRRWI raises an illegal-instruction exception with exception code 2.
RULE 27: When virtualization mode is one and CSRRWI specifies a supervisor CSR that has a corresponding virtual-supervisor CSR, the instruction accesses the corresponding virtual-supervisor CSR instead of the HS-level supervisor CSR.
RULE 28: When virtualization mode is one and CSRRWI executed in VS-mode or VU-mode directly specifies an implemented virtual-supervisor CSR, the instruction raises a virtual-instruction exception with exception code 22 if the same access would be permitted in HS-mode.
RULE 29: When virtualization mode is one and CSRRWI executed in VS-mode or VU-mode specifies an implemented hypervisor CSR, the instruction raises a virtual-instruction exception with exception code 22 if the same access would be permitted in HS-mode.
RULE 30: When virtualization mode is one and CSRRWI executed in VU-mode specifies an implemented supervisor CSR, the instruction raises a virtual-instruction exception with exception code 22 if the same access would be permitted in HS-mode.
RULE 31: When virtualization mode is one, XLEN is 32, and CSRRWI makes an invalid access to a high-half CSR whose corresponding low-half access would be HS-qualified, the instruction raises a virtual-instruction exception with exception code 22.
RULE 32: When a CSR access is disallowed and the conditions for a virtual-instruction exception do not apply, CSRRWI raises an illegal-instruction exception with exception code 2.
RULE 33: If CSRRWI raises an exception before completing its CSR access, it does not modify the addressed CSR.
RULE 34: If CSRRWI raises an exception before completing its CSR access, it does not modify rd.
RULE 35: If CSRRWI raises an exception before completing its CSR access, it causes none of the CSR read or write side effects that successful execution would have caused.
RULE 36: If CSRRWI raises a synchronous exception, the instruction does not retire and does not increment instret.
RULE 37: Unless the addressed CSR specifies otherwise, a hart observes a CSRRWI access after every earlier instruction whose behavior modifies or is modified by that CSR's state.
RULE 38: Unless the addressed CSR specifies otherwise, a hart observes a CSRRWI access before every later instruction whose behavior modifies or is modified by that CSR's state.
RULE 39: Unless specified otherwise, side effects caused by a successful CSRRWI CSR access occur synchronously in program order.
RULE 40: Unless specified otherwise, the full consequences of CSRRWI CSR-access side effects are observable by the next instruction in program order.
RULE 41: Unless specified otherwise, no instruction preceding CSRRWI in program order may observe consequences of its CSR-access side effects.
RULE 42: Under RVWMO and absent stronger ordering constraints, other harts or devices may observe a CSRRWI CSR access in an order different from program order.
RULE 43: Under RVWMO, a CSRRWI CSR access is not ordered with respect to an explicit memory access unless the CSR access modifies that memory-access instruction's execution behavior, a memory-model syntactic dependency orders the accesses, a Memory-Ordering PMA orders the accesses, or an applicable fence orders them.
RULE 44: For FENCE ordering, the CSR read performed by CSRRWI when rd is not x0 is classified as device input.
RULE 45: For FENCE ordering, the CSR write performed by every successfully executed CSRRWI is classified as device output.
RULE 46: When rd is not x0, the addressed CSR is a source register of CSRRWI for syntactic-dependency purposes.
RULE 47: The addressed CSR is a destination register of every CSRRWI for syntactic-dependency purposes.
RULE 48: When rd is not x0, rd is a destination register of CSRRWI for syntactic-dependency purposes.
RULE 49: When rd is not x0, CSRRWI carries a syntactic dependency from the addressed CSR to rd.
