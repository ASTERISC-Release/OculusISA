RULE 1: SFENCE.VMA orders stores.
RULE 2: An invalidate, clean, or flush operation is not ordered by SFENCE.VMA.
RULE 3: If the hart is executing in S-mode and the `mstatus.TVM` bit is set to 1, then the execution of the `SFENCE.VMA` instruction shall raise an illegal-instruction exception.
RULE 4: If the menvcfg.PBMTE bit is changed, executing an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 synchronizes address-translation caches with respect to the altered interpretation of page-table entries' PBMT fields.
RULE 5: If the menvcfg.ADUE bit is changed, executing an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 synchronizes address-translation caches with respect to the altered interpretation of page-table entries' A/D bits.
RULE 6: In a system with page-based virtual memory, the execution of an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 synchronizes PMP settings with the virtual memory system and any PMP or address-translation caches.
RULE 7: Execution of SFENCE.VMA orders only the local hart's implicit references to the memory-management data structures.
RULE 8: Execution of SFENCE.VMA orders previous stores visible to the current hart before subsequent implicit references to memory-management data structures by the current hart.
RULE 9: Execution of SFENCE.VMA invalidates address-translation cache entries associated with the local hart.
RULE 10: If rs1 = x0 and rs2 = x0, SFENCE.VMA orders all reads and writes made to any level of the page tables for all address spaces.
RULE 11: If rs1 = x0 and rs2 = x0, SFENCE.VMA invalidates all address-translation cache entries for all address spaces.
RULE 12: If rs1 = x0 and rs2 ≠ x0, SFENCE.VMA orders all reads and writes made to any level of the page tables for the address space identified by rs2.
RULE 13: If rs1 = x0 and rs2 ≠ x0, SFENCE.VMA invalidates all address-translation cache entries matching the address space identified by rs2, except for entries containing global mappings.
RULE 14: If rs1 ≠ x0 and rs2 = x0, SFENCE.VMA orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 15: If rs1 ≠ x0 and rs2 = x0, SFENCE.VMA invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 16: If rs1 ≠ x0 and rs2 ≠ x0, SFENCE.VMA orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for the address space identified by rs2.
RULE 17: If rs1 ≠ x0 and rs2 ≠ x0, SFENCE.VMA invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 and match the address space identified by rs2, except for entries containing global mappings.
RULE 18: If the value held in rs1 is not a valid virtual address, SFENCE.VMA has no effect.
RULE 19: SFENCE.VMA synchronizes the hart's address-translation caches.
RULE 20: SFENCE.VMA synchronizes the hart's address-translation caches based on the values in registers rs1 and rs2.
RULE 21: Execution of SFENCE.VMA in U-mode raises an illegal-instruction exception.
RULE 22: Execution of SFENCE.VMA in S-mode when mstatus.TVM is 1 raises an illegal-instruction exception.
RULE 23: Execution of SFENCE.VMA in HS-mode when mstatus.TVM is 1 raises an illegal-instruction exception.
RULE 24: Execution of SFENCE.VMA in VS-mode raises a virtual-instruction exception.
RULE 25: Execution of SFENCE.VMA in VU-mode raises a virtual-instruction exception.
RULE 26: Execution of SFENCE.VMA in VS-mode when hstatus.VTVM is 1 raises a virtual-instruction exception.
RULE 27: When V=0, the virtual-address argument of SFENCE.VMA is an HS-level virtual address.
RULE 28: When V=0, the ASID argument of SFENCE.VMA is an HS-level ASID.
RULE 29: When V=0, the SFENCE.VMA instruction orders stores only to HS-level address-translation structures with subsequent HS-level address translations.
RULE 30: When V=1, the virtual-address argument of SFENCE.VMA is a guest virtual address within the current virtual machine.
RULE 31: When V=1, the ASID argument of SFENCE.VMA is a VS-level ASID within the current virtual machine.
RULE 32: When V=1, the SFENCE.VMA instruction orders stores only to the VS-level address-translation structures with subsequent VS-stage address translations for instructions that execute when hgatp.VMID is the same as it was when the SFENCE.VMA instruction was executed.
RULE 33: When V=1 and hstatus.VTVM=1, an attempt to execute SFENCE.VMA in VS-mode causes a virtual-instruction exception.
