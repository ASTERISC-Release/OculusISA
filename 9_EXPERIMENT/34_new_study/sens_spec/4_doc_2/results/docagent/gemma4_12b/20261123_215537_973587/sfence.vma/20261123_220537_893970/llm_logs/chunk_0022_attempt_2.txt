RULE 1: Execution of SFENCE.VMA orders only the local hart's implicit references to the memory-management data structures.
RULE 2: Execution of SFENCE.VMA orders previous stores visible to the current hart before subsequent implicit references to memory-management data structures by the current hart.
RULE 3: Execution of SFENCE.VMA invalidates address-translation cache entries associated with the local hart.
RULE 4: If rs1 = x0 and rs2 = x0, SFENCE.VMA orders all reads and writes made to any level of the page tables for all address spaces.
RULE 5: If rs1 = x0 and rs2 = x0, SFENCE.VMA invalidates all address-translation cache entries for all address spaces.
RULE 6: If rs1 = x0 and rs2 ≠ x0, SFENCE.VMA orders all reads and writes made to any level of the page tables for the address space identified by rs2.
RULE 7: If rs1 = x0 and rs2 ≠ x0, SFENCE.VMA invalidates all address-translation cache entries matching the address space identified by rs2, except for entries containing global mappings.
RULE 8: If rs1 ≠ x0 and rs2 = x0, SFENCE.VMA orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 9: If rs1 ≠ x0 and rs2 = x0, SFENCE.VMA invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 10: If rs1 ≠ x0 and rs2 ≠ x0, SFENCE.VMA orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for the address space identified by rs2.
RULE 11: If rs1 ≠ x0 and rs2 ≠ x0, SFENCE.VMA invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 and match the address space identified by rs2, except for entries containing global mappings.
RULE 12: If the value held in rs1 is not a valid virtual address, SFENCE.VMA has no effect.
