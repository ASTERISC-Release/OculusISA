RULE 1: When a hart is executing in privilege mode x, interrupts are globally enabled if x IE is 1.
RULE 2: When a hart is executing in privilege mode x, interrupts are globally disabled if x IE is 0.
RULE 3: When a hart is executing in privilege mode x, interrupts for lower-privilege modes w < x are always globally disabled regardless of the value of w IE.
RULE 4: When a hart is executing in privilege mode x, interrupts for higher-privilege modes y > x are always globally enabled regardless of the value of y IE.
RULE 5: When a trap is taken from privilege mode y into privilege mode x, x PIE is set to the value of x IE, x IE is set to 0, and x PP is set to y.
RULE 6: When an x RET instruction is executed and x PP holds the value y, x IE is set to x PIE, the privilege mode is changed to y, x PIE is set to 1, and x PP is set to the least-privileged supported mode.
RULE 7: When an x RET instruction is executed and the new privilege mode y is not M, MPRV is set to 0.
RULE 8: The x PP fields can only hold privilege modes up to privilege mode x.
RULE 9: If privilege mode x is not implemented, then x PP is read-only 0.
RULE 10: When the MDT bit is set to 1 by an explicit CSR write, the MIE bit is cleared to 0.
RULE 11: When an explicit CSR write attempts to set the MIE bit to 1, the MIE bit is set to 1 only if the MDT bit is currently 0 or, for RV64, if the MDT bit is being set to 0 by the same write.
RULE 12: When a trap is taken into M-mode, if the MDT bit is 0, the MDT bit is set to 1.
RULE 13: When MRET or SRET is executed in M-mode, the MDT bit is set to 0.
RULE 14: When MRET, SRET, or MNRET is executed and the new privilege mode is U, VS, or VU, sstatus.SDT is set to 0.
RULE 15: When the MNRET instruction is executed, if the new privilege mode is not M, the MDT bit is set to 0.
RULE 16: When MXLEN=32, the SXL and UXL fields do not exist, and SXLEN is 32 and UXLEN is 32.
RULE 17: When MXLEN=64 and S-mode is not supported, SXL is read-only zero.
RULE 18: When MXLEN=64 and U-mode is not supported, UXL is read-only zero.
RULE 19: When S-mode is implemented and MXLEN=64, the set of legal values for UXL excludes those that would cause UXLEN to be greater than SXLEN.
RULE 20: When MPRV is 0, explicit memory accesses behave as normal, using the translation and protection mechanisms of the current privilege mode.
RULE 21: When MPRV is 1, explicit load and store memory addresses are translated and protected as though the current privilege mode were set to MPP.
RULE 22: The MPRV bit does not affect instruction address-translation and protection.
RULE 23: When U-mode is not supported, the MPRV bit is read-only 0.
RULE 24: When an MRET or SRET instruction changes the privilege mode to a mode less privileged than M, MPRV is set to 0.
RULE 25: When MXR is 0, only loads from pages marked readable (R=1) succeed.
RULE 26: When MXR is 1, loads from pages marked readable (R=1) or executable (X=1) succeed.
RULE 27: The MXR bit has no effect when page-based virtual memory is not in effect.
RULE 28: When S-mode is not supported, the MXR bit is read-only 0.
RULE 29: When SUM is 0, S-mode memory accesses to pages that are accessible by U-mode (U=1) fault.
RULE 30: When SUM is 1, S-mode memory accesses to pages that are accessible by U-mode (U=1) are permitted.
RULE 31: The SUM bit has no effect when page-based virtual memory is not in effect.
RULE 32: The SUM bit is in effect when MPRV is 1 and MPP is S.
RULE 33: When S-mode is not supported or if satp.MODE is read-only 0, the SUM bit is read-only 0.
RULE 34: When mstatus.MPRV is 0 and MBE is 0, non-instruction-fetch memory accesses in M-mode are little-endian.
RULE 35: When mstatus.MPRV is 0 and MBE is 1, non-instruction-fetch memory accesses in M-mode are big-endian.
RULE 36: When S-mode is supported and SBE is 0, explicit load and store memory accesses in S-mode are little-endian.
RULE 37: When S-mode is supported and SBE is 1, explicit load and store memory accesses in S-mode are big-endian.
RULE 38: When U-mode is supported and UBE is 0, explicit load and store memory accesses in U-mode are little-endian.
RULE 39: When U-mode is supported and UBE is 1, explicit load and store memory accesses in U-mode are big-endian.
RULE 40: For implicit accesses to supervisor-level memory management data structures, endianness is always controlled by SBE.
RULE 41: If S-mode is supported, SBE may be a read-only copy of MBE.
RULE 42: If U-mode is supported, UBE may be a read-only copy of MBE or SBE.
RULE 43: When MBE, SBE, and UBE are all read-only 0, the implementation supports only little-endian memory accesses.
RULE 44: When MBE is read-only 1, SBE is read-only 1, and UBE is read-only 1, the implementation supports only big-endian memory accesses (aside from instruction fetches).
RULE 45: When TVM is 1, attempts to read or write the satp CSR or execute an SFENCE.VMA or SINVAL.VMA instruction while executing in S-mode raise an illegal-instruction exception.
RULE 46: When TVM is 0, attempts to read or write the satp CSR or execute an SFENCE.VMA or SINVAL.VMA instruction while executing in S-mode are permitted.
RULE 47: When S-mode is not supported, the TVM bit is read-only 0.
RULE 48: When TW is 1, if WFI is executed in a mode less privileged than M and does not complete within an implementation-specific, bounded time limit, the WFI instruction causes an illegal-instruction exception.
RULE 49: When there are no modes less privileged than M, the TW bit is read-only 0.
RULE 50: When S-mode is implemented, executing WFI in U-mode causes an illegal-instruction exception regardless of the value of the TW bit, unless the instruction completes within an implementation-specific, bounded time limit.
RULE 51: When TSR is 1, attempts to execute SRET while executing in S-mode raise an illegal-instruction exception.
RULE 52: When TSR is 0, executing SRET in S-mode is permitted.
RULE 53: When S-mode is not supported, the TSR bit is read-only 0.
RULE 54: The SD bit is set to 1 if any of the FS, VS, or XS fields encode a Dirty state.
RULE 55: If FS, VS, and XS are all read-only zero, the SD bit is set to 0.
RULE 56: If the F extension is implemented, the FS field shall not be read-only zero.
RULE 57: If neither the F extension nor S-mode is implemented, the FS field is read-only zero.
RULE 58: If the v registers are implemented, the VS field shall not be read-only zero.
RULE 59: If neither the v registers nor S-mode is implemented, the VS field is read-only zero.
RULE 60: In harts without additional user-extensions requiring new state, the XS field is read-only zero.
RULE 61: When the FS field is Off, any instruction that attempts to read or write the corresponding state causes an illegal-instruction exception.
RULE 62: When the FS field is Initial and an instruction is executed that possibly modifies state, the FS field transitions to Dirty.
RULE 63: When the FS field is Clean and an instruction is executed that possibly modifies state, the FS field transitions to Dirty.
RULE 64: When the FS field is Dirty and an instruction is executed that possibly modifies state, the FS field remains Dirty.
RULE 65: When the FS field is Off and an instruction is executed to unconfigure unit, the FS field remains Off.
RULE 66: When the FS field is Off and an instruction is executed to disable unit, the FS field transitions to Off.
RULE 67: When the FS field is Off and an instruction is executed to enable unit, the FS field transitions to Initial.
RULE 68: When the VS field is Off, any instruction that attempts to read or write the corresponding state causes an illegal-instruction exception.
RULE 69: When the VS field is Initial and an instruction is executed that possibly modifies state, the VS field transitions to Dirty.
RULE 70: When the VS field is Clean and an instruction is executed that possibly modifies state, the VS field transitions to Dirty.
RULE 71: When the VS field is Dirty and an instruction is executed that possibly modifies state, the VS field remains Dirty.
RULE 72: When the VS field is Off and an instruction is executed to unconfigure unit, the VS field remains Off.
RULE 73: When the VS field is Off and an instruction is executed to disable unit, the VS field transitions to Off.
RULE 74: When the VS field is Off and an instruction is executed to enable unit, the VS field transitions to Initial.
RULE 75: When the XS field is Off, any instruction that attempts to read or write the corresponding state causes an illegal-instruction exception.
RULE 76: When the XS field is Initial and an instruction is executed that possibly modifies state, the XS field transitions to Dirty.
RULE 77: When the XS field is Clean and an instruction is executed that possibly modifies state, the XS field transitions to Dirty.
RULE 78: When the XS field is Dirty and an instruction is executed that possibly modifies state, the XS field remains Dirty.
RULE 79: When the XS field is Off and an instruction is executed to unconfigure unit, the XS field remains Off.
RULE 80: When the XS field is Off and an instruction is executed to disable unit, the XS field transitions to Off.
RULE 81: When the XS field is Off and an instruction is executed to enable unit, the XS field transitions to Initial.
