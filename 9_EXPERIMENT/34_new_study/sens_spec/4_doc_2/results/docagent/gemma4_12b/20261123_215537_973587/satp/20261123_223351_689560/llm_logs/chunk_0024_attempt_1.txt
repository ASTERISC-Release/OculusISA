RULE 1: When V=1, vsatp substitutes for satp for instructions that normally read or modify satp.
RULE 2: When V=1, vsatp controls VS-stage address translation.
RULE 3: vsatp is active for the purposes of the address-translation algorithm unless the effective privilege mode is U and hstatus.HU=0.
RULE 4: When vsatp is active and the effective privilege mode is neither VS nor VU, VS-stage page-table entries' A bits must not be set as a result of speculative execution.
RULE 5: Mispredicted virtual-machine load/store instructions (HLV, HLVX, or HSV) must not cause VS-stage A bits to be set.
RULE 6: When V=0, a write to vsatp with an unsupported MODE value is either ignored or its fields are treated as WARL.
RULE 7: When V=1, a write to satp with an unsupported MODE value is ignored and no write to vsatp is effected.
RULE 8: When V=0, vsatp does not directly affect the behavior of the machine unless a virtual-machine load/store (HLV, HLVX, or HSV) or the MPRV feature in the mstatus register is used to execute a load or store as though V=1.
RULE 9: When V=1, the first stage of two-stage translation for guest virtual addresses is controlled by vsatp.
RULE 10: When V=1, zeroing vsatp effectively disables VS-stage address translation.
RULE 11: When V=1, memory accesses made in support of VS-stage address translation are subject to G-stage address translation alone.
RULE 12: When V=0, SFENCE.VMA applies only to memory-management data structures controlled by the HS-level satp.
RULE 13: When V=1, SFENCE.VMA applies only to memory-management data structures controlled by vsatp.
RULE 14: When V=0, SFENCE.VMA orders stores only to HS-level address-translation structures with subsequent HS-level address translations.
RULE 15: When V=1, SFENCE.VMA orders stores only to VS-level address-translation structures with subsequent VS-stage address translations where the hgatp.VMID is the same.
RULE 16: If vsatp.MODE is not BARE, the pointer masking issue for guest physical addresses does not apply.
