RULE 1: When a trap is taken into M-mode, the MPV bit in mstatus is set to the value of the virtualization mode V at the time of the trap.
RULE 2: When a trap is taken into M-mode, the MPP field in mstatus is set to the nominal privilege mode at the time of the trap.
RULE 3: When an MRET instruction is executed, the MPV bit in mstatus is set to 0.
RULE 4: When an MRET instruction is executed, the MPP field in mstatus is set to 0.
RULE 5: When an MRET instruction is executed, the MIE field in mstatus is set to the value of the MPIE field.
RULE 6: When an MRET instruction is executed, the MPIE field in mstatus is set to 1.
RULE 7: When an MRET instruction is executed, the virtualization mode V is set to the value of the MPV bit in mstatus, unless the MPP field in mstatus is 3, in which case V is set to 0.
RULE 8: When a trap (breakpoint, address misaligned, access fault, page fault, or guest-page fault) that writes a guest virtual address to mtval is taken into M-mode, the GVA field in mstatus is set to 1.
RULE 9: When any trap other than those specified in Rule 8 is taken into M-mode, the GVA field in mstatus is set to 0.
RULE 10: In HS-mode, the TSR and TVM fields of mstatus affect execution.
RULE 11: In VS-mode, the TSR and TVM fields of mstatus do not affect execution.
RULE 12: In all modes except M-mode, the TW field of mstatus affects execution.
RULE 13: In M-mode, the TW field of mstatus does not affect execution.
RULE 14: When the TVM bit in mstatus is set to 1, HS-mode is prevented from accessing the hgatp register.
RULE 15: When the TVM bit in mstatus is set to 1, HS-mode is prevented from executing the HFENCE.GVMA instruction.
RULE 16: When the TVM bit in mstatus is set to 1, HS-mode is prevented from executing the HINVAL.GVMA instruction.
RULE 17: When the TVM bit in mstatus is set to 1, accesses to the vsatp register and the execution of HFENCE.VVMA or HINVAL.VVMA instructions are not affected.
RULE 18: When the MPRV field in mstatus is set to 0, translation and protection behave normally, with the current privilege mode applying.
RULE 19: When the MPRV field in mstatus is 1, the MPV bit is 0, and the MPP field is 0, explicit memory accesses are translated and protected as U-level access with HS-level translation and protection only.
RULE 20: When the MPRV field in mstatus is 1, the MPV bit is 0, and the MPP field is 1, explicit memory accesses are translated and protected as HS-level access with HS-level translation and protection only.
RULE 21: When the MPRV field in mstatus is 1 and the MPP field is 3, explicit memory accesses are translated and protected as M-level access with no translation.
RULE 22: When the MPRV field in mstatus is 1, the MPV bit is 1, and the MPP field is 0, explicit memory accesses are translated and protected as VU-level access with two-stage translation and protection, where the HS-level MXR bit makes any executable page readable, the vsstatus.MXR bit makes those pages readable at the VS translation stage only if they are readable at the guest-physical translation stage, and the vsstatus.SUM bit applies instead of the HS-level SUM bit.
RULE 23: When the MPRV field in mstatus is 1, the MPV bit is 1, and the MPP field is 1, explicit memory accesses are translated and protected as VS-level access with two-stage translation and protection, where the HS-level MXR bit makes any executable page readable, the vsstatus.MXR bit makes those pages readable at the VS translation stage only if they are readable at the guest-physical translation stage, and the vsstatus.SUM bit applies instead of the HS-level SUM bit.
RULE 24: The MPRV field in mstatus does not affect the translation and protection of virtual-machine load/store instructions (HLV, HLVX, and HSV), which always act as though V=1 and the nominal privilege mode is hstatus.SPVP.
