### **1. What is the purpose of the `mdeleg` and `mideleg` registers?**
The `medeleg` (machine exception delegation) and `mideleg` (machine interrupt delegation) registers are used to **delegate certain traps directly to a lower privilege level** (such as S-mode) instead of having them handled in M-mode. This is intended to increase performance by allowing the hardware to process these exceptions directly in the lower level without requiring a machine-mode handler to redirect them.

### **2. How do the `mip` and `mie` registers relate to each other?**
*   **`mip` (Machine Interrupt Pending):** This is an MXLEN-bit read/write register that contains information on **pending interrupts**.
*   **`mie` (Machine Interrupt Enable):** This is the corresponding MXLEN-bit read/write register that contains **interrupt enable bits**.
*   **Relationship:** An interrupt $i$ will trap to M-mode if it is set in both `mip` (pending) and `mie` (enabled) bits, and (if `mideleg` exists) it is not set in the `mideleg` register. Furthermore, the bits in `mip` and `mie` correspond to the same interrupt cause numbers.

### **3. What is the purpose of the `mcycle` and `minstret` registers?**
These are hardware performance-monitoring counters:
*   **`mcycle`**: Counts the number of **clock cycles** executed by the processor core.
*   **`minstret`**: Counts the number of **instructions** the hart has retired.

### **4. Describe the different modes of the `stvec` register.**
The `stvec` register contains a **BASE** address and a **MODE** setting:
*   **Direct (MODE=0):** All traps into supervisor mode cause the PC to be set to the address in the BASE field.
*   **Vectored (MODE=1):** All synchronous exceptions into supervisor mode cause the PC to be set to the BASE address, whereas **interrupts** cause the PC to be set to the BASE address plus four times the interrupt cause number (e.g., a timer interrupt might set the PC to $BASE + 0x14$).

### **5. What is the purpose of the `mtval` register?**
The `mtval` (Machine Trap Value) register is used to **assist software in handling traps** by providing exception-specific information. For example, if a memory access fault occurs, `mtval` may contain the faulting virtual address. It can also be used to return the faulting instruction bits during an illegal-instruction exception or to hold cause information for software-check exceptions.

### **6. What is the purpose of the `mconfigptr` register?**
The `mconfigptr` register holds the **physical address of a configuration data structure**. Software can traverse this structure to discover information about the harts, the platform, and their specific configurations.

### **7. What is the purpose of the `menvcfg` register?**
The `menvcfg` register controls **execution environment characteristics for modes less privileged than M-mode**. It includes various bits for:
*   **FIOM:** Controlling how `FENCE` instructions handle device I/O and memory ordering.
*   **PBMTE:** Enabling the `Svpbmt` extension (Page-Based Memory Types).
*   **ADUE:** Controlling hardware updating of PTE A/D bits.
*   **CDE:** Enabling counter delegation.
*   **STCE:** Enabling supervisor-mode timer interrupts.
*   **CBZE/CBCFE/CBIE:** Enabling cache block zero, clean, and invalidate instructions in lower modes.
*   **PMM:** Enabling/disabling pointer masking for the next-lower privilege mode.
*   **LPE:** Enabling the `Zicfilp` (Landing Pad) extension.
*   **SSE:** Enabling the `Zicfiss` (Shadow Stack) extension.
*   **DTE:** Enabling the `Ssdbltrp` (Double Trap) extension.

### **8. What is the purpose of the `mseccfg` register?**
The `mseccfg` register controls **security features**. It includes:
*   **USEED/SEED:** Controlling access to a seed CSR (used for entropy).
*   **RLB (Rule Locking Bypass):** A mechanism to temporarily modify Locked PMP rules.
*   **MMWP (Machine-Mode Allowlist Policy):** Changes the default PMP policy for M-mode when accessing memory without a matching rule (to "denied" instead of "ignored").
*   **MML (Machine Mode Lockdown):** Changes the interpretation of the `pmpcfg.L` bit to make rules M-mode-only or S/U-mode-only.
*   **PMM:** Controlling pointer masking for M-mode.
*   **MLPE:** Enabling the `Zicfilp` extension in M-mode.

### **10. What is the purpose of the `mepc` register?**

### **12. What is the purpose of the `mnepc` register?**
