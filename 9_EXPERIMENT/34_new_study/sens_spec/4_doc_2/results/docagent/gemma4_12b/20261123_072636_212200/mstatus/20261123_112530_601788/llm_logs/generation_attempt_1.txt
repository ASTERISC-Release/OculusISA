Based on the provided RISC-V Privileged Architecture specification, here are the answers to your questions:

### 1. What is the function of the `mcycle` register?
The `mcycle` register counts the **number of clock cycles executed** by the processor core on which the hart is running. It has 64-bit precision on all RV32 and RV64 harts.

### 2. What is the function of the `minstret` register?
The `minstret` register counts the **number of instructions** the hart has retired. Like `mcycle`, it has 64-bit precision on all RV32 and RV64 harts.

### 3. How are the `mcycle` and `minstret` registers related to the `mcountinhibit` register?
The `mcountinhibit` register is used to **inhibit the incrementing** of the counters. Specifically:
*   If the **CY** bit in `mcountinhibit` is clear, `mcycle` increments as usual. If it is set, `mcycle` does not increment.
*   If the **IR** bit in `mcountinhibit` is clear, `minstret` increments as usual. If it is set, `minstret` does not increment.
*   The goal of this mechanism is to reduce energy consumption when these counters are not needed.

### 4. What is the difference between `mcycle` and `time`?
*   **`mcycle`** is a cycle counter that counts the number of clock cycles executed by the processor core.
*   **`time`** is a real-time counter (wall-clock time). It is provided by a memory-mapped register (`mtime`) that increments at a constant frequency. Unlike `mcycle`, which may be affected by clock frequency changes (DVFS), `time` is designed to support processors with variable clock frequencies to save energy.

### 5. What are the three types of "external" interrupts mentioned in the text?
The text identifies three types of supervisor-level external interrupts (SEI):
1.  **Supervisor external interrupt** (Standard)
2.  **Virtual supervisor external interrupt** (Used in VS-mode, delegated from guest external interrupts)
3.  **Supervisor guest external interrupt** (Specifically for guest external interrupts at the HS-level)

### 6. What is a "double trap" and what is the purpose of the `Ssdbltrp` extension?
A **double trap** occurs when a trap is taken into a privilege mode lower than M-mode (like S-mode or VS-mode) that is already in a "trap" state (e.g., an interrupt occurring during the tail phase of a previous trap).

The **`Ssdbltrp` extension** is designed to handle these cases by:
*   Providing a mechanism for M-mode to invoke a critical error handler in a virtual machine on a double trap in VS-mode.
*   Allowing M-mode to invoke a critical error handler in the OS/Hypervisor on a double trap in S/HS-mode.
*   It adds the `SDT` (S-mode-disable-trap) bit to `sstatus` to track and manage this state.

### 7. What are the two different ways a page-fault exception can be raised in Sv32?
According to the **Sv32 Virtual Address Translation Process** (Section 12.3.2), a page-fault exception is raised in the following ways:
1.  **Standard Page Fault:** Raised if the Page Table Entry (PTE) is invalid (V=0), if it lacks required permissions (R=0, W=0, or X=0), or if it contains reserved bits.
2.  **Double Trap Page Fault (via `Ssdbltrp`):** If the `SDT` bit is set to 1 and a trap is attempted, it is treated as an "unexpected trap" and a double-trap exception (cause code 16) is delivered into M-mode instead of the intended S-mode trap. (Alternatively, if `Svade` is implemented, a page-fault is raised if A/D bits need to be set but cannot be).

### 8. What is "SV-stage" and "G-stage" address translation?
These are the two stages of address translation used when the **Hypervisor extension (H)** is active (V=1):
*   **VS-stage (Virtual Supervisor stage):** Translates a **guest virtual address** to a **guest physical address**. It is controlled by the `vsatp` register.
*   **G-stage (Guest-physical stage):** Translates the **guest physical address** to a **supervisor physical address**. It is controlled by the `hgatp` register.

### 9. What is the function of the `mstatus.MPV` bit?
The `mstatus.MPV` (Machine Previous Virtualization) bit is written by the hardware whenever a trap is taken into M-mode. It records the **virtualization mode (V)** at the time of the trap. This allows M-mode to know if the hart was in VS-mode or VU-mode before the trap occurred.

### 10. What is a "virtual-instruction exception"?
A **virtual-instruction exception** is a specific type of exception (cause code 22) used primarily in the Hypervisor extension (H). It is raised in VS-mode or VU-mode when:
*   A hypervisor instruction (HLV, HLVX, HSV, etc.) is executed.
*   A non-high-half hypervisor CSR is accessed.
*   A high-half counter CSR is accessed (when XLEN=32).
*   A software instruction is attempted that is prevented by the `hstatus.VTW` or `hstatus.VTSR` bits.
*   An attempt to access `vsatp` or `hgatp` is made when `mstatus.TVM` is set.

### 11. What is "pointer masking" and what is its purpose?
**Pointer masking** is a feature that causes the CPU to ignore the upper bits (tag bits) of an effective address during memory access. 
*   **Purpose:** It is primarily used for dynamic safety checkers like **HWASAN**. By storing "tags" in the upper bits of a pointer and comparing them against a side table, the system can identify memory errors (like use-after-free or buffer overflows) with minimal performance overhead, as the hardware automatically "masks out" the tags during standard memory operations.

### 12. What is "Standardization" and how does it apply to "Count Overflow" interrupts?
In this context, **Standardization** refers to the process of defining a consistent architectural behavior for a feature so that software can run across different hardware implementations without modification.
*   **Application to Count Overflow:** The **`Sscofpmf` extension** standardizes the `mhpmevent` CSRs. It ensures that all hardware implementations provide the same **OF (Overflow status/interrupt disable)** bit and **INH (Inhibit)** bits for different privilege modes. This allows OS developers to write a single overflow interrupt handler that works regardless of the specific hardware manufacturer.

### 13. What is the purpose of the `mcounteren` register?
The `mcounteren` register is a **counter-enable** register. It controls the **accessibility** of the hardware performance-monitoring counters (cycle, time, instret, and HPM counters) to the next-lower privileged mode (S-mode or U-mode). If a bit in `mcounteren` is clear, an attempt to read the corresponding counter from a lower privilege mode will cause an **illegal-instruction exception**.

### 14. What is "Shadow Stack" and how does the `Zicfiss` extension implement it?
A **Shadow Stack** is a memory region used to store return addresses to defend against return-oriented programming (ROP) attacks.
*   **Implementation:** The `Zicfiss` extension introduces:
    *   A **Shadow Stack Pointer (ssp)** CSR.
    *   A **Shadow Stack-Enabled (SSE)** state bit in `sstatus`.
    *   **Shadow Stack pages:** A new PTE type (R=0, W=1, X=0) that restricts writes to only the `SSAMOSWAP` instruction.
    *   **Instructions:** `SSPUSH` and `SSPOPCHK` to push and verify return addresses on the shadow stack.

### 15. What is "Remote Trap" and how does the `Smrnmi` extension facilitate it?
A **Remote Trap** (or Resumable Non-Maskable Interrupt - RNMI) is an interrupt that can be taken and then "resumed," meaning the processor can return to the exact instruction that was interrupted (rather than jumping to a new execution point).
*   **Facilitation:** The `Smrnmi` extension adds:
    *   **mnepc, mncause, mnstatus, and mnscratch** CSRs to hold the interrupted state (PC, cause, privilege mode, and a scratch register).
    *   The **MNRET** instruction, which restores the state from these registers and returns the hart to the original instruction.
    *   Unlike standard NMIs, which are "unresumable" (overwriting the `mepc`), RNMIs allow the hart to handle a critical error and then continue execution.

### 16. What is "Virtual Machine Identifier (VMID)" and how does it interact with "Address Translation Cache"?
The **VMID** is a unique identifier for a virtual machine (guest) in a multi-tenant hypervisor environment. 
*   **Interaction:** It is used in the **G-stage (Guest-physical stage)** of address translation. The address translation cache (TLB) uses the VMID to distinguish between different guests. If two different guests map the same guest physical address to different supervisor physical addresses, the TLB entries must be tagged with the VMID to ensure that Guest A cannot access Guest B's memory through a cached translation.

### 17. What is "Privilege Mode" and how do "M-mode", "S-mode", and "U-mode" differ?
**Privilege Mode** determines what instructions a hart can execute and which memory regions it can access.
*   **M-mode (Machine):** The highest privilege level. It has full access to all hardware resources, including all CSRs and all physical memory. It handles low-level system tasks, firmware, and device management.
*   **S-mode (Supervisor):** The standard level for operating systems (like Linux). It has restricted access to hardware and CSRs; it relies on M-mode (or a hypervisor) for managing timers, interrupts, and physical memory.
*   **U-mode (User):** The lowest privilege level for applications. It has the most restricted access and cannot execute most privileged instructions or access CSRs directly.

### 18. What is the "S-mode" and what is its role in a "Hypervisor"?
**S-mode** is the Supervisor mode, intended for running an operating system. 
*   **Role in a Hypervisor:** In a system with the **Hypervisor (H) extension**, a hypervisor can run in **HS-mode** (Hypervisor-extended Supervisor mode). In this mode, the hypervisor manages a guest OS running in **VS-mode** (Virtual Supervisor mode). The hypervisor uses its own set of CSRs (like `hgatp`) to manage the second stage of address translation (G-stage) for the guest.

### 19. What is "Address Translation" and what is the difference between "Virtual" and "Physical" addresses?
**Address Translation** is the process of converting a **Virtual Address** (used by software) into a **Physical Address** (the actual location in hardware memory).
*   **Virtual Address:** A logical address generated by a program. It allows each process to have its own private address space (e.g., every program thinks it starts at address 0).
*   **Physical Address:** The actual address of a memory cell in the physical RAM or on-chip memory.
*   **The Difference:** The translation (managed by page tables and the `satp` CSR) allows the hardware to map a single virtual address to a specific physical address. This enables memory protection (isolating programs) and memory virtualization (allowing multiple programs to share physical RAM).

### 20. What is "PMP" and how does it differ from "Page Tables"?
**PMP (Physical Memory Protection)** is a hardware mechanism to define access rights (Read, Write, Execute) to regions of **physical memory**.
*   **PMP:** Operates on **physical addresses**. It is usually managed by M-mode and provides a "hard" security boundary. It is independent of whether paging is enabled.
*   **Page Tables:** Operate on **virtual addresses** to provide memory isolation between processes (U-mode and S-mode). They translate virtual addresses to physical ones and can also define permissions.
*   **Key Difference:** PMP is the final gatekeeper for physical memory, while Page Tables are the mechanism for virtual memory management.

### 21. What is "Fence" and how does "SFENCE.VMA" work?
A **Fence** instruction is used to enforce ordering between memory accesses, ensuring that a write to one location is "visible" to other parts of the system before a subsequent read or write occurs.
*   **SFENCE.VMA:** Specifically synchronizes updates to **memory-management data structures** (like page tables). Because page tables are often cached in a TLB or hardware walker, a simple store to a page table entry might not be "seen" by the hardware immediately. `SFENCE.VMA` tells the hardware to flush those specific entries from its internal caches, ensuring that the next memory access uses the updated translation.

### 22. What is "TLB" and what is "TLB Hit" and "TLB Miss"?
A **TLB (Translation Lookaside Buffer)** is a small, high-speed hardware cache that stores recent translations from virtual addresses to physical addresses.
*   **TLB Hit:** When the CPU looks up a virtual address and the translation is found in the TLB. This is very fast and allows the CPU to proceed with the memory access immediately.
*   **TLB Miss:** When the translation is NOT in the TLB. The hardware (or software) must then perform a **Page Table Walk**, which involves reading multiple entries from physical memory. This is much slower than a hit.

### 23. What is "AMO" and what are its types?
**AMO** stands for **Atomic Memory Operations**. These are instructions that perform a read-modify-write operation on a memory location as a single, indivisible (atomic) unit.
*   **Types:** The text mentions several types defined by the "A" extension:
    *   `amoswap` (Swap)
    *   `amoand` (Logical AND)
    *   `amoor` (Logical OR)
    *   `amoxor` (Logical XOR)
    *   `amoadd` (Arithmetic Add)
    *   `amomin` (Arithmetic Min)
    *   `amomax` (Arithmetic Max)
    *   `amomiu` (Arithmetic Min Unsigned)
    *   `amomaxu` (Arithmetic Max Unsigned)

### 24. What is "Page Fault" and what is "Page Table Walk"?
A **Page Fault** is an exception raised by the hardware when a program tries to access a virtual address that is not currently mapped to a valid physical page in the page tables.
*   **Page Table Walk:** This is the process by which the hardware (or software) traverses a multi-level tree of **Page Table Entries (PTEs)** to find the mapping for a virtual address. 
*   **The Relation:** If a "Page Table Walk" fails (e.g., it finds an entry with the "Valid" bit set to 0), the hardware triggers a **Page Fault** exception, allowing the Operating System to handle it (e.g., by loading the page from disk or terminating the program).

### 25. What is "Cache" and what are "Read-only", "Write-only", and "Execute-only" permissions?
A **Cache** is a high-speed memory storage area (like L1, L2, or L3) that stores copies of frequently accessed data from the main memory (RAM) to speed up processing.
*   **Read-only:** The cache/memory can be read from, but any attempt to write to it will trigger an access fault.
*   **Write-only:** The memory can be written to, but any attempt to read from it will trigger an access fault. (Note: This is rare in most systems).
*   **Execute-only:** The memory can be fetched as an instruction (executed), but any attempt to read from it as data or write to it will trigger an access fault. This is often used for security to prevent "reading" the code of a program.

### 26. What is "Interrupt" and what is "NMI"?
An **Interrupt** is a signal to the processor emitted by hardware or software indicating an event that needs immediate attention. The processor pauses its current task, jumps to an interrupt handler, and then returns.
*   **NMI (Non-Maskable Interrupt):** A special type of interrupt that **cannot be disabled** (masked) by software. It is reserved for critical hardware errors (like a power failure or memory parity error) where the system must take immediate action regardless of the current software state.

### 27. What is "SBI" and how does it work?
**SBI (Supervisor Binary Interface)** is a standardized set of functions provided by a low-level software environment (like firmware or a hypervisor) to the Supervisor (S-mode) software.
*   **How it works:** When an OS needs to perform a task that it is not allowed to do directly (like reading a hardware timer or requesting an interprocessor interrupt), it makes an **ECALL** to the SBI. The SBI implementation then performs the task on behalf of the OS and returns the result. It acts as an abstraction layer between the OS and the raw hardware.

### 28. What is "Context Switch" and how does "mscratch" help?
A **Context Switch** is the process of the OS saving the state (registers, PC, etc.) of one running task/thread and restoring the state of another so that they can share a single CPU core.
*   **mscratch:** This is a Machine-mode register. In a context switch (specifically during a trap to M-mode), `mscratch` is used to hold a pointer to the hart-local context space. Software can swap the contents of `mscratch` with a general-purpose register to safely save and restore the registers of the interrupted task without overwriting them.

### 29. What is "Trap" and what is "Exception"?
Both are events that cause the processor to stop its current execution and jump to a predefined handler.
*   **Exception:** A **synchronous** event caused by the execution of an instruction. For example, an "Illegal Instruction" or a "Page Fault" is an exception because it happens exactly at the moment the instruction is processed.
*   **Trap:** A general term that includes both exceptions and **asynchronous interrupts**. An **Interrupt** (like a timer or a button press) is a trap because it happens independently of the current instruction's execution. In RISC-V, "Trap" is the overarching category for both.

### 30. What is "Privilege Mode" and what are "M-mode", "S-mode", and "U-mode"?
**Privilege Mode** determines the level of authority a piece of software has over the hardware and memory. RISC-V uses three main modes:
*   **M-mode (Machine):** The highest privilege level. It has complete access to all hardware resources. It is used for firmware and low-level system management.
*   **S-mode (Supervisor):** The level used by standard operating systems (like Linux or Windows). It has restricted access to hardware and is managed by the OS kernel.
*   **U-mode (User):** The lowest privilege level, where standard applications (like a web browser or a game) run. It is highly restricted to ensure that a bug or malicious act in an app cannot crash the entire system.

### 31. What is "Register" and what is "CSR"?
A **Register** is a small, high-speed storage location inside the CPU used to hold data or instruction addresses during execution.
*   **CSR (Control and Status Register):** A special type of register used to control the processor's behavior (like enabling interrupts, setting privilege modes, or configuring timers) and to report the status of the processor (like reporting an interrupt cause). CSRs are generally only accessible from privileged modes (M, S, or HS).

### 32. What is "Instruction" and what is "Opcode"?
An **Instruction** is a command given to the processor to perform a specific action (like adding two numbers, loading a value from memory, or jumping to a new location).
*   **Opcode (Operation Code):** The part of the instruction that identifies the specific operation to be performed. For example, in a "Load Word" instruction, the opcode is the specific binary pattern that tells the hardware "this is a load operation" rather than a "store" or "add" operation.

### 33. What is "Memory" and what is "Physical Memory"?
**Memory** is the general term for the storage area (RAM, Flash, etc.) where data and instructions are kept.
*   **Physical Memory:** Refers to the actual, physical hardware addresses of the memory chips. It is the "true" location of the data. In a system with virtual memory, the program sees a **Virtual Address**, but the hardware uses the **Physical Address** to actually access the data.

### 34. What is "Bus" and what is "Interconnect"?
*   **Bus:** A communication pathway that connects different components of a computer system (like the CPU, memory, and peripherals) and allows them to exchange data.
*   **Interconnect:** A broader term for the complex network of wires, logic, and protocols that link various components of a System-on-Chip (SoC). While "Bus" often refers to a specific standard (like AXI or AHB), "Interconnect" describes the overall architecture that manages traffic between all the components.

### 35. What is "Hart" and what is "Core"?
*   **Hart:** A RISC-V specific term for a "hardware thread." A hart is the smallest unit of execution in a RISC-V system.
*   **Core:** A physical processor unit on a chip.
*   **Difference:** A single physical **Core** can support multiple **Harts** (Hardware Threads). For example, a "Dual-core, Quad-hart" system has two physical cores, each capable of executing two threads simultaneously.

### 36. What is "Clock" and what is "Frequency"?
*   **Clock:** A periodic signal (a pulse) that synchronizes the actions of the processor. Each "tick" of the clock allows the processor to perform a step of an instruction.
*   **Frequency:** The speed at which the clock pulses occur, measured in Hertz (Hz). For example, a 2.0 GHz clock means the processor receives 2 billion "ticks" every second. High frequency generally leads to faster execution of instructions.

### 37. What is "Pipeline" and what is "Stall"?
*   **Pipeline:** A technique where the processor overlaps the execution of multiple instructions. Similar to an assembly line, different stages of multiple instructions (Fetch, Decode, Execute, Memory, Writeback) are processed simultaneously.
*   **Stall:** A delay in the pipeline. If an instruction is waiting for data from memory or a result from a previous calculation, the pipeline must "stall" (pause) the progress of subsequent instructions until the required data is available.

### 38. What is "Cycle" and what is "Instret"?
*   **Cycle:** A single tick of the processor's clock. The `mcycle` register counts how many of these have occurred.
*   **Instret:** A count of the number of instructions that have been "retired" (completed successfully). The `minstret` register tracks this value. 
*   **Difference:** One instruction can take many cycles to complete (e.g., a complex operation or a memory load), but one cycle does not always complete an instruction.

### 39. What is "State" and what is "Context"?
*   **State:** The current "snapshot" of a processor's internal data, including the values in its registers, the Program Counter (PC), and various status bits (like interrupt enable bits).
*   **Context:** The collection of all data that defines the environment of a specific task or thread. During a **Context Switch**, the OS saves the "state" of one task into a "context" structure and restores the state of another task from its respective "context" structure.

### 40. What is "Register" and what is "Operand"?
*   **Register:** A small, high-speed internal storage cell within the CPU (e.g., `x1`, `x2`, `t0`).
*   **Operand:** The actual data or the location of the data being acted upon by an instruction. For example, in the instruction `add x1, x2, x3`, the **operands** are the values contained in registers `x2` and `x3`, and the **destination** is register `x1`.

### 41. What is "Instruction" and what is "Immediate"?
*   **Instruction:** A command that tells the CPU what to do (e.g., "add these two numbers").
*   **Immediate:** A constant value that is "embedded" directly within the instruction itself, rather than being read from a register or memory. For example, in `addi x1, x2, 10`, the number `10` is an **immediate** value.

### 42. What is "Memory" and what is "Load/Store"?
*   **Memory:** The storage area (RAM, Flash, etc.) where data is kept.
*   **Load:** An instruction that copies data from a memory location into a CPU register.
*   **Store:** An instruction that copies data from a CPU register into a memory location.
*   **Load/Store Architecture:** A design philosophy (like RISC-V) where the only instructions that can access memory are specifically "Load" and "Store" instructions. All other instructions (like "Add" or "Sub") only operate on registers.

### 43. What is "Address" and what is "Effective Address"?
*   **Address:** A general term for a identifier for a location in memory or a register.
*   **Effective Address:** The final, calculated address used by the processor to access memory during the execution of a specific instruction. It may be calculated by taking a base register and adding an immediate offset (e.g., `x10 + 4`).

### 44. What is "Translation" and what is "Page Table"?
*   **Translation:** The process of converting a **Virtual Address** (what the program sees) into a **Physical Address** (where the data actually is in RAM).
*   **Page Table:** A data structure (a "map") stored in memory that contains the rules for this translation. Each entry in the table (a **PTE**) tells the hardware which physical page corresponds to a specific virtual page and what the permissions (Read/Write/Execute) are.

### 45. What is "Virtual Memory" and what is "Physical Memory"?
*   **Virtual Memory:** A memory management technique that creates an illusion for each program that it has a large, private, contiguous block of memory. The program uses **Virtual Addresses**.
*   **Physical Memory:** The actual hardware RAM of the computer.
*   **Relationship:** Virtual memory allows the system to run programs larger than the available physical RAM by "swapping" parts of the virtual memory to disk, and it allows multiple programs to run simultaneously without interfering with each other's memory.

### 46. What is "Privilege" and what is "Mode"?
*   **Privilege:** The level of authority a piece of software has to perform certain actions or access specific hardware.
*   **Mode:** The actual state of the processor that enforces these privilege levels. In RISC-V, this is expressed through modes like **M-mode**, **S-mode**, and **U-mode**.

### 47. What is "Trap" and what is "Exception"?
*   **Trap:** A general term for any event that causes the processor to stop its current execution and jump to a special handler.
*   **Exception:** A **synchronous** trap—it is caused by the execution of an instruction. Examples include a "Page Fault" or an "Illegal Instruction."
*   **Interrupt:** An **asynchronous** trap—it is caused by an external event (like a timer or a button press) and is not tied to a specific instruction.

### 48. What is "Interrupt" and what is "Maskable"?
*   **Interrupt:** A signal from hardware or software that tells the CPU to pause its current task and handle an event.
*   **Maskable:** An interrupt that can be "ignored" (masked) by the CPU while it is doing other work. For example, a timer interrupt can be masked while a high-priority task is running.
*   **Non-Maskable Interrupt (NMI):** An interrupt that **cannot** be ignored and must be handled immediately by the CPU.

### 49. What is "CSR" and what is "mstatus"?
*   **CSR (Control and Status Register):** A special register used to control the CPU's behavior (e.g., turning on interrupts, changing privilege modes).
*   **mstatus:** The most important CSR in RISC-V. It holds the **Machine Status** of the processor, including the current privilege mode, the global interrupt enable bit, and bits for CSR tracking.

### 50. What is "RV32" and what is "RV64"?
*   **RV32:** A RISC-V architecture where the registers and the general-purpose registers are **32 bits wide**.
*   **RV64:** A RISC-V architecture where the registers are **64 bits wide**.
*   **Difference:** RV64 allows for much larger memory addressing and larger integer values but requires more hardware resources than RV32.

### 51. What is "XLEN" and what is "MXLEN"?
*   **XLEN:** The number of bits in the standard general-purpose registers (e.g., 32 for RV32, 64 for RV64).
*   **MXLEN:** The number of bits in the **Machine-mode** CSRs. This is often larger than XLEN to allow the machine mode to access more address space or wider status information.

### 52. What is "Privileged ISA" and what is "Unprivileged ISA"?
*   **Unprivileged ISA:** The set of instructions that can be executed in **User (U) mode**. These are the instructions used by standard applications.
*   **Privileged ISA:** The set of instructions that can only be executed in **Machine (M)** or **Supervisor (S)** modes. These are used by the operating system, firmware, and hypervisors to manage the system.

### 53. What is "SBI" and what is "ECALL"?
*   **SBI (Supervisor Binary Interface):** A standardized set of functions provided by firmware or a hypervisor to the Operating System.
*   **ECALL:** The instruction used by a program to "call" the SBI or any higher-privilege mode. It triggers a trap that allows the higher-privilege mode to perform a task (like reading a timer) and return the result to the lower-privilege mode.

### 54. What is "Page Table" and what is "PTE"?
*   **Page Table:** A data structure (a "map" in memory) that stores the rules for converting **Virtual Addresses** to **Physical Addresses**.
*   **PTE (Page Table Entry):** A single entry in the Page Table. It contains the physical address of the page, as well as "permissions" (Read, Write, Execute) and "status bits" (Valid, Dirty, Accessed).

### 55. What is "TLB" and what is "TLB Miss"?
*   **TLB (Translation Lookaside Buffer):** A small, high-speed hardware cache that stores the most recent **Virtual-to-Physical Address** translations.
*   **TLB Miss:** Occurs when the CPU looks for a translation in the TLB and it is **not** found. The hardware must then perform a "Page Table Walk" (reading from the actual page tables in memory) to find the correct translation and then update the TLB.

### 56. What is "ASID" and what is "VMID"?
*   **ASID (Address Space Identifier):** A unique ID used to distinguish between different processes (Address Spaces) in the TLB. It allows the OS to switch between processes without flushing the entire TLB.
*   **VMID (Virtual Machine Identifier):** A unique ID used in the **Hypervisor extension** to distinguish between different Virtual Machines (Guests) in the translation cache. It is similar to ASID but for virtualization.

### 57. What is "PMA" and what is "PMP"?
*   **PMA (Physical Memory Attribute):** Defines the **properties** of a memory region (e.g., is it cacheable? is it I/O memory? is it strongly ordered?).
*   **PMP (Physical Memory Protection):** Defines the **permissions** (Read, Write, Execute) for a physical memory region.
*   **Difference:** PMA tells the CPU *how* to access memory; PMP tells the CPU *if* it is allowed to access it.

### 58. What is "PMLEN" and what is "Pointer Masking"?
*   **PMLEN:** A configurable number of bits at the top of a pointer that are intended to be "masked" or ignored by the hardware.
*   **Pointer Masking:** A feature that tells the hardware to automatically "mask out" (set to zero or sign-extend) those top bits during memory access. This is used for **HWASAN** and other safety tools to store "tags" in the upper bits of a pointer without those tags affecting the actual physical address accessed.

### 59. What is "Memory Model" and what is "RVWMO"?
*   **Memory Model:** A set of rules that defines the order in which memory operations (loads and stores) are seen by different processors in a multi-core system.
*   **RVWMO (RISC-V Weak Memory Ordering):** The standard memory model for RISC-V. It allows for high performance by letting the hardware reorder certain memory operations, unless the programmer explicitly uses a **Fence** instruction to enforce a specific order.

### 60. What is "Atomic" and what is "AMO"?
*   **Atomic:** An operation that is "indivisible." It happens all at once, and no other processor can see the operation in a partially-completed state.
*   **AMO (Atomic Memory Operation):** A specific type of instruction (like "Atomic Add") that performs a read-modify-write operation as a single, atomic step in memory.

### 61. What is "Root Page Table" and what is "PPN"?
*   **Root Page Table:** The very first page table in a multi-level page table tree. Its address is stored in the `satp` CSR.
*   **PPN (Physical Page Number):** The identifier for a page in physical memory. Since pages are usually 4 KiB, a PPN is the physical address divided by 4096 (e.g., a PPN of 0x1000 refers to physical address 0x1000000).

### 62. What is "Shadow Stack" and what is "RAS"?
*   **Shadow Stack:** A secondary stack (separate from the normal data stack) used specifically to store return addresses. It helps prevent "Return-Oriented Programming" (ROP) attacks by ensuring that return addresses haven't been tampered with.
*   **RAS (Return Address Stack):** A hardware structure (or software emulation) that predicts the next return address to improve performance by pre-fetching instructions.

### 63. What is "Context Switch" and what is "mscratch"?
*   **Context Switch:** The process of a CPU switching from executing one thread/process to another by saving the "state" (registers, PC) of the first and loading the state of the second.
*   **mscratch:** A Machine-mode register used during a context switch. It typically holds a pointer to the "hart-local context space," allowing the system to save and restore registers safely.

### 64. What is "Trap" and what is "mepc"?
*   **Trap:** Any event (interrupt or exception) that causes the processor to jump to a special handler.
*   **mepc (Machine Exception Program Counter):** A CSR that holds the address of the instruction that was interrupted or caused the trap. When a trap occurs, the hardware writes the "old" PC into `mepc` so the processor can return to it later.

### 65. What is "Trap Cause" and what is "mcause"?
*   **Trap Cause:** The specific reason a trap occurred (e.g., "Integer Overflow", "Page Fault", or "Timer Interrupt").
*   **mcause (Machine Cause):** A CSR that holds the "cause code" of the last trap taken into Machine-mode. It tells the software *why* it was called.

### 66. What is "Trap Value" and what is "mtval"?
*   **Trap Value:** Additional information provided by the hardware to the software handler to help it solve the problem caused by the trap.
*   **mtval (Machine Trap Value):** A CSR that holds this extra data. For a "Page Fault," it might hold the specific virtual address that failed. For a "Load Address Misaligned" error, it might hold the address that was misaligned.

### 67. What is "Machine Mode" and what is "S-mode"?
*   **Machine Mode (M-mode):** The highest privilege level in RISC-V. It has full access to the entire system.
*   **Supervisor Mode (S-mode):** The level where the Operating System (OS) usually runs. It has restricted access and is managed by the OS kernel.

### 68. What is "Privilege Mode" and what is "User Mode"?
*   **Privilege Mode:** A security concept where different levels of authority are defined (M, S, U).
*   **User Mode (U-mode):** The lowest privilege level. Applications run here. They are restricted from accessing hardware directly and cannot execute privileged instructions.

### 69. What is "Hypervisor" and what is "HS-mode"?
*   **Hypervisor:** Software (like KVM or Xen) that runs multiple "guest" operating systems on a single piece of hardware.
*   **HS-mode (Hypervisor-extended Supervisor mode):** A special "privilege mode" introduced by the RISC-V Hypervisor extension. It allows the hypervisor to manage the guest OSs efficiently by providing "two-stage" address translation and extra CSRs specifically for virtualization.

### 70. What is "Virtual Machine" and what is "VS-mode"?
*   **Virtual Machine (VM):** A software emulation of a physical computer.
*   **VS-mode (Virtual Supervisor mode):** The privilege mode where the **Guest OS** runs. It is "virtualized" because its memory accesses are translated twice (once by the guest OS, once by the hypervisor).

### 71. What is "Address Translation" and what is "Bare Mode"?
*   **Address Translation:** The process of converting a virtual address to a physical address.
*   **Bare Mode:** A state where **no translation** occurs. The virtual address is equal to the physical address. This is often used in "bare-metal" firmware or simple embedded systems.

### 72. What is "Instruction" and what is "Load/Store"?
*   **Instruction:** A command (like `add` or `jump`) that tells the CPU what to do.
*   **Load/Store:** A specific type of instruction in the RISC-V architecture where only these instructions can move data between the CPU registers and the computer's memory (RAM).

### 73. What is "CSR" and what is "satp"?
*   **CSR (Control and Status Register):** A special register for controlling the CPU (e.g., turning on interrupts).
*   **satp (Supervisor Address Translation and Protection):** A critical CSR used by the OS to control the **Page Tables**. It holds the "Root Page Table" address and defines the "Address Translation Mode" (e.g., Sv39).

### 74. What is "Page Table" and what is "PTE"?
*   **Page Table:** A map in memory that translates virtual addresses to physical addresses.
*   **PTE (Page Table Entry):** A single "row" in that map. It contains the physical page address and the "permissions" (Read, Write, Execute).

### 75. What is "Fence" and what is "SFENCE.VMA"?
*   **Fence:** An instruction that ensures memory operations happen in a specific order.
*   **SFENCE.VMA:** A specialized fence used to synchronize the **Page Tables**. Because the hardware caches translations (in the TLB), a simple store to a page table might not be seen immediately. `SFENCE.VMA` forces the hardware to flush those cached translations.

### 76. What is "Interrupt" and what is "Non-Maskable Interrupt (NMI)"?
*   **Interrupt:** A hardware signal that tells the CPU to stop what it's doing and handle an event (like a mouse click or a timer).
*   **NMI (Non-Maskable Interrupt):** A high-priority interrupt that **cannot be ignored** (masked) by software. It is used for emergency "critical errors" (e.g., hardware failure).

### 77. What is "RV32" and what is "RV64"?
*   **RV32:** A RISC-V version where registers are **32 bits wide**.
*   **RV64:** A RISC-V version where registers are **64 bits wide**.

### 78. What is "Privilege Mode" and what is "Machine Mode"?
*   **Privilege Mode:** A system that defines levels of authority (high to low).
*   **Machine Mode (M-mode):** The **highest** privilege level in RISC-V. It can do anything and has access to all hardware.

### 79. What is "Trap" and what is "Exception"?
*   **Trap:** A general event that causes the CPU to jump to a handler.
*   **Exception:** A **synchronous** trap caused by an instruction (e.g., dividing by zero or a page fault).

### 80. What is "CSR" and what is "mstatus"?
*   **CSR (Control and Status Register):** Registers used to control and monitor the CPU's behavior.
*   **mstatus:** The primary machine-mode CSR. It holds the "Status" of the CPU, such as the current privilege mode and the global interrupt enable bit.

### 81. What is "Instruction" and what is "Opcode"?
*   **Instruction:** A command for the CPU (e.g., "Add").
*   **Opcode:** The specific part of the instruction's binary code that identifies the action (e.g., the part that says "this is an Addition").

### 82. What is "Memory" and what is "Physical Memory"?
*   **Memory:** The general storage (RAM, etc.).
*   **Physical Memory:** The actual hardware RAM addresses.

### 83. What is "Register" and what is "Operand"?
*   **Register:** A small, ultra-fast storage spot inside the CPU (e.g., `x1`).
*   **Operand:** The data or the location of the data being used by an instruction.

### 84. What is "Address" and what is "Effective Address"?
*   **Address:** A general location identifier.
*   **Effective Address:** The final calculated address used to access memory (e.g., Base + Offset).

### 85. What is "Privilege" and what is "User Mode"?
*   **Privilege:** The level of authority a program has.
*   **User Mode (U-mode):** The lowest privilege level where standard applications run.

### 86. What is "Bus" and what is "Interconnect"?
*   **Bus:** A communication pathway between components (e.g., CPU to RAM).
*   **Interconnect:** The overall complex network (wiring + logic) connecting everything in a chip.

### 87. What is "Cycle" and what is "Instret"?
*   **Cycle:** One "tick" of the clock (measured by `mcycle`).
*   **Instret:** A count of instructions that have finished executing (retired).

### 88. What is "Virtual Memory" and what is "Page Table"?
*   **Virtual Memory:** A technique that gives every program its own private memory space.
*   **Page Table:** The "map" in memory that tells the hardware how to turn virtual addresses into real physical ones.

### 89. What is "Page Fault" and what is "Page Table Walk"?
*   **Page Fault:** An exception when a program tries to access a page that isn't in memory.
*   **Page Table Walk:** The process of reading the "map" (Page Table) to find where a page is located.

### 90. What is "Fence" and what is "SFENCE.VMA"?
*   **Fence:** An instruction that ensures memory operations happen in a specific order.
*   **SFENCE.VMA:** A special fence for "Page Tables" to flush the internal caches (TLB) of those translations.

### 91. What is "Hypervisor" and what is "HS-mode"?
*   **Hypervisor:** Software that runs multiple "Guest" operating systems on one physical machine.
*   **HS-mode:** A special RISC-V privilege mode specifically for running a hypervisor, providing high-performance "two-stage" address translation.

### 92. What is "Trap" and what is "mcause"?
*   **Trap:** An event that makes the CPU jump to a handler.
*   **mcause:** A CSR that tells the software *why* the trap happened (e.g., "Timer Interrupt" or "Illegal Instruction").

### 93. What is "mcycle" and what is "time"?
*   **mcycle:** A counter of clock cycles.
*   **time:** A "wall-clock" timer (real-time) that counts seconds/milliseconds, often used for scheduled tasks.

### 94. What is "mstatus" and what is "mepc"?
*   **mstatus:** The main status register for Machine-mode (privilege, interrupts, etc.).
*   **mepc:** The "Machine Exception Program Counter." It saves the address of the instruction that was interrupted.

### 95. What is "mscratch" and what is "Context Switch"?
*   **mscratch:** A special Machine-mode register.
*   **Context Switch:** The process of the OS "swapping" the saved data of two different programs so they can share the same CPU.

### 96. What is "ASID" and what is "VMID"?
*   **ASID:** A "User ID" for memory translations to allow multiple apps to share the TLB.
*   **VMID:** A "Guest ID" for memory translations used by hypervisors to separate multiple virtual machines.

### 97. What is "PMP" and what is "PMA"?
*   **PMP:** Physical Memory Protection (hardware rules about who can read/write which physical address).
*   **PMA:** Physical Memory Attributes (rules about *how* to access memory, e.g., "Is it cacheable?").

### 98. What is "PMLEN" and what is "Pointer Masking"?
*   **PMLEN:** A number of bits at the top of a pointer to be "masked" (ignored).
*   **Pointer Masking:** A security feature that automatically masks these bits so that "tags" can be stored in them without affecting the actual address accessed.

### 99. What is "AMO" and what is "Swap"?
*   **AMO:** An "Atomic Memory Operation" (an indivisible read-modify-write).
