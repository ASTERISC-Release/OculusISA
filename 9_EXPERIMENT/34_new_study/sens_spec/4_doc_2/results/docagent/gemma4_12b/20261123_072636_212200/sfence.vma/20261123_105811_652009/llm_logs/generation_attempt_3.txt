### 1. What is the purpose of the `mcounteren` register?
The `mcounteren` register is a 32-bit register that **controls the availability of the hardware performance-monitoring counters to the next-lower privileged mode**. 
*   It determines whether the cycle (`cycle`), time (`time`), instruction retired (`instret`), or performance counter (`hpmcounter n`) registers can be accessed by a lower privilege mode (e.g., S-mode or U-mode). 
*   If a corresponding bit in `mcounteren` is clear, an attempt to read those counters from a lower privilege mode will cause an **illegal-instruction exception**.

### 2. What is the difference between `mcountinhibit` and `mcounteren`?
The two registers serve different purposes regarding the performance counters:
*   **`mcounteren` (Accessibility):** Controls **who** can see the counters. If a bit is clear, the lower privilege mode is blocked from accessing the counter.
*   **`mcountinhibit` (Functionality):** Controls **whether the counters increment**. If a bit is set, the corresponding counter (e.g., `mcycle`, `minstret`, or `mhpmcounter n`) does not increment, even though it remains accessible.

### 3. How does the `mideleg` register function?
The `medeleg` register is used for **Machine Trap Delegation**. 
*   By default, all traps (exceptions and interrupts) are handled in machine mode. 
*   By setting a bit in `medeleg`, a specific exception can be **delegated** to be handled directly by a lower privilege level (specifically S-mode). 
*   When an exception is delegated, the hardware handles the trap at the lower level; the `scause`, `sepc`, and `stval` registers are updated, and the `SIE` field of `mstatus` is cleared.
*   **Note:** Delegated interrupts result in the interrupt being masked at the delegator privilege level.

### 4. What is the `mcycle` register?
The `mcycle` CSR is a hardware performance-monitoring counter that **counts the number of clock cycles executed by the processor core** on which the hart is running.
*   It has 64-bit precision on all RV32 and RV64 harts.
*   It can be shared between harts on the same core.
*   It is a read-only shadow of the memory-mapped `mtime` register's cycle count (in some implementations) or a dedicated counter.

### 5. What is the `mcause` register?
The `mcause` register is an MXLEN-bit read-write register that is **written with a code indicating the event that caused the trap** when a trap is taken into machine mode.
*   It contains an **Interrupt bit** (set if the trap was caused by an interrupt).
*   It contains an **Exception Code** field (identifying the specific exception or interrupt).
*   It is used by software to determine the source of the trap and branch to the appropriate handler.

### 6. What is the `mtval` register?
The `mtval` (Machine Trap Value) register is used to **provide exception-specific information to assist software in handling the trap**. 
*   When a trap is taken, the hardware writes either zero or specific data (like a faulting virtual address) into this register.
*   It is used for various exceptions, such as page faults, access faults, or illegal instructions (where it may contain the actual faulting instruction bits).

### 7. What is the `mscratch` register?
The `mscratch` register is an MXLEN-bit read-write register **dedicated for use by machine mode**. 
*   It is typically used to hold a pointer to a machine-mode hart-local context space.
*   It is swapped with a user register upon entry to an M-mode trap handler to provide the handler with a "scratch" register that the user-mode software cannot interfere with.

### 8. What is the `mepc` register?
The `mepc` (Machine Exception Program Counter) is an MXLEN-bit read-write register that **holds the virtual address of the instruction that was interrupted or encountered the exception** when a trap is taken into M-mode.
*   It is used to return execution to the correct point after the trap handler completes.
*   On implementations supporting only IALIGN=32, the two low bits are always zero.

### 9. What is the `mip` register?
The `mip` (Machine Interrupt Pending) register is an MXLEN-bit read-write register that **contains information on pending interrupts**.
*   Each bit $i$ corresponds to an interrupt cause number.
*   If bit $i$ is set, it indicates that interrupt $i$ is pending.
*   It is used by the hardware to determine which interrupt to take next.

### 10. What is the `mie` register?
The `mie` (Machine Interrupt Enable) register is an MXLEN-bit read-write register containing **interrupt enable bits**.
*   Bit $i$ corresponds to the same interrupt cause as in the `mip` register.
*   An interrupt $i$ will only trap to M-mode if bit $i$ is set in both `mip` and `mie` (and is not delegated).

### 11. What is the `mstatus` register?
The `mstatus` register is a central CSR that **keeps track of the processor's current operating state**. Key fields include:
*   **MIE / SIE:** Global interrupt enable bits for M-mode and S-mode.
*   **MPP:** Indicates the privilege mode the hart was in before a trap.
*   **MPIE:** Indicates the interrupt enable state before a trap.
*   **MPRV:** Modifies the privilege with which loads access virtual memory.
*   **MXR:** Modifies the privilege with which loads access virtual memory (specifically making execute-only pages readable).

### 12. What is the `misa` register?
The `misa` (Machine ISA) register is a CSR that **indicates the maximal set of supported extensions** for the hart. 
*   It is set to enable specific extensions (like the "A" extension for atomics or the "H" extension for hypervisor support).
*   It is reset to enable the maximal set of supported extensions.

### 13. What is the `mconfigptr` register?
The `mconfigptr` register is an MXLEN-bit read-only CSR that **holds the physical address of a configuration data structure**. 
*   Software can traverse this structure to discover information about the harts, the platform, and their configuration.

### 14. What is the `menvcfg` register?
The `menvcfg` (Machine Environment Configuration) register is a 64-bit read-write register that **controls certain characteristics of the execution environment for modes less privileged than M**. 
*   It includes bits for pointer masking (PMM), hardware updating of A/D bits (ADUE), and various extension-specific enables (like `FIOM` for Fence of I/O implies Memory).

### 15. What is the `mseccfg` register?
The `mseccfg` (Machine Security Configuration) register is a 64-bit read-write register that **controls security features**. 
*   It includes bits like `USEED` and `SSEED` to control access to the seed CSR.
*   It also contains fields for PMP enhancements like `RLB` (Rule Locking Bypass), `MMWP` (Machine-Mode Allowlist Policy), and `MML` (Machine Mode Lockdown).

### 16. What is the `mtime` register?
The `mtime` register is a **memory-mapped machine-mode read-write register** that provides a real-time counter.
*   It must increment at a constant frequency.
*   It is used to provide wall-clock time, supporting processors with variable clock frequencies.

### 17. What is the `mtimecmp` register?
The `mtimecmp` register is a **memory-mapped machine-mode timer compare register**.
*   A machine timer interrupt becomes pending whenever `mtime` contains a value greater than or equal to `mtimecmp`.
*   The interrupt is cleared when `mtimecmp` is updated to a value greater than `mtime`.

### 18. What is the `sstatus` register?
The `sstatus` register is an SXLEN-bit read/write register that **keeps track of the processor's operating state for Supervisor mode**.
*   It contains fields like `SPP` (Previous Privilege), `SIE` (Interrupt Enable), `SPIE` (Previous Interrupt Enable), `SUM` (Supervisor User Memory access), and `MXR`.

### 19. What is the `stvec` register?
The `stvec` register is an SXLEN-bit read/write register that **holds the trap vector configuration for Supervisor mode**.
*   It consists of a **BASE** field (the address) and a **MODE** field (Direct or Vectored).
*   In Vectored mode, asynchronous interrupts set the PC to `BASE + 4 × cause`.

### 20. What is the `scause` register?
The `scause` register is an SXLEN-bit read-write register that is **written with a code indicating the event that caused a trap into Supervisor mode**.
*   Similar to `mcause`, it contains an Interrupt bit and an Exception Code.

### 21. What is the `sepc` register?
The `sepc` register is an SXLEN-bit read/write register that **holds the virtual address of the instruction that was interrupted or encountered the exception** when a trap is taken into Supervisor mode.

### 22. What is the `stval` register?
The `stval` register is an SXLEN-bit read-write register that **provides exception-specific information to assist software in handling a trap into Supervisor mode**.
*   It provides data for faults, such as the faulting virtual address.

### 23. What is the `senvcfg` register?
The `senvcfg` register is an SXLEN-bit read/write register that **controls certain characteristics of the execution environment for User mode**.
*   It includes bits for pointer masking (`PMM`), hardware updating of A/D bits (`ADUE`), and other extension-specific controls like `CBZE` and `CBCFE`.

### 24. What is the `satp` register?
The `satp` register is an SXLEN-bit read/write register that **controls Supervisor-mode address translation and protection**.
*   It holds the physical page number (**PPN**) of the root page table, an address space identifier (**ASID**), and a **MODE** field that selects the translation scheme (e.g., Sv32, Sv39, Sv48, Sv57, or Bare).

### 25. What is the `stimecmp` register?
The `stimecmp` register is a 64-bit register used to **schedule timer interrupts for Supervisor mode**.
*   A supervisor timer interrupt becomes pending whenever `time` is $\ge$ `stimecmp`.

### 26. What is the `sscratch` register?
The `sscratch` register is an SXLEN-bit read/write register **dedicated for use by the supervisor**.
*   It is typically used to hold a pointer to the hart-local supervisor context while executing user code.

### 27. What is the `sip` register?
The `sip` register is an SXLEN-bit read-write register that **contains information on pending interrupts for Supervisor mode**.

### 28. What is the `sie` register?
The `sie` register is an SXLEN-bit read-write register containing **interrupt enable bits for Supervisor mode**.

### 29. What is the `mstatus.MPRV` bit?
The `MPRV` (Modify Privilege) bit **modifies the privilege with which loads access virtual memory**.
*   When `MPRV=0`, translation and protection behave normally.
*   When `MPRV=1`, explicit memory accesses are translated and protected as though the current virtualization mode were set to `MPV` and the current nominal privilege mode were set to `MPP`.

### 30. What is the `mstatus.MXR` bit?
The `MXR` (Make eXecutable Readable) bit **modifies the privilege with which loads access virtual memory**.
*   When `MXR=0`, only loads from pages marked readable (`R=1`) succeed.
*   When `MXR=1`, loads from pages marked either readable or executable (`R=1` or `X=1`) succeed.

### 31. What is the `mstatus.SUM` bit?
The `SUM` (permit Supervisor User Memory access) bit **modifies the privilege with which S-mode loads and stores access virtual memory**.
*   When `SUM=0`, S-mode memory accesses to pages marked for user mode (`U=1`) will fault.
*   When `SUM=1`, these accesses are permitted.

### 32. What is the `mstatus.MPV` bit?
The `MPV` (Machine Previous Virtualization) bit is **written by the implementation whenever a trap is taken into M-mode**.
*   It sets the value of the virtualization mode `V` at the time of the trap (e.g., 1 if in VS-mode, 0 otherwise).

### 33. What is the `mstatus.MPP` bit?
The `MPP` (Machine Previous Privilege) bit is **written by the implementation whenever a trap is taken into M-mode**.
*   It indicates the privilege level at which the hart was executing before entering machine mode (e.g., 0 for U-mode, 1 for S-mode, 3 for M-mode).

### 34. What is the `mstatus.MIE` bit?
The `MIE` bit is the **global interrupt enable bit for machine mode**.
*   When set, interrupts are enabled in M-mode.
*   When clear, interrupts are not taken while in M-mode.

### 35. What is the `mstatus.MPIE` bit?
The `MPIE` bit **indicates whether supervisor interrupts were enabled prior to trapping into machine mode**.
*   When a trap is taken into M-mode, `MPIE` is set to the value of `MIE`.
*   When `MRET` is executed, `MIE` is set to `MPIE`, and `MPIE` is then set to 1.

### 36. What is the `mstatus.SIE` bit?
The `SIE` bit is the **global interrupt enable bit for supervisor mode**.
*   When set, interrupts are enabled in S-mode.
*   When clear, interrupts are not taken while in S-mode.

### 37. What is the `mstatus.SPIE` bit?
The `SPIE` bit **indicates whether supervisor interrupts were enabled prior to trapping into supervisor mode**.
*   When a trap is taken into S-mode, `SPIE` is set to `SIE`, and `SIE` is then set to 0.

### 38. What is the `mstatus.TVM` bit?
The `TVM` (Trap Virtual Memory) bit **prevents HS-mode from accessing `hgatp` or executing `HFENCE.GVMA`**.
*   It is intended to allow machine-level software to modify address translations managed by a supervisor-level OS without being detected by the OS.

### 39. What is the `mstatus.TW` bit?
The `TW` (Trap Wait) bit **affects execution in all modes except M-mode**.
*   When `TW=1`, an attempt in VS-mode to execute `WFI` raises a virtual-instruction exception if the instruction does not complete within a bounded time limit.

### 40. What is the `mstatus.TSR` bit?

### 41. What is the `mstatus.UBE` bit?
The `UBE` (User Big Endian) bit **controls the endianness of explicit memory accesses made from U-mode**.
*   When `UBE=0`, accesses are little-endian; when `UBE=1`, they are big-endian.

### 42. What is the `mstatus.UXL` bit?

The `SDT` bit is used to **address double traps at privilege modes lower than M**.
*   When set, the `SIE` bit is cleared to 0.

### 928. What is the `mstatus.SPELP` bit?
The `SPELP` bit **holds the previous ELP state** (Landing Pad Expected) for the Zicfilp extension.

### 929. What is the `mstatus.MPRV` bit?
