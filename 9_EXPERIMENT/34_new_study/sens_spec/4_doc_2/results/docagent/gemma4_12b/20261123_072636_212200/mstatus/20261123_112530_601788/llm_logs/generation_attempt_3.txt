Based on the provided text, here are the answers to your questions:

### 1. What is the difference between `mepc` and `mtval`?
*   **`mepc` (Machine Exception Program Counter):** This register is written with the **virtual address** of the instruction that was interrupted or that encountered the exception. It essentially points to the "return address" for the instruction.
*   **`mtval` (Machine Trap Value):** This register is written with **exception-specific information** to assist software in handling the trap. For example, it can contain the faulting virtual address (for memory access faults) or specific metadata for software-check exceptions.

### 2. What is the difference between a "virtual instruction" and an "illegal instruction"?
While the text doesn't provide a single-sentence definition, it describes the distinction through the behavior of the Hypervisor extension:
*   **Illegal Instruction:** Generally occurs when an instruction is not valid in the current mode or violates architecture rules (e.g., accessing a CSR it doesn't have permission for).
*   **Virtual Instruction:** This is a specific trap (Cause Code 22) triggered when a hart is in **virtualization mode (V=1)** and attempts to execute a hypervisor instruction (like `HLV` or `HFENCE`) that is **HS-qualified** but prevented from executing because of the virtualization state (e.g., insufficient privilege or a disabled CSR bit). Essentially, it is a "trap" that the hypervisor can intercept to emulate the instruction for the guest.

### 3. What is the difference between `mstatus` and `hstatus`?
*   **`mstatus`:** The standard machine-mode status register that tracks the processor's current operating state (privilege mode, interrupt enables, etc.) for the entire hart.
*   **`hstatus`:** A register specific to the **Hypervisor extension**. It provides facilities analogous to `mstatus` but specifically for tracking and controlling the exception behavior of a **VS-mode guest** (Virtual Supervisor mode). It includes extra fields like `SPV` (Supervisor Previous Virtualization mode) and `GVA` (Guest Virtual Address) to manage the state of the virtual machine.

### 4. What is the purpose of the `hgatp` register?
The `hgatp` register is used for **G-stage (Guest-stage) address translation**. It holds the physical page number (PPN) of the **guest-physical root page table**. It allows the hypervisor to map guest physical addresses (GPAs) to supervisor physical addresses (SPAs) as part of two-stage address translation.

### 5. What is the difference between `satp` and `hgatp`?
*   **`satp`:** Controls **first-stage (VS-stage)** address translation. It translates a **virtual address** (from the guest OS) into a **guest physical address**.
*   **`hgatp`:** Controls **second-stage (G-stage)** address translation. It translates a **guest physical address** into a **supervisor physical address**.
*   In short: `satp` handles the guest's own memory management, while `hgatp` handles the hypervisor's isolation of that guest's memory.

### 6. What is the difference between `mstatus` and `sstatus`?
*   **`mstatus`:** The status register for **Machine mode**. It is the "highest" level of privilege and controls the overall state of the hart.
*   **`sstatus`:** The status register for **Supervisor mode**. It is a **subset** of `mstatus`. It tracks the processor's state specifically for supervisor-level software (like an OS kernel), including fields like `SUM` (permit Supervisor User Memory access) and `MXR` (Make eXecutable Readable).

### 7. What is the difference between `mideleg` and `hideleg`?
*   **`mideleg` (Machine Interrupt Delegation):** Used to delegate interrupts from **Machine mode** down to the **Hypervisor mode (HS-mode)**.
*   **`hideleg` (Hypervisor Interrupt Delegation):** Used to delegate interrupts from **Hypervisor mode** down to the **Virtual Supervisor mode (VS-mode)**.
*   Both registers allow lower privilege modes to handle specific interrupts directly without trapping back up to a higher mode.

### 8. What is the difference between `mstatus` and `vsstatus`?
*   **`mstatus`:** The standard machine-mode status register.
*   **`vsstatus`:** A register for **Virtual Supervisor mode**. When virtualization is active (V=1), `vsstatus` is the VS-mode version of `sstatus`. It tracks the state of the guest operating system's supervisor mode.

### 9. What is the difference between `mstatus` and `mstatush`?
*   **`mstatus`:** The primary machine status register.
*   **`mstatush`:** A **high-half** (or extra) register used only when the **Hypervisor extension** is implemented and the hart is in a 32-bit mode (RV32). It holds extra bits (like `MPV` and `GVA`) that wouldn't fit in the standard 32-bit `mstatus` register, ensuring that the hypervisor has enough state bits to manage the guest.

### 10. What is the difference between `mstatus` and `hstatus`? (Note: You asked this twice, but I will highlight the specific "Hypervisor" distinction again).
*   **`mstatus`:** Tracks the state of the **Machine mode** (the highest privilege).
*   **`hstatus`:** Tracks the state of the **Hypervisor-extended Supervisor mode (HS-mode)**. It specifically contains fields to manage the virtualization mode of the guest, such as `SPV` and `GVA`.
