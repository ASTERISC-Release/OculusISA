### 1. What are the different modes for the `stvec` register?
According to Table 36 and the description in section 12.1.2, there are two modes:
*   **Direct**: All traps into supervisor mode cause the PC to be set to the address in the `BASE` field.
*   **Vectored**: All synchronous exceptions into supervisor mode cause the PC to be set to the address in the `BASE` field, whereas interrupts cause the PC to be set to the address in the `BASE` field plus four times the interrupt cause number.

### 2. What does the `mcycle` CSR count?
The `mcycle` CSR counts the **number of clock cycles executed by the processor core** on which the hart is running.

### 3. What is the `mscratch` register used for?
The `mscratch` register is a hart-local register dedicated for use by machine mode. It is typically used to **hold a pointer to a machine-mode hart-local context space** and is swapped with a user register upon entry to an M-mode trap handler.

### 4. What are the fields in the `mstatus` register?
While the text does not provide a single table for all fields, it describes several specific fields including:
*   **MIE**: Machine-level interrupt enable.
*   **MPRV**: Modify Privilege (determines if translation/protection behaves as if the current privatization mode were set to the value in MPP).
*   **MPP**: Machine Previous Privilege (holds the privilege mode at the time of a trap).
*   **MPIE**: Machine Previous Interrupt Enable.
*   **UXL**: Controls the value of XLEN for U-mode.
*   **MXR**: Make eXecutable Readable (modifies privilege with which loads access virtual memory).
*   **SUM**: Permit Supervisor User Memory access (modifies privilege with which S-mode loads and stores access virtual memory).
*   **UBE**: User Byte Enable (controls endianness of explicit memory accesses in U-mode).
*   **SPP**: Supervisor Previous Privilege.
*   **SPIE**: Supervisor Previous Interrupt Enable.
*   **SIE**: Supervisor Interrupt Enable.
*   **SDT**: Supervisor-mode-disable-trap (used for double trap handling).
*   **TSR**: Trap Stack Replacement (affects execution in HS-mode).
*   **TW**: Trap Word (affects execution in all modes except M-mode).
*   **TVM**: Trap Virtual Memory (prevents HS-mode from accessing `hgatp` or executing `HFENCE.GVMA`).
*   **FS**: Floating-point status.
*   **VS**: Vector status.

### 5. What is the `mcause` register?
The `mcause` register is an MXLEN-bit read-write register that is written with a code indicating the **event that caused the trap** (either an interrupt or an exception) when a trap is taken into M-mode.

### 6. What are the different types of memory access permissions in the PMP configuration register?
As shown in Figure 34 and the surrounding text, the permissions are:
*   **R**: Read permission.
*   **W**: Write permission.
*   **X**: Execute permission.
*   The combination of these bits determines whether an access type (read, write, or execute) is allowed for a specific physical memory region.

### 7. How is the `mepc` register used?
When a trap is taken into M-mode, `mepc` is written with the **virtual address of the instruction that was interrupted or that encountered the exception**. It is used to return to the correct execution point after the trap handler completes.

### 8. What does the `mtval` register hold?
The `mtval` register is written with **exception-specific information** to assist software in handling the trap. For example:
*   For **breakpoint, address-misaligned, access-fault, page-fault, or hardware-error** exceptions on an instruction fetch, load, or store, it contains the **faulting virtual address**.
*   For **software-check** exceptions, it holds the **cause for the exception** (e.g., Landing Pad Fault or Shadow Stack Fault).
*   For **illegal-instruction** exceptions, it can optionally hold the **faulting instruction bits**.

### 9. What is the `mconfigptr` register?
The `mconfigptr` register is a read-only CSR that holds the **physical address of a configuration data structure**. Software can traverse this structure to discover information about the harts, the platform, and their configuration.

### 10. What is the `menvcfg` register?
The `menvcfg` register is a 64-bit read-write register that **controls certain characteristics of the execution environment** for modes less privileged than M. It includes bits to control features like Fence of I/O implies Memory (FIOM), pointer masking (PMM), hardware updating of A/D bits (ADUE), and various extension-specific enables (e.g., for cache block zero/clean/invalidate).

### 11. What is the `mseccfg` register?
The `mseccfg` register is a 64-bit read-write register that **controls security features**. It includes fields like:
*   **SEED/USEED**: Access control to the seed CSR.
*   **RLB**: Rule Locking Bypass.
*   **MMWP**: Machine-Mode Allowlist Policy (sticky bit changing default PMP policy for M-mode).
*   **MML**: Machine Mode Lockdown (changes the interpretation of the PMP lock bit).
*   **MLPE**: Machine-level Landing Pad Enable.

### 12. What is the `mcountinhibit` register?
The `mcountinhibit` register is a 32-bit WARL register that **controls which of the hardware performance-monitoring counters increment**. Setting a bit (CY, IR, HPMn) prevents the corresponding counter from incrementing while the hart is running.

### 13. What is the `mip` register?
The `mip` register is an MXLEN-bit read-write register containing **information on pending interrupts**. Each bit $i$ corresponds to an interrupt cause number $i$.

### 14. What is the `mie` register?
The `mie` register is an MXLEN-bit read-write register containing **interrupt enable bits**. An interrupt $i$ will trap to M-mode if bit $i$ is set in both `mip` and `mie` (and is not delegated).

### 15. What is the `medeleg` register?
