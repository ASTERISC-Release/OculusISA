INSTRUCTION: CSRRWI
FORMAT: csrrwi rd, csr, zimm5
RULE 1: The CSRRWI instruction updates the CSR using an XLEN-bit value obtained by zero-extending a 5-bit unsigned immediate (uimm[4:0]) field encoded in the rs1 field of the instruction.
RULE 2: If the destination register rd of the CSRRWI instruction is x0, the CSRRWI instruction does not read the CSR.
RULE 3: If the destination register rd of the CSRRWI instruction is x0, the CSRRWI instruction shall not cause any of the side effects that might occur on a CSR read.
RULE 4: If the destination register rd of the CSRRWI instruction is x0, the CSRRWI instruction writes the CSR.
RULE 5: If the destination register rd of the CSRRWI instruction is not x0, the CSRRWI instruction reads the CSR.
RULE 6: If the destination register rd of the CSRRWI instruction is not x0, the CSRRWI instruction writes the CSR.
RULE 7: If a CSRRWI instruction is executed and the architectural state does not reflect the expected action side effects of the written CSR fields, then the behavior is incorrect.

INSTRUCTION: FCVT.W.D
FORMAT: fcvt.w.d rd, fs1, rm
RULE 1: FCVT.W.D converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 2: FCVT.W.D rounds the result according to the rm field.

INSTRUCTION: SFENCE.VMA
FORMAT: sfence.vma rs1, rs2
RULE 1: Executing an SFENCE.VMA instruction while in S-mode is permitted when TVM=0.
RULE 2: If the value held in rs1 for the SFENCE.VMA instruction is not a valid virtual address, no exception is raised.
RULE 3: If an implicit access generated by a speculative execution of the SFENCE.VMA instruction occurs, then no exception is raised.
RULE 4: An attempt to execute the SFENCE.VMA instruction in U-mode must raise an illegal-instruction exception.
RULE 5: When the VTVM bit is 1, an attempt to execute the SFENCE.VMA instruction in VS-mode raises a virtual-instruction exception.
RULE 6: Executing an SFENCE.VMA instruction in VS-mode when hstatus.VTVM=1 raises a virtual-instruction exception.

INSTRUCTION: VLE32FF.V
FORMAT: vle32ff.v vd, (rs1), vm
RULE 1: If VLE32FF.V causes a synchronous exception on element 0, the vector length vl is not modified and the trap is taken.
RULE 2: If VLE32FF.V causes a synchronous exception on an element with an index greater than 0, the trap is not taken and the vector length vl is reduced to the index of the element that would have raised the exception.
RULE 3: If a VLE32FF.V instruction triggers a trap at element index $i$, the destination vector register elements at indices greater than $i$ may be overwritten by the load operation.
RULE 4: If a VLE32FF.V instruction causes a fault, any destination element index greater than the original vector length must not be updated in the destination register.
RULE 5: If a VLE32FF.V instruction reports a trap or trimming at index $i$, then the values in the destination register elements at indices $j > i$ are not required to correspond to the values in the addressed memory locations.
RULE 6: If a VLE32FF.V instruction is restarted due to a trap or vector-length trimming and a non-idempotent memory location in its access path was accessed, then the value of that memory location will differ from its state prior to the instruction's execution.
RULE 7: If vstart is 0 and vl is greater than 0, and the instruction completes without an exception and the destination register remains unchanged, then the rule is violated.
RULE 8: When VLE32FF.V takes a trap due to an interrupt, the vector length vl should not be reduced and a vstart value should be set.
RULE 9: When VLE32FF.V would trigger a debug data-watchpoint trap on an element with an index greater than 0, the vector length vl should not be reduced and the debug trap should be triggered.
