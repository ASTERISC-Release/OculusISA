REGISTER: mseccfg
SUMMARY: The mseccfg CSR (address 0x747) is a machine‑mode read‑write register that configures machine security features such as seed‑CSR accessibility, pointer masking, PMP policy, and extension enablement. The USEED and SSEED bits control read‑write access to the seed CSR in U‑ and S/HS‑mode respectively, raising an illegal‑instruction exception when cleared, while M‑mode always has unrestricted access. The sticky WARL fields MMWP and MML, once set, cannot be cleared without a PMP reset; MMWP changes the default PMP policy for unfound accesses from ignored to denied, and MML reinterprets PMP rule L/R/W/X bits to provide M‑mode‑only, S/U‑mode‑only, and locked/shared region semantics, with the RLB lock bit further freezing PMP rule changes until reset. Pointer masking is selected by the PMM field (off, 7‑bit, or 16‑bit mask on RV64) and the MLPE bit enables the Zicfilp extension in M‑mode, and any disallowed seed accesses or PMP‑rule violations generate illegal‑instruction or access‑exception faults as specified by these configuration bits.

REGISTER: mstatus
SUMMARY: mstatus is the central machine‑mode CSR that records the current execution environment, including global interrupt enables, saved interrupt‑enable copies, the current and previous privilege modes, and virtualization state.  Its main field groups are: MIE/SIE and MPIE/SPIE for interrupt control, MPP/SPP for privilege tracking, MPRV, MXR, SUM, TVM, TW and TSR for memory‑access and privilege‑modification checks, MBE/SBE/UBE for endianness control, FS/VS/XS for extension‑state tracking (with the read‑only SD bit summarising any dirty state), and the virtualization bits V, MPV and GVA.  Access rules dictate that MPRV makes data accesses be checked as if executed in the privilege indicated by MPP; TVM blocks satp and SFENCE.VMA in S‑mode; TSR makes SRET illegal when set; TW makes WFI illegal when set; MXR and SUM modify load/store permission checks; and any execution or CSR access of vector, floating‑point, or other extension state when the corresponding VS, FS or XS field is Off causes an illegal‑instruction exception.  Additionally, clearing MPV makes all cache‑block management instructions illegal, and the SD bit automatically reflects any dirty FS, VS or XS state, while attempts to use disabled extensions or violate the above controls raise illegal‑instruction exceptions.

REGISTER: satp
SUMMARY: The satp CSR configures supervisor address translation by holding a MODE field that selects the translation scheme (e.g., Bare, Sv39, Sv48, Sv57, Sv64), an ASID that tags address spaces, and a PPN that points to the root page table, while optional PBMTE and ADUE bits are read‑only zero when the corresponding extensions are not implemented. It is readable and writable in S‑mode (SRW), but when the TVM bit is set any S‑mode read, write, or execution of SFENCE.VMA/SINVAL.VMA raises an illegal‑instruction exception; in M‑mode satp is inactive, reads return zero and writes have no effect. Changes to MODE (including switching to or from Bare) and to ASID take effect immediately, whereas SFENCE.VMA must be used to synchronize other translation structures, and writes with unsupported MODE values are ignored. Implicit reads of satp must match explicit CSR reads, otherwise a state‑mismatch is observed, and attempts to use forced‑Bare implementations (read‑only zero MODE) cause SFENCE.VMA to fault.

REGISTER: scounteren
SUMMARY: The scounteren CSR resides at supervisor privilege level and grants supervisor‑mode read/write control over the visibility of the cycle, time, instruction‑retired, and programmable hardware performance counters to lower‑privilege software. Each of its bits, when set, permits access to the corresponding counter; if a bit is cleared or hard‑wired zero, a U‑mode read of that counter raises an illegal‑instruction exception. U‑mode may read a counter only when the same bit is set in both scounteren and the machine‑level mcounteren register, and the writability of scounteren bits is unaffected by mcounteren settings. Accesses to scounteren itself are always allowed in supervisor mode and, when the V bit in mstatus is 1, also complete without exception.
