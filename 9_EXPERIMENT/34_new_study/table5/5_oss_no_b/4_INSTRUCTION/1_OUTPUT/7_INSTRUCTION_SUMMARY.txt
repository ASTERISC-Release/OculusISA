INSTRUCTION: CSRRWI
SUMMARY: CSRRWI atomically writes a CSR with the zero‑extended value of the 5‑bit immediate and always performs the write. If rd ≠ x0 the instruction reads the CSR, places the previous value into rd, and treats the CSR as a source register, causing any read‑side effects; if rd = x0 no CSR read occurs and no read‑side effects are generated. The operation follows the usual CSR access checks, so writing a read‑only CSR raises an illegal‑instruction exception.

INSTRUCTION: FCVT.W.D
SUMMARY: FCVT.W.D converts the double‑precision floating‑point value in FP source register rs1 to a signed 32‑bit integer and writes the result to integer destination register rd. On RV64 implementations the 32‑bit result is sign‑extended to XLEN bits before being stored. The conversion uses the rounding mode encoded in the instruction's rm field, and any floating‑point exception flags required by the conversion semantics are raised. Execution follows the standard privilege and access rules for floating‑point instructions.

INSTRUCTION: SFENCE.VMA
SUMMARY: SFENCE.VMA uses rs1 to supply a virtual address (or zero for a global flush) and rs2 to supply an address‑space identifier, with any bits above the ASID width masked off; the instruction has no destination register. It is a supervisor‑level instruction, so it executes without exception only in S‑mode (or HS‑mode) when mstatus.TVM = 0, otherwise an illegal‑instruction trap is taken, and it is illegal in U‑mode. In virtualized modes (VS‑mode or VU‑mode) the instruction always causes a virtual‑instruction exception, regardless of the hstatus.VTVM setting. When a virtual‑instruction exception is taken, mtval or stval is written with the same value that would be written for an illegal‑instruction trap.

INSTRUCTION: VLE32FF.V
SUMMARY: VLE32FF.V reads 32‑bit elements from memory at addresses rs1 + 4 × i and writes each loaded element into the corresponding element of the destination vector register group vd, updating only those elements whose mask bit (vm) is true. A synchronous exception on element 0 causes a taken trap and leaves the architectural vector‑length register vl unchanged, whereas faults on later elements do not take a trap; instead the hardware trims vl to the index of the first failing element (interrupts and debug watchpoints on later elements leave vl unchanged and set vstart to the following element). Writes may occur to any active destination elements up to the original vl at instruction entry but must never exceed that original bound. The instruction respects the current vstart and processes at least one element when vstart = 0 and the initial vl > 0.
