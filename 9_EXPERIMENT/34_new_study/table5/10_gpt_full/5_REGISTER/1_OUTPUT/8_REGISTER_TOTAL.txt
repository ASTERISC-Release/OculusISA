REGISTER: mseccfg
NUMBER: 0x747
MODE: M-mode
WIDTH: 64
FIELDS: 33..32=PMM, 10..10=MLPE, 9..9=SSEED, 8..8=USEED, 2..2=RLB, 1..1=MMWP, 0..0=MML
EXTENSIONS: Smepmp, Smmpm, Zicfilp, Zkr
RULE 1: Software may discover whether access to the seed CSR can be enabled in U and S modes by writing 1 to the mseccfg [s,u]seed fields and reading back the result.
RULE 2: If an instruction reads or writes mseccfg below M-mode, it raises an illegal-instruction exception; in M-mode, reads and writes are permitted and readback follows mseccfg’s defined field semantics.
RULE 3: A write to mseccfg updates its writable fields, and a subsequent read returns the updated values subject to each field’s architectural write constraints.
RULE 4: If any implemented extension adds a field to mseccfg, then an M-mode read of mseccfg returns its CSR value rather than raising an illegal-instruction exception for an unimplemented CSR.
RULE 5: When mseccfg.USEED is 0, any access to the seed CSR from U-mode raises an illegal-instruction exception.
RULE 6: When mseccfg.USEED is 1, read-write access to the seed CSR from U-mode is allowed.
RULE 7: When mseccfg.USEED is 1, an access to the seed CSR from U-mode other than a read-write access raises an illegal-instruction exception.
RULE 8: When mseccfg.SSEED is 0, any access to the seed CSR from S-mode or HS-mode raises an illegal-instruction exception.
RULE 9: When mseccfg.SSEED is 1, read-write access to the seed CSR from S-mode or HS-mode is allowed.
RULE 10: When mseccfg.SSEED is 1, an access to the seed CSR from S-mode or HS-mode other than a read-write access raises an illegal-instruction exception.
RULE 11: Regardless of mseccfg.SSEED and mseccfg.USEED, the seed CSR is always available in M-mode through a CSR read-write instruction.
RULE 12: When mseccfg.RLB is 1, locked PMP rules may be removed, modified, or edited.
RULE 13: When mseccfg.RLB is 0 and pmpcfg.L is 1 in any PMP rule or entry, including a disabled entry, mseccfg.RLB remains 0 until a PMP reset.
RULE 14: When mseccfg.RLB is 0 and pmpcfg.L is 1 in any PMP rule or entry, including a disabled entry, further modifications to mseccfg.RLB are ignored until a PMP reset.
RULE 15: mseccfg.MMWP is a sticky bit that cannot be unset after being set until a PMP reset.
RULE 16: When mseccfg.MMWP is set, the default PMP policy for M-mode access to a memory region without a matching PMP rule is denied instead of ignored.
RULE 17: mseccfg.MML is a sticky bit that cannot be unset after being set until a PMP reset.
RULE 18: When mseccfg.MML is set, a set pmpcfg.L bit marks a PMP rule as M-mode-only instead of marking it as locked and enforced in all modes.
RULE 19: When mseccfg.MML is set, an unset pmpcfg.L bit marks a PMP rule as S/U-mode-only.
RULE 20: If mseccfg.MML=1 and a PMP entry has pmpcfg.R=0 and pmpcfg.W=1, accesses matching that entry use Shared-Region semantics; the RW=01 encoding is not treated as reserved.
RULE 21: If mseccfg.MML=1 and a matching PMP entry has L=R=W=X=1, loads, stores, and instruction fetches are allowed or fault according to Shared-Region permissions, not ordinary locked RWX permissions.
RULE 22: If mseccfg.MML=1 and an M-mode instruction fetch, load, or store violates an applicable M-mode-only PMP rule, the access raises the corresponding instruction, load, or store access-fault exception.
RULE 23: When mseccfg.MML is set, an M-mode-only PMP rule denies access from S-mode and U-mode.
RULE 24: When mseccfg.MML is set, an M-mode-only PMP rule remains locked so that modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.
RULE 25: If mseccfg.MML=1 and an S-mode or U-mode instruction fetch, load, or store violates an applicable S/U-mode-only PMP rule, the access raises the corresponding instruction, load, or store access-fault exception.
RULE 26: When mseccfg.MML is set, an S/U-mode-only PMP rule denies access from M-mode.
RULE 27: If mseccfg.MML=1 and an access from any privilege mode, including M-mode, violates a Shared-Region PMP rule, the access raises the corresponding instruction, load, or store/AMO access-fault exception.
RULE 28: When mseccfg.MML is set, a Shared-Region PMP rule encoded with pmpcfg.RW=01 and an unset pmpcfg.L bit is not executable.
RULE 29: When mseccfg.MML is set, M-mode has read/write access to a Shared-Region PMP rule encoded with pmpcfg.RW=01 and an unset pmpcfg.L bit.
RULE 30: When mseccfg.MML is set, S-mode and U-mode have read access to a Shared-Region PMP rule encoded with pmpcfg.RW=01, an unset pmpcfg.L bit, and an unset pmpcfg.X bit.
RULE 31: When mseccfg.MML is set, S-mode and U-mode have read/write access to a Shared-Region PMP rule encoded with pmpcfg.RW=01, an unset pmpcfg.L bit, and a set pmpcfg.X bit.
RULE 32: When mseccfg.MML is set, a Shared-Region PMP rule encoded with pmpcfg.RW=01 and a set pmpcfg.L bit is not writable.
RULE 33: When mseccfg.MML is set, M-mode, S-mode, and U-mode have execute access to a Shared-Region PMP rule encoded with pmpcfg.RW=01 and a set pmpcfg.L bit.
RULE 34: When mseccfg.MML is set, M-mode also has read access to a Shared-Region PMP rule encoded with pmpcfg.RW=01 and set pmpcfg.L and pmpcfg.X bits.
RULE 35: When mseccfg.MML is set, a Shared-Region PMP rule encoded with pmpcfg.RW=01 and a set pmpcfg.L bit remains locked so that modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.
RULE 36: When mseccfg.MML is set, M-mode, S-mode, and U-mode have only read-only access to a Shared-Region PMP rule encoded with pmpcfg.LRWX=1111.
RULE 37: When mseccfg.MML is set, a Shared-Region PMP rule encoded with pmpcfg.LRWX=1111 remains locked so that modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.
RULE 38: When mseccfg.MML is set, adding an executable M-mode-only PMP rule or an executable locked Shared-Region PMP rule is not possible unless mseccfg.RLB is set.
RULE 39: When mseccfg.MML is set and mseccfg.RLB is not set, a pmpcfg write that attempts to add an executable M-mode-only PMP rule or an executable locked Shared-Region PMP rule is ignored and leaves pmpcfg unchanged.
RULE 40: If mseccfg.MML=1 and mseccfg.RLB=0, an attempt to add an executable M-mode-only PMP rule or an executable locked Shared-Region PMP rule does not install that rule, as observed in PMP CSR readback; setting RLB=1 temporarily allows the same otherwise-valid rule to be installed.
RULE 41: When mseccfg.MML is set, executing code with M-mode privileges is possible only from a memory region with a matching M-mode-only PMP rule or a matching locked Shared-Region PMP rule with executable privileges.
RULE 42: When mseccfg.MML is set, executing code with M-mode privileges from a memory region without a matching PMP rule is denied.
RULE 43: When mseccfg.MML is set, executing code with M-mode privileges from a memory region with a matching S/U-mode-only PMP rule is denied.
RULE 44: If the Smmpm extension is not implemented, mseccfg.PMM is read-only zero.
RULE 45: The mseccfg.PMM value 10 enables pointer masking with PMLEN equal to XLEN - 57, which is 7 on RV64.
RULE 46: If mseccfg.PMM is set to 11, pointer masking uses PMLEN = XLEN − 48; on RV64, bits 63:48 of each affected pointer are ignored when forming the address.
RULE 47: If mseccfg.MLPE is 1 and M-mode execution violates a Zicfilp landing-pad requirement, a software-check exception is raised.
RULE 48: If mseccfg.MLPE is 0, an indirect control transfer executed in M-mode does not raise a software-check exception solely because its target lacks a valid Zicfilp landing pad.
RULE 49: If mseccfg.MLPE is 0, then executing any instruction in M-mode leaves the ELP state unchanged at NO_LP_EXPECTED.
RULE 50: When mseccfg.MLPE is 0, the LPAD instruction operates as a no-op in M-mode.
RULE 51: When XLEN=64, mseccfgh does not exist as an alias of mseccfg.
RULE 52: Upon reset, if the Zicfilp extension is implemented, the mseccfg.MLPE field is reset to 0.
RULE 53: When mseccfg.MML is set to 1 and pmpcfg.L, pmpcfg.R, pmpcfg.W, and pmpcfg.X are all 0, the region is inaccessible in M-mode and the M-mode result is an access exception.
RULE 54: When mseccfg.MML is set to 1 and pmpcfg.L, pmpcfg.R, pmpcfg.W, and pmpcfg.X are all 0, the region is inaccessible in S/U-mode and the S/U-mode result is an access exception.
RULE 55: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.R, and pmpcfg.W are 0, and pmpcfg.X is 1, the M-mode result is an access exception.
RULE 56: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.R, and pmpcfg.W are 0, and pmpcfg.X is 1, the region is execute-only in S/U-mode.
RULE 57: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.R are 0, pmpcfg.W is 1, and pmpcfg.X is 0, the region is a shared data region with read/write access in M-mode.
RULE 58: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.R are 0, pmpcfg.W is 1, and pmpcfg.X is 0, the region is a shared data region with read-only access in S/U-mode.
RULE 59: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.R are 0, and pmpcfg.W and pmpcfg.X are 1, the region is a shared data region with read/write access in M-mode.
RULE 60: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.R are 0, and pmpcfg.W and pmpcfg.X are 1, the region is a shared data region with read/write access in S/U-mode.
RULE 61: When mseccfg.MML is set to 1, pmpcfg.L is 0, pmpcfg.R is 1, and pmpcfg.W and pmpcfg.X are 0, the M-mode result is an access exception.
RULE 62: When mseccfg.MML is set to 1, pmpcfg.L is 0, pmpcfg.R is 1, and pmpcfg.W and pmpcfg.X are 0, the region is read-only in S/U-mode.
RULE 63: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.W are 0, and pmpcfg.R and pmpcfg.X are 1, the M-mode result is an access exception.
RULE 64: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.W are 0, and pmpcfg.R and pmpcfg.X are 1, the region permits read and execute access in S/U-mode.
RULE 65: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.X are 0, and pmpcfg.R and pmpcfg.W are 1, the M-mode result is an access exception.
RULE 66: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.X are 0, and pmpcfg.R and pmpcfg.W are 1, the region permits read and write access in S/U-mode.
RULE 67: When mseccfg.MML is set to 1, pmpcfg.L is 0, and pmpcfg.R, pmpcfg.W, and pmpcfg.X are 1, the M-mode result is an access exception.
RULE 68: When mseccfg.MML is set to 1, pmpcfg.L is 0, and pmpcfg.R, pmpcfg.W, and pmpcfg.X are 1, the region permits read, write, and execute access in S/U-mode.
RULE 69: When mseccfg.MML is set to 1, pmpcfg.L is 1, and pmpcfg.R, pmpcfg.W, and pmpcfg.X are 0, the region is a locked inaccessible region in M-mode and the M-mode result is an access exception.
RULE 70: When mseccfg.MML is set to 1, pmpcfg.L is 1, and pmpcfg.R, pmpcfg.W, and pmpcfg.X are 0, the region is a locked inaccessible region in S/U-mode and the S/U-mode result is an access exception.
RULE 71: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.X are 1, and pmpcfg.R and pmpcfg.W are 0, the region is a locked execute-only region in M-mode.
RULE 72: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.X are 1, and pmpcfg.R and pmpcfg.W are 0, the S/U-mode result is an access exception.
RULE 73: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.W are 1, and pmpcfg.R and pmpcfg.X are 0, the region is a locked shared code region with execute-only access in M-mode.
RULE 74: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.W are 1, and pmpcfg.R and pmpcfg.X are 0, the region is a locked shared code region with execute-only access in S/U-mode.
RULE 75: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.W, and pmpcfg.X are 1, and pmpcfg.R is 0, the region is a locked shared code region with read and execute access in M-mode.
RULE 76: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.W, and pmpcfg.X are 1, and pmpcfg.R is 0, the region is a locked shared code region with execute-only access in S/U-mode.
RULE 77: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.R are 1, and pmpcfg.W and pmpcfg.X are 0, the region is a locked read-only region in M-mode.
RULE 78: When mseccfg.MML is set to 1, pmpcfg.L and pmpcfg.R are 1, and pmpcfg.W and pmpcfg.X are 0, the S/U-mode result is an access exception.
RULE 79: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.R, and pmpcfg.X are 1, and pmpcfg.W is 0, the region is a locked read/execute region in M-mode.
RULE 80: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.R, and pmpcfg.X are 1, and pmpcfg.W is 0, the S/U-mode result is an access exception.
RULE 81: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.R, and pmpcfg.W are 1, and pmpcfg.X is 0, the region is a locked read/write region in M-mode.
RULE 82: When mseccfg.MML is set to 1, pmpcfg.L, pmpcfg.R, and pmpcfg.W are 1, and pmpcfg.X is 0, the S/U-mode result is an access exception.
RULE 83: When mseccfg.MML is set to 1 and pmpcfg.L, pmpcfg.R, pmpcfg.W, and pmpcfg.X are all 1, the region is a locked shared data region with read-only access in M-mode.
RULE 84: When mseccfg.MML is set to 1 and pmpcfg.L, pmpcfg.R, pmpcfg.W, and pmpcfg.X are all 1, the region is a locked shared data region with read-only access in S/U-mode.
RULE 85: When S-mode is implemented and execution is in M-mode, mseccfg.MLPE is the effective xLPE control: if MLPE=1, a Zicfilp landing-pad violation raises a software-check exception; if MLPE=0, the same transfer is not rejected by Zicfilp landing-pad enforcement.

REGISTER: mstatus
NUMBER: 0x300
MODE: M-mode
WIDTH: MXLEN
FIELDS: 63..63=SD, 42..42=MDT, 41..41=MPELP, 39..39=MPV, 38..38=GVA, 37..37=MBE, 36..36=SBE, 35..34=SXL, 33..32=UXL, 23..23=SPELP, 22..22=TSR, 21..21=TW, 20..20=TVM, 19..19=MXR, 18..18=SUM, 17..17=MPRV, 16..15=XS, 14..13=FS, 12..11=MPP, 10..9=VS, 8..8=SPP, 7..7=MPIE, 6..6=UBE, 5..5=SPIE, 3..3=MIE, 1..1=SIE
EXTENSIONS: D, F, H, Q, Smdbltrp, Smrnmi, Ssdbltrp, Svinval, V, Zawrs, Zfinx, Zicboz, Zicfilp
RULE 1: If mstatus.TW=1 and WRS.NTO is executed outside M-mode but does not complete within the implementation-specific bounded time limit, then WRS.NTO raises an illegal-instruction exception.
RULE 2: The vector context status field mstatus.VS occupies mstatus[10:9].
RULE 3: The mstatus.VS field is shadowed in sstatus[10:9].
RULE 4: When mstatus.VS is Off, an attempt to execute any vector instruction or access any vector CSR raises an illegal-instruction exception.
RULE 5: When mstatus.VS is Initial or Clean, executing any instruction that changes vector state, including an instruction that changes a vector CSR, changes mstatus.VS to Dirty.
RULE 6: When mstatus.VS is Dirty, mstatus.SD is 1.
RULE 7: When mstatus.VS is not Dirty, mstatus.VS makes no Dirty-state contribution to mstatus.SD.
RULE 8: When V=1, an attempt to execute any vector instruction raises an illegal-instruction exception if either vsstatus.VS or mstatus.VS is set to Off.
RULE 9: When V=1, an attempt to access any vector CSR raises an illegal-instruction exception if either vsstatus.VS or mstatus.VS is set to Off.
RULE 10: When V=1 and neither vsstatus.VS nor mstatus.VS is set to Off, executing any instruction that changes vector state, including an instruction that changes the vector CSRs, changes both mstatus.VS and vsstatus.VS to Dirty.
RULE 11: If mstatus.VS is Dirty, mstatus.SD is 1.
RULE 12: If mstatus.VS is not Dirty, mstatus.SD reads as 0 unless another condition defined to set mstatus.SD is present, in which case it reads as 1.
RULE 13: If mstatus.FS is Off, any attempt to execute a vector floating-point instruction will raise an illegal-instruction exception.
RULE 14: Any vector floating-point instruction that modifies floating-point extension state, comprising floating-point CSRs or f registers, must set mstatus.FS to Dirty.
RULE 15: If the hypervisor extension is implemented, V=1, and either vsstatus.FS or mstatus.FS is Off, any attempt to execute a vector floating-point instruction will raise an illegal-instruction exception.
RULE 16: If the hypervisor extension is implemented and V=1, any vector floating-point instruction that modifies floating-point extension state, comprising floating-point CSRs or f registers, must set both mstatus.FS and vsstatus.FS to Dirty.
RULE 17: The mstatus register is a machine-level read/write CSR.
RULE 18: Reading mstatus returns only bits [MXLEN−1:0]; no architectural mstatus bits exist at positions MXLEN or above.
RULE 19: The mstatus register is read/write.
RULE 20: If CSRRSI or CSRRCI targets an implemented global xIE bit in the low-order bits of mstatus, that single instruction atomically sets or clears the bit, and a subsequent mstatus read returns the updated value.
RULE 21: Each xPP field in mstatus is a WARL field that can hold only privilege mode x and any implemented privilege mode lower than x.
RULE 22: Reading mstatus and extracting the MPP field yields a two-bit value in the range 0–3.
RULE 23: After writing mstatus, reading it back reports SPP as a single-bit value, either 0 or 1.
RULE 24: When a trap is taken from privilege mode y into privilege mode x, the xPIE field in mstatus is set to the value of the xIE field in mstatus.
RULE 25: When a trap is taken from privilege mode y into privilege mode x, the xIE field in mstatus is set to 0.
RULE 26: When a trap is taken from privilege mode y into privilege mode x, the xPP field in mstatus is set to y.
RULE 27: When an xRET instruction executes with the xPP field in mstatus holding privilege mode y, the xIE field in mstatus is set to the value of the xPIE field in mstatus.
RULE 28: When an xRET instruction executes with the xPP field in mstatus holding privilege mode y, the privilege mode is changed to y.
RULE 29: When an xRET instruction executes with the xPP field in mstatus holding privilege mode y, the xPIE field in mstatus is set to 1.
RULE 30: When an xRET instruction executes with the xPP field in mstatus holding privilege mode y, the xPP field is set to the least-privileged supported mode, which is U if U-mode is implemented and M otherwise.
RULE 31: When an xRET instruction executes with the xPP field in mstatus holding a privilege mode y where y != M, the MPRV field in mstatus is also set to 0.
RULE 32: M-mode software can determine whether a privilege mode is implemented by writing that privilege mode to the MPP field in mstatus and then reading MPP back.
RULE 33: Upon reset, the MDT field represented in mstatus or mstatush is set to 1.
RULE 34: When an explicit CSR write sets the MDT bit in mstatus or mstatush to 1, the MIE bit in mstatus is cleared to 0.
RULE 35: On RV64, when an explicit CSR write sets mstatus.MDT to 1, mstatus.MIE is cleared to 0 regardless of the value written, if any, to mstatus.MIE by the same write.
RULE 36: An explicit CSR write can set mstatus.MIE to 1 only if the MDT bit in mstatus or mstatush is already 0 or, on RV64, the same write sets mstatus.MDT to 0.
RULE 37: When a trap is to be taken into M-mode and the MDT bit in mstatus or mstatush is currently 0, the MDT bit is set to 1.
RULE 38: If a trap targets M-mode while the MDT bit in mstatus or mstatush is 0, the hart takes the trap normally and transfers control to the M-mode trap handler.
RULE 39: When MRET is executed in M-mode, it sets the MDT bit in mstatus or mstatush to 0.
RULE 40: When SRET is executed in M-mode, it sets the MDT bit in mstatus or mstatush to 0.
RULE 41: On an RV64 hart, after entering S-mode, instructions execute with the XLEN encoded by the read-back value of mstatus.SXL; if SXL selects 32 bits, operand bits 63:32 are ignored and register results are sign-extended from bit 31, whereas if SXL selects 64 bits, all 64 operand and result bits are used.
RULE 42: On an RV64 hart, after writing and reading back mstatus.UXL, U-mode instructions execute with the XLEN encoded by the read-back UXL value.
RULE 43: For an RV64 hart, the encoding of the SXL field of mstatus is the same as the encoding of the MXL field of misa.
RULE 44: For an RV64 hart, the encoding of the UXL field of mstatus is the same as the encoding of the MXL field of misa.
RULE 45: When MXLEN=64 and S-mode is supported, reading mstatus returns an SXL field whose value encodes the current SXLEN.
RULE 46: When MXLEN=64 and U-mode is supported, the UXL field of mstatus encodes the current value of UXLEN.
RULE 47: If S-mode is implemented and mstatus.UXL is written with a value that would make UXLEN greater than SXLEN, a subsequent read of mstatus.UXL returns a legal value for which UXLEN is no greater than SXLEN.
RULE 48: When mstatus.MPRV=0, protection for explicit memory accesses uses the protection mechanisms of the current privilege mode.
RULE 49: When mstatus.MPRV=1, loads and stores are protected as though the current privilege mode were the privilege mode encoded in mstatus.MPP.
RULE 50: When mstatus.MPRV=1, endianness is applied to loads and stores as though the current privilege mode were the privilege mode encoded in mstatus.MPP.
RULE 51: An MRET instruction that changes the privilege mode to a mode less privileged than M-mode also sets mstatus.MPRV=0.
RULE 52: An SRET instruction that changes the privilege mode to a mode less privileged than M-mode also sets mstatus.MPRV=0.
RULE 53: The mstatus.MXR mechanism has no impact on whether access-fault exceptions are raised due to PMAs or PMP.
RULE 54: The mstatus.SUM bit has no effect when page-based virtual memory is not in effect.
RULE 55: The mstatus.SUM bit is read-only 0 if satp.MODE is read-only 0.
RULE 56: The mstatus.SUM mechanism has no impact on whether access-fault exceptions are raised due to PMAs or PMP.
RULE 57: For non-instruction-fetch memory accesses in M-mode, S-mode, and U-mode, the corresponding MBE, SBE, or UBE field in mstatus or mstatush selects the byte order used by loads, stores, and other data-memory accesses; changing these fields does not change instruction-fetch byte order.
