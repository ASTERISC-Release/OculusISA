REGISTER: mseccfg
SUMMARY: mseccfg is an MRW machine-mode CSR that configures optional security controls, including seed-CSR access for U/S modes, PMP/MML policy and lock behavior, pointer masking, and M-mode Zicfilp enabling. M-mode accesses complete without exception when mseccfg is implemented by a relevant extension, whereas S-mode and U-mode accesses raise an illegal-instruction exception; absent any extension adding an mseccfg field, accesses raise illegal-instruction. SSEED and USEED gate S/HS-mode and U-mode read-write access to the seed CSR, with zero causing an illegal-instruction exception for that mode and one permitting read-write access while other access types trap; M-mode seed access is not gated, and implementations may hardwire these fields to read-only zero, discoverable by write-readback. PMP-related fields control sticky MMWP/MML behavior, locked-rule modification via RLB, MML-based PMP permission decoding/shared-region enforcement and M-mode execution restrictions, while PMM controls M-mode pointer masking under Smmpm and MLPE controls/resets M-mode Zicfilp enforcement.

REGISTER: mstatus
SUMMARY: mstatus is the machine-level status CSR (CSR 0x300) that holds global interrupt-enable state, trap/return privilege state, and control/status fields for endianness, PMP/MPRV, virtualization, and extension context tracking such as FS, VS, XS, and the SD dirty summary. It is readable and writable in M-mode, while access from S-mode or U-mode raises an illegal-instruction exception; writable fields are WARL and may legalize unsupported values, with shared fields visible through sstatus. mstatus controls exception behavior: WFI/WRS may trap when TW is set, S-mode satp/SFENCE/invalidation and SRET may trap under TVM/TSR, and vector or floating-point use raises illegal-instruction exceptions when the relevant VS/FS state is Off, including virtual-mode checks. Trap entry and xRET operations update interrupt-enable, previous-privilege, virtualization/ELP, and dirty-summary fields, and subsequent readbacks must reflect those architectural updates.

REGISTER: satp
SUMMARY: satp is a currently allocated SRW supervisor CSR (0x180) that stores the root page-table physical page number together with ASID and MODE fields, allowing these values to be changed atomically for context switches; unsupported MODE writes have no effect. It is an SXLEN-bit read/write register with MODE-dependent translation such as Sv39. Access from M-mode and HS-mode does not fault, S-mode reads and writes are permitted only when mstatus.TVM=0, and TVM=1 makes S-mode satp accesses raise an illegal-instruction exception (mcause=2) without completing; U-mode access also raises illegal-instruction. Virtualization-intercepted guest S-mode satp operations trap to the hypervisor with no guest-visible satp update, and if satp.MODE is read-only 0 then SUM is read-only 0.

REGISTER: scounteren
SUMMARY: The scounteren register (CSR 0x106, SRW, implemented) is a supervisor counter-enable register whose CY, TM, IR, and HPMn bits control U-mode access to corresponding cycle, time, instret, and HPM counters. S-mode and M-mode accesses are permitted read/write, with reads returning the current enable mask and writes updating implemented enable bits; direct U-mode access to scounteren raises an illegal-instruction exception. Clearing an implemented enable bit makes a U-mode read of the matching counter raise an illegal-instruction exception, while setting it permits access only when the corresponding mcounteren bit is also set. Under virtualization, VU-mode counter reads are gated by scounteren bits and access to a nonexistent vscounteren raises an illegal-instruction exception.
