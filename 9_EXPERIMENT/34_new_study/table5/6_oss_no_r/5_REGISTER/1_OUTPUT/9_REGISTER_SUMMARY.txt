REGISTER: mseccfg
SUMMARY: The mseccfg CSR is a machine‑read/write register that defines a hart's security configuration, covering seed‑CSR access control, PMP policy modifiers, and optional landing‑pad enablement. Its USEED and SSEED fields (added by the Zkr extension) gate read‑write access to the seed CSR from U‑mode and S/HS‑mode respectively; when a field is zero any such access raises an illegal‑instruction exception, while a one (if Zkr is present) permits normal access. The RLB, MMWP, and MML bits adjust PMP behavior—RLB is a WARL lock‑bypass, MMWP and MML are sticky bits that change default PMP permissions and rule lockdown semantics—and they are writable only in M‑mode with a reset value of zero, causing access‑fault exceptions according to the PMP truth table when violated. Writes to undefined fields or to USEED/SSEED when Zkr is not implemented, as well as any access to mseccfg from S‑ or U‑mode, raise an illegal‑instruction exception.

REGISTER: mstatus
SUMMARY: The mstatus CSR (address 0x300) is the machine‑level status register, readable‑and‑writable only in Machine mode and containing the superset of all fields found in sstatus. It records the privilege‑mode stack (MPP, SPP, MPIE, etc.) and global interrupt‑enable bits (MIE, SIE), controls virtual‑memory and protection (MPRV, MPV, MXR, SUM, TVM, TSR, TW), selects endianness for non‑instruction accesses (MBE/SBE/UBE), and tracks the state of optional extensions (XS, FS, VS) whose Dirty condition drives the read‑only SD flag. The MPRV/MPV bits cause explicit loads/stores (including CMO) to be checked as if executed in the privilege level encoded by MPP, MXR and SUM modify page‑permission checks for reads and supervisor‑user accesses, TVM and TSR trap attempts to use satp/SFENCE.VMA or SRET, and the endianness bits select byte order for those accesses. Violations raise the appropriate exceptions: illegal‑instruction for unauthorized CSR or extension use, load‑access‑fault when MXR=0 and a page is not readable, and memory‑access faults when permission bits deny the operation, while any change to extension state automatically updates the corresponding XS/FS/VS field and consequently the SD flag.

REGISTER: satp
SUMMARY: The supervisor address‑translation register (satp) is a supervisor‑level CSR that selects the virtual‑memory scheme (MODE), identifies the address space (ASID), and holds the physical page number of the root page table (PPN). It is readable and writable in S‑mode (SRW) unless the TVM bit in mstatus is set, in which case any S‑mode access raises an illegal‑instruction exception; U‑mode accesses are always illegal, while M‑mode accesses are permitted. When MODE is non‑zero, satp enables page‑based address translation and activates MXR and SUM privilege checks, whereas MODE = Bare disables translation and treats virtual addresses as physical. Changes to MODE or ASID take effect immediately without an implicit TLB flush, and attempts to write an unsupported MODE or to access satp while prohibited raise an illegal‑instruction exception (mcause = 2).

REGISTER: scounteren
SUMMARY: The scounteren CSR (address 0x106) is a supervisor‑level register that enables user‑mode reads of the hardware counters—cycle (CY), time (TM), retired‑instruction (IR), and the programmable HPM counters. Each field is a single enable bit; a set bit permits U‑mode access to the associated counter, while a cleared or hard‑wired‑zero bit causes an illegal‑instruction exception on any U‑mode read of that counter. The register is readable and writable in supervisor (and machine) privilege (SRW), produces no exception in M‑ or HS‑mode, but raises an illegal‑instruction exception when accessed directly from U‑mode. A U‑mode counter read succeeds only if both the corresponding scounteren bit and the matching mcounteren bit are set, and scounteren has no virtual‑supervisor counterpart even when the hypervisor extension is implemented.
