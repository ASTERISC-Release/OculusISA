REGISTER: mseccfg
RULE 1: The mseccfg CSR contains the SSEED and USEED fields, which are added by the Zkr extension.
RULE 2: The SSEED and USEED fields within mseccfg are used to control access to the seed CSR from U, S, or HS modes.
RULE 3: Implementations may design mseccfg such that the [s,u]seed fields are read-only constant values of 0.
RULE 4: Software can determine if access to the seed CSR can be enabled in U and S mode by writing a 1 to the [s,u]seed fields of mseccfg and reading back the result.
RULE 5: The mseccfg.[s,u]seed option allows for the creation of a security boundary around a component regarding Sensitive Security Parameter (SSP) flows.
RULE 6: The mseccfg.[s,u]seed option enables the security boundary to be established even if the component is not operating in M mode.
RULE 7: The mseccfg.[s,u]seed option is useful when implementing trusted enclaves to ensure the entire key lifecycle occurs without the key being passed across the boundary to external code.
RULE 8: The mseccfg register is the Machine security configuration register.
RULE 9: The address of the mseccfg register is 0x747.
RULE 10: The privilege level for the mseccfg register is MRW.
RULE 11: The mseccfg register is categorized under Machine Configuration.
RULE 12: mseccfg is a 64-bit read/write register used to control security features.
RULE 13: mseccfg exists if any extension that adds a field to it is implemented; otherwise, it is reserved.
RULE 14: The Zkr extension adds the SSEED and USEED fields to mseccfg to control seed CSR access from modes less privileged than M.
RULE 15: In mseccfg, if USEED is 0, U-mode access to the seed CSR raises an illegal-instruction exception; if USEED is 1, read-write access is allowed.
RULE 16: If Zkr or U-mode is not implemented, the USEED field in mseccfg is read-only zero.
RULE 17: In mseccfg, if SSEED is 0, S-/HS-mode access to the seed CSR raises an illegal-instruction exception; if SSEED is 1, read-write access is allowed.
RULE 18: If Zkr or S-mode is not implemented, the SSEED field in mseccfg is read-only zero.
RULE 19: The Smepmp extension adds the RLB, MMWP, and MML fields to mseccfg.
RULE 20: mseccfg.RLB (Rule Locking Bypass) is a WARL field; when it is 1, locked PMP rules may be removed, modified, or edited.
RULE 21: If mseccfg.RLB is 0 and any pmpcfg.L is 1, mseccfg.RLB remains 0 and further modifications to it are ignored until a PMP reset.

RULE 33: The mseccfg CSR contains the RLB, MMWP, and MML fields.

RULE 19: In VU-mode, a virtual-instruction exception is raised when attempting to access a non-high-half counter CSR if the corresponding bit in mcounteren is 1 but the corresponding bit in either hcounteren or scounteren is 0.
RULE 20: In M-mode, accessing scounteren register should result in no exception (# Result: mcause = 0x0) [# Extension Must Be Active: NONE; csrr a0, 0x106; # Result: mcause = 0x0].
RULE 21: In HS-mode, accessing scounteren register should result in no exception (# Result: mcause = 0x0) [# Extension Must Be Active: NONE; call machine_to_supervisor; csrr a0, 0x106; # Result: mcause = 0x0].
