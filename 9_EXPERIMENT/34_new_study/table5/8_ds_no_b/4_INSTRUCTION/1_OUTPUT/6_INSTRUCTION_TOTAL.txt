INSTRUCTION: CSRRWI
FORMAT: -
RULE 1: CSRRWI updates the single CSR selected by the CSRRWI's CSR specifier using an XLEN-bit value obtained by zero-extending the 5-bit unsigned immediate uimm[4:0] instead of using a value from an integer register.
RULE 2: If CSRRWI has rd = x0, then it must not trigger any side effect that would occur on a read of the CSR selected by its CSR specifier; any architectural state change or exception caused solely by reading that CSR does not occur, and only effects of the CSRRWI’s CSR write or write-access exception are observable.
RULE 3: CSRRWI with rd = x0 writes the single CSR selected by the CSRRWI's CSR specifier.
RULE 4: CSRRWI with rd not equal to x0 reads the single CSR selected by the CSRRWI's CSR specifier.
RULE 5: CSRRWI with rd not equal to x0 writes the single CSR selected by the CSRRWI's CSR specifier.
RULE 6: If a CSRRWI has rd ≠ x0, then the instruction reads the single CSR selected by its CSR specifier and any architectural side effects of that CSR read occur; if rd = x0, no such CSR-read side effects occur.
RULE 7: When CSRRWI successfully writes the CSR selected by its CSR specifier, the architectural state changes exactly as if the 5-bit immediate were written to that one selected CSR, including any side effects defined for a write to that CSR; if no such write occurs, none of that CSR’s write side effects occur.
RULE 8: When CSRRWI writes the CSR selected by its CSR specifier, every field in that CSR that has a write side effect performs that side effect; if any such field’s side effect is missing, the post-instruction architectural state does not match the defined CSRRWI write, as observable through affected CSR readback or other architectural state changed by that side effect.

INSTRUCTION: FCVT.W.D
FORMAT: -
RULE 1: FCVT.W.D converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 2: On RV64, FCVT.W.D sign-extends the 32-bit integer result into the destination register.
RULE 3: FCVT.W.D rounds its result according to the rm field.
RULE 4: If FCVT.W.D is executed with a rounding mode other than RTZ (including DYN with frm not RTZ) and the source double value rounds to a different integer than truncation toward zero, then the destination register contains the integer produced by the selected rounding mode, not the truncation toward zero; for example, with rm=RNE and source 3.5, rd contains 4, not 3.
RULE 5: If FCVT.W.D is executed with a numeric source whose rounded, unbounded two’s complement result is outside the signed 32-bit range, then integer register rd does not contain the sign-extension to XLEN of bits 31:0 of that result; instead rd contains 0x7fffffff sign-extended to XLEN for positive overflow or 0x80000000 sign-extended to XLEN for negative overflow, and fflags.NV is set.
RULE 6: If FCVT.W.D is executed with a double-precision positive infinity source and invalid-operation exceptions are disabled, then the destination register contains 0x7fffffff rather than zero and fflags.NV is set; if invalid-operation exceptions are enabled, it raises a floating-point invalid-operation exception instead of writing zero.
RULE 7: FCVT.W.D does not convert negative infinity to zero.
RULE 8: FCVT.W.D does not convert NaN to zero.
RULE 9: Executing FCVT.W.D sets the floating-point exception flag bits in fflags according to its input operand: a NaN, infinity, or out-of-range signed 32-bit conversion result sets NV, and a non-exact conversion sets NX, with the resulting fflags value observable by reading fflags after the instruction.

INSTRUCTION: SFENCE.VMA
FORMAT: -
RULE 1: When TVM=1, an attempt to execute SFENCE.VMA while executing in S-mode raises an illegal-instruction exception.
RULE 2: When TVM=0, execution of SFENCE.VMA in S-mode is permitted.
RULE 3: If the value held in rs1 is not a valid virtual address, SFENCE.VMA raises no exception.
RULE 4: If SFENCE.VMA is executed with rs2!=x0 and any reserved bit in rs2[SXLEN-1:ASIDMAX] is set that is not defined by a standard extension, then those reserved bits are ignored: no exception is raised because of them, and subsequent address translations behave as if those reserved bits were zero while the defined ASID bits are unchanged.
RULE 5: An SFENCE.VMA instruction requires the same permissions as a SINVAL.VMA instruction.
RULE 6: An attempt to execute SFENCE.VMA in U-mode always raises an illegal-instruction exception.
RULE 7: An attempt to execute SFENCE.VMA in S-mode when mstatus.TVM=1 raises an illegal-instruction exception.
RULE 8: An attempt to execute SFENCE.VMA in HS-mode when mstatus.TVM=1 raises an illegal-instruction exception.
RULE 9: An attempt to execute SFENCE.VMA in VU-mode raises a virtual-instruction exception.
RULE 10: When hstatus.VTVM=1, an attempt to execute SFENCE.VMA in VS-mode raises a virtual-instruction exception.
RULE 11: When VTVM=1, an attempt in VS-mode to execute SFENCE.VMA raises a virtual-instruction exception rather than an illegal-instruction exception.
RULE 12: If hstatus.VTVM=1 and SFENCE.VMA is executed in VS-mode, then SFENCE.VMA raises a virtual-instruction exception; if SFENCE.VMA is executed in any mode other than VS-mode, hstatus.VTVM has no effect on SFENCE.VMA and no VTVM-induced exception is raised.
RULE 13: An attempt in VS-mode to execute SFENCE.VMA when V=1 and hstatus.VTVM=1 raises a virtual-instruction exception.
RULE 14: When an attempt in VS-mode to execute SFENCE.VMA when V=1 and hstatus.VTVM=1 raises a virtual-instruction exception, mtval or stval is written the same as for an illegal-instruction trap.

INSTRUCTION: VLE32FF.V
FORMAT: -
RULE 1: If element 0 raises a synchronous exception during VLE32FF.V execution, VLE32FF.V takes the trap.
RULE 2: If element 0 raises a synchronous exception during VLE32FF.V execution, VLE32FF.V leaves vl unmodified.
RULE 3: If an element after element 0 raises a synchronous exception during VLE32FF.V execution, VLE32FF.V does not take the corresponding trap.
RULE 4: If an element after element 0 raises a synchronous exception during VLE32FF.V execution, VLE32FF.V reduces vl to the index of the element that would have raised the exception.
RULE 5: During VLE32FF.V execution, VLE32FF.V does not update active destination elements past the original vector length.
RULE 6: For VLE32FF.V, if vstart equals 0 and vl is greater than 0, then at least one element must be processed.
RULE 7: If VLE32FF.V takes a trap due to an interrupt and the vl CSR readback afterward is less than the vl value before the instruction, then the implementation has violated the rule; conforming behavior leaves vl not reduced by the interrupt trap.
RULE 8: When VLE32FF.V would trigger a debug data-watchpoint trap on an element after the first, implementations should not reduce vl.
