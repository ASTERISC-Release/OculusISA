REGISTER: mseccfg
RULE 1: The [s,u]seed field of mseccfg can be a read-only constant value 0.
RULE 2: Software can discover whether access to the seed CSR can be enabled in U and S modes by writing 1 to the [s,u]seed field of mseccfg and reading back the result.
RULE 3: The direct mseccfg.[s,u]seed option allows a security boundary to be drawn around a component in relation to Sensitive Security Parameter (SSP) flows even if that component is not in M mode.
RULE 4: mseccfg has privilege MRW.
RULE 5: mseccfg is a 64-bit read/write register that controls security features.
RULE 6: mseccfg exists if any extension that adds a field to mseccfg is implemented.
RULE 7: mseccfg is reserved if no extension that adds a field to mseccfg is implemented.
RULE 8: When XLEN=64, the mseccfgh alias register of mseccfg does not exist.
RULE 9: When mseccfg.USEED is 0, access to the seed CSR in U-mode raises an illegal-instruction exception.
RULE 10: When mseccfg.USEED is 1, read-write access to the seed CSR from U-mode is allowed.
RULE 11: When mseccfg.USEED is 1, a seed CSR access from U-mode that is not a read-write access raises an illegal-instruction exception.
RULE 12: If Zkr or U-mode is not implemented, mseccfg.USEED is read-only zero.
RULE 13: When mseccfg.SSEED is 0, access to the seed CSR from S-/HS-mode raises an illegal-instruction exception.
RULE 14: When mseccfg.SSEED is 1, read-write access to the seed CSR from S-/HS-mode is allowed.
RULE 15: When mseccfg.SSEED is 1, a seed CSR access from S-/HS-mode that is not a read-write access raises an illegal-instruction exception.
RULE 16: If Zkr or S-mode is not implemented, mseccfg.SSEED is read-only zero.
RULE 17: When the H extension is implemented and mseccfg.SSEED is 0, any seed CSR access from VS or VU mode raises an illegal-instruction exception.
RULE 18: When the H extension is implemented and mseccfg.SSEED is 1, a read-write seed CSR access from VS or VU mode by an HS-qualified instruction raises a virtual-instruction exception.
RULE 19: When the H extension is implemented and mseccfg.SSEED is 1, all other types of seed CSR accesses from VS or VU mode raise an illegal-instruction exception.
RULE 20: When mseccfg.RLB is 1, locked PMP rules may be removed or modified and locked PMP rules may be edited.
RULE 21: When mseccfg.RLB is 0 and pmpcfg.L is 1 in any PMP rule or entry including disabled entries, mseccfg.RLB remains 0.
RULE 22: When mseccfg.RLB is 0 and pmpcfg.L is 1 in any PMP rule or entry including disabled entries, any further modifications to mseccfg.RLB are ignored until a PMP reset.
RULE 23: mseccfg.MMWP is a sticky bit, meaning that once set it cannot be unset until a PMP reset.
RULE 24: When mseccfg.MMWP is set, the default PMP policy for M-mode when accessing memory regions that do not have a matching PMP rule is denied instead of ignored.
RULE 25: mseccfg.MML is a sticky bit, meaning that once set it cannot be unset until a PMP reset.
RULE 26: When mseccfg.MML is set, pmpcfg.L set marks a PMP rule as M-mode-only instead of marking that rule as locked and enforced in all modes.
RULE 27: When mseccfg.MML is set, pmpcfg.L unset marks a PMP rule as S/U-mode-only.
RULE 28: When mseccfg.MML is set, the formerly reserved encoding pmpcfg.RW=01 encodes a Shared-Region.
RULE 29: When mseccfg.MML is set, the encoding pmpcfg.LRWX=1111 encodes a Shared-Region.
RULE 30: When mseccfg.MML is set, an M-mode-only PMP rule is enforced on Machine mode and denied in Supervisor or User mode.
RULE 31: When mseccfg.MML is set, an M-mode-only PMP rule remains locked so that any further modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.
RULE 32: When mseccfg.MML is set, an S/U-mode-only PMP rule is enforced on Supervisor and User modes and denied on Machine mode.
RULE 33: When mseccfg.MML is set and a Shared-Region PMP rule has pmpcfg.L not set, the rule can be used for sharing data between M-mode and S/U-mode and is not executable.
RULE 34: When mseccfg.MML is set and a Shared-Region PMP rule has pmpcfg.L not set, M-mode has read/write access to that region.
RULE 35: When mseccfg.MML is set and a Shared-Region PMP rule has pmpcfg.L not set and pmpcfg.X is not set, S/U-mode has read access to that region.

RULE 39: When mseccfg.MML is set and a Shared-Region PMP rule has pmpcfg.L set and pmpcfg.X is set, M-mode also has read access to the region.
RULE 40: When mseccfg.MML is set and a Shared-Region PMP rule has pmpcfg.L set, the rule remains locked so that any further modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.
RULE 41: When mseccfg.MML is set, the encoding pmpcfg.LRWX=1111 can be used for sharing data between M-mode and S/U-mode with both modes having only read-only access to the region.
RULE 42: When mseccfg.MML is set and a PMP rule uses the encoding pmpcfg.LRWX=1111, the rule remains locked so that any further modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.
RULE 43: When mseccfg.MML is set, adding a PMP rule with executable privileges that is M-mode-only is not possible and such pmpcfg writes are ignored leaving pmpcfg unchanged.
RULE 44: When mseccfg.MML is set, adding a PMP rule with executable privileges that is a locked Shared-Region is not possible and such pmpcfg writes are ignored leaving pmpcfg unchanged.
RULE 45: When mseccfg.MML is set, the restriction on adding a PMP rule with executable privileges that is M-mode-only or a locked Shared-Region can be temporarily lifted by setting mseccfg.RLB, for example during the boot process.
RULE 46: When mseccfg.MML is set, executing code with Machine mode privileges is only possible from memory regions with a matching M-mode-only rule or a matching locked Shared-Region rule with executable privileges.
RULE 47: When mseccfg.MML is set, executing code with Machine mode privileges from a memory region without a matching PMP rule is denied.
RULE 48: When mseccfg.MML is set, executing code with Machine mode privileges from a memory region with a matching S/U-mode-only rule is denied.
RULE 49: When mseccfg.MML is not set, the combination pmpcfg.RW=01 remains reserved for future standard use.
RULE 50: If Smmpm is not implemented, mseccfg.PMM is read-only zero.
RULE 51: When mseccfg.PMM is 00, pointer masking is disabled with PMLEN=0.
RULE 52: mseccfg.PMM value 01 is reserved.
RULE 53: When mseccfg.PMM is 10, pointer masking is enabled with PMLEN=XLEN-57, which is PMLEN=7 on RV64.
RULE 54: When mseccfg.PMM is 11, pointer masking is enabled with PMLEN=XLEN-48, which is PMLEN=16 on RV64.
RULE 55: When mseccfg.MLPE is 1, the Zicfilp extension is enabled in M-mode.
RULE 56: When mseccfg.MLPE is 0, the Zicfilp extension is not enabled in M-mode.
RULE 57: When mseccfg.MLPE is 0, the hart does not update the ELP state and the ELP state remains NO_LP_EXPECTED in M-mode.
RULE 58: When mseccfg.MLPE is 0, the LPAD instruction operates as a no-op in M-mode.
RULE 59: If the Zicfilp extension is implemented, the mseccfg.MLPE field is reset to 0.
RULE 60: At reset, the mseccfg.MML field is set to 0 unless the platform mandates a different reset value.
RULE 61: At reset, the mseccfg.MMWP field is set to 0 unless the platform mandates a different reset value.
RULE 62: At reset, the mseccfg.RLB field is set to 0 unless the platform mandates a different reset value.
RULE 63: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 0, 0, 0, the region is inaccessible with an access exception in M-mode and is inaccessible with an access exception in S/U-mode.
RULE 64: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 0, 0, 1, the M-mode result is an access exception and the S/U-mode result is an execute-only region.
RULE 65: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 0, 1, 0, the M-mode and S/U-mode results both specify a shared data region that is read/write in M-mode and read-only in S/U-mode.

RULE 67: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 1, 0, 0, the M-mode result is an access exception and the S/U-mode result is a read-only region.
RULE 68: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 1, 0, 1, the M-mode result is an access exception and the S/U-mode result is a read/execute region.
RULE 69: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 1, 1, 0, the M-mode result is an access exception and the S/U-mode result is a read/write region.
RULE 70: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 0, 1, 1, 1, the M-mode result is an access exception and the S/U-mode result is a read/write/execute region.
RULE 71: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 1, 0, 0, 0, the region is locked inaccessible with an access exception in M-mode and is locked inaccessible with an access exception in S/U-mode.
RULE 72: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 1, 0, 0, 1, the M-mode result is a locked execute-only region and the S/U-mode result is an access exception.
RULE 73: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 1, 0, 1, 0, the M-mode and S/U-mode results both specify a locked shared code region that is execute-only in both M-mode and S/U-mode.
RULE 74: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 1, 0, 1, 1, the M-mode and S/U-mode results both specify a locked shared code region that is execute-only in S/U-mode and read/execute in M-mode.
RULE 75: When mseccfg.MML is set to 1 and the pmpcfg L, R, W, and X bits are 1, 1, 0, 0, the M-mode result is a locked read-only region and the S/U-mode result is an access exception.

REGISTER: mstatus
RULE 1: When the TW (Timeout Wait) bit in mstatus is set, WRS.NTO is executed in any privilege mode other than M mode, and WRS.NTO does not complete within an implementation-specific bounded time limit, WRS.NTO will cause an illegal-instruction exception.

RULE 64: When V=1 and the hart is in VS-mode, a virtual-instruction exception with code 22 is raised for attempts to access satp when hstatus.VTVM=1.
RULE 65: If satp.MODE or, when V=1, vsatp.MODE is set to Bare and the effective privilege mode is less than M, shadow stack instructions raise a store/AMO access-fault exception.
RULE 66: The active satp register's MODE field not being Bare is the exception to the ignore transformation applying to a physical address, including a guest-physical address, to replace the upper PMLEN bits with 0.

REGISTER: scounteren
RULE 1: scounteren has privilege SRW.
RULE 2: When the CY bit in scounteren is clear, an attempt to read the cycle register while executing in U-mode will cause an illegal-instruction exception.
RULE 3: When the TM bit in scounteren is clear, an attempt to read the time register while executing in U-mode will cause an illegal-instruction exception.
RULE 4: When the IR bit in scounteren is clear, an attempt to read the instret register while executing in U-mode will cause an illegal-instruction exception.
RULE 5: When the HPM n bit in scounteren is clear, an attempt to read the hpmcountern register while executing in U-mode will cause an illegal-instruction exception.
RULE 6: When the CY bit in scounteren is set, access to the cycle register is permitted.
RULE 7: When the TM bit in scounteren is set, access to the time register is permitted.
RULE 8: When the IR bit in scounteren is set, access to the instret register is permitted.
RULE 9: When the HPM n bit in scounteren is set, access to the hpmcountern register is permitted.
RULE 10: A bit in scounteren being read-only zero indicates that reads to the corresponding counter will cause an exception when executing in U-mode.
RULE 11: The setting of a bit in mcounteren does not affect whether the corresponding bit in scounteren is writable.
RULE 12: U-mode may access a counter only if the corresponding bits in scounteren and mcounteren are both set.
RULE 13: scounteren continues to have its usual function and accessibility even when V=1, except with VS-mode and VU-mode substituting for HS-mode and U-mode.
RULE 14: In VU-mode, a counter is not readable unless the applicable bits are set in both hcounteren and scounteren.
RULE 15: When V=1, a virtual-instruction exception (code 22) is normally raised instead of an illegal-instruction exception if an attempted HS-qualified instruction is prevented from executing because the instruction is expressly disabled by a supervisor or hypervisor CSR such as scounteren or hcounteren.
RULE 16: In VU-mode, an attempt to access a non-high-half counter CSR raises a virtual-instruction exception when the corresponding bit in either hcounteren or scounteren is 0 and the same bit in mcounteren is 1.
