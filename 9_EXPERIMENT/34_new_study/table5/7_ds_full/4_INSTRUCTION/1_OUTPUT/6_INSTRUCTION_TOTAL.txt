INSTRUCTION: CSRRWI
FORMAT: csrrwi rd, csr, zimm5
RULE 1: If rd is not x0, then executing CSRRWI atomically reads the CSR selected by csr, writes the zero-extended zimm into that same CSR, and writes the previously read CSR value into rd; the observable post-instruction state is rd equal to the old selected-CSR value and a readback of the selected CSR equal to the zero-extended zimm, with no other CSR changed.
RULE 2: CSRRWI updates the specified CSR using an XLEN-bit value obtained by zero-extending the 5-bit unsigned immediate uimm[4:0] instead of using a value from an integer register.
RULE 3: When rd is x0, CSRRWI atomically writes the single CSR specified by the instruction.
RULE 4: If CSRRWI is executed with rd=x0, then it does not read the specified CSR and therefore does not raise any exception or produce any side effect that would result from reading that CSR.
RULE 5: If CSRRWI uses x0 as rd, then the addressed CSR is not read and no CSR-read side effect occurs; the instruction’s specified CSR write still occurs and x0 remains zero.
RULE 6: If CSRRWI writes a CSR, then every field in that CSR that has a write side effect performs its specified side effect, observable in the resulting architectural state; if any such field’s side effect is not performed, that is the violation.
RULE 7: If CSRRWI targets a writable CSR, then it writes the zero-extended 5-bit immediate into that CSR and causes the architectural side effects defined for a write to that CSR, observable by reading back the CSR or affected architectural state; if the CSR is read-only or the write is otherwise illegal, the instruction raises an illegal-instruction exception and no CSR write or write side effect occurs.
RULE 8: If rd is not x0, executing CSRRWI reads the specified CSR and causes the architectural side effects of that read; if rd is x0, executing CSRRWI does not read the specified CSR and therefore does not cause those read side effects.

INSTRUCTION: FCVT.W.D
FORMAT: fcvt.w.d rd, fs1, rm
RULE 1: FCVT.W.D converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 2: FCVT.W.D rounds according to the rm field.
RULE 3: For RV64, FCVT.W.D sign-extends the 32-bit result.
RULE 4: If FCVT.W.D is executed with a double-precision source outside the valid input range of FCVT.W.S (NaN, infinity, or a value that rounds outside the signed 32-bit integer range under the current rounding mode), then it raises an invalid-operation floating-point exception by setting fflags.NV and writes the saturated signed 32-bit result (0x7fffffff for NaN or positive overflow, 0x80000000 for negative overflow); if the source is inside that range, it performs the signed conversion without setting fflags.NV.
RULE 5: If FCVT.W.D is executed with a NaN, an infinity, or a finite input whose value rounded according to the instruction’s rounding mode is outside the signed 32-bit integer range, then it sets fflags.NV and writes the destination integer register to the same value FCVT.W.S writes for that invalid input (0x7fffffff for NaN, positive overflow, or +infinity; 0x80000000 for negative overflow or -infinity), without raising an illegal-instruction exception.
RULE 6: For a given input operand, FCVT.W.D raises the same floating-point exception flags as FCVTMOD.W.D raises for that same input operand.

INSTRUCTION: SFENCE.VMA
FORMAT: sfence.vma rs1, rs2
RULE 1: When TVM=1, an attempt to execute an SFENCE.VMA instruction while executing in S-mode raises an illegal-instruction exception.
RULE 2: When TVM=0, an attempt to execute an SFENCE.VMA instruction while executing in S-mode is permitted.
RULE 3: If the value held in rs1 is not a valid virtual address, SFENCE.VMA raises no exception.
RULE 4: SFENCE.VMA requires the same permissions as SINVAL.VMA.
RULE 5: SFENCE.VMA raises the same exceptions as SINVAL.VMA.
RULE 6: An attempt to execute SFENCE.VMA in U-mode always raises an illegal-instruction exception.
RULE 7: An attempt to execute SFENCE.VMA in S-mode or HS-mode when mstatus.TVM=1 raises an illegal-instruction exception.
RULE 8: An attempt to execute SFENCE.VMA in VU-mode raises a virtual-instruction exception.
RULE 9: When hstatus.VTVM=1, an attempt to execute SFENCE.VMA in VS-mode raises a virtual-instruction exception.
RULE 10: When VTVM=1, an attempt in VS-mode to execute SFENCE.VMA raises a virtual-instruction exception.
RULE 11: When V=1, in VS-mode, an attempt to execute an SFENCE.VMA instruction when hstatus.VTVM=1 raises a virtual-instruction exception with code 22.
RULE 12: If an SFENCE.VMA instruction causes a virtual-instruction trap, mtval or stval is written the same as for an illegal-instruction trap.

INSTRUCTION: VLE32FF.V
FORMAT: vle32ff.v vd, (rs1), vm
RULE 1: VLE32FF.V executes as a regular load except that VLE32FF.V takes a trap caused by a synchronous exception only on element 0.
RULE 2: If element 0 of VLE32FF.V raises an exception, vl is not modified and the trap is taken.
RULE 3: If an element with index greater than 0 of VLE32FF.V raises an exception, the corresponding trap is not taken and vl is reduced to the index of that element.
RULE 4: VLE32FF.V may update active destination elements past the element that causes trimming of vl but not past the original vl.
RULE 5: If a VLE32FF.V element load from a non-idempotent memory location can be restarted because of a trap or vector-length trimming, then the implementation must not access that non-idempotent location for that element; if it does access it and the element load restarts, the location’s observable read side effect occurs more than once, which is a violation.
RULE 6: When VLE32FF.V raises no exception and vstart equals 0 and vl is greater than 0, VLE32FF.V must process at least one element.
RULE 7: If VLE32FF.V takes a trap due to an interrupt, the trap handler observes that vl is unchanged from its value at the start of VLE32FF.V and that vstart is set to the index of the first element not yet loaded; if the implementation reduces vl or leaves vstart not identifying that first uncompleted element, the architectural state seen by the handler is incorrect.
RULE 8: When VLE32FF.V would trigger a debug data-watchpoint trap on an element after the first element, implementations should not reduce vl and should instead trigger the debug trap so that the event is not lost.
