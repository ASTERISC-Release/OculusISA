REGISTER: mseccfg
RULE 1: The SSEED and USEED fields in the mseccfg CSR control access to the seed CSR from U, S, or HS modes.
RULE 2: Software may discover whether access to the seed CSR can be enabled in U and S modes by writing 1 to the [s,u]seed fields of the mseccfg CSR and reading back the result.
RULE 3: mseccfg has privilege MRW.
RULE 4: mseccfgh is the upper 32 bits of mseccfg.
RULE 5: mseccfgh, which is the upper 32 bits of mseccfg, has privilege MRW.
RULE 6: If no extension that adds a field to mseccfg is implemented, mseccfg is reserved.
RULE 7: When mseccfg.USEED is 0, access to the seed CSR in U-mode raises an illegal-instruction exception.
RULE 8: When mseccfg.USEED is 1, read-write access to the seed CSR from U-mode is allowed.
RULE 9: When mseccfg.USEED is 1, seed CSR accesses from U-mode other than read-write accesses raise an illegal-instruction exception.
RULE 10: If Zkr or U-mode is not implemented, mseccfg.USEED is read-only zero.
RULE 11: When mseccfg.SSEED is 0, access to the seed CSR from S-/HS-mode raises an illegal-instruction exception.
RULE 12: When mseccfg.SSEED is 1, read-write access to the seed CSR from S-/HS-mode is allowed.
RULE 13: When mseccfg.SSEED is 1, seed CSR accesses from S-/HS-mode other than read-write accesses raise an illegal-instruction exception.
RULE 14: If Zkr or S-mode is not implemented, mseccfg.SSEED is read-only zero.
RULE 15: When the H extension is also implemented and mseccfg.SSEED is 1, an access to the seed CSR from an HS-qualified instruction in VS or VU mode leads to a virtual-instruction exception.
RULE 16: In M-mode, the seed CSR is always available as normal with a CSR read-write instruction regardless of the mseccfg.SSEED and mseccfg.USEED access-control bits.
RULE 17: An attempted read of the seed CSR without a write raises an illegal-instruction exception regardless of mode and regardless of the mseccfg access-control bits.
RULE 18: When mseccfg.SSEED is 0, any access to the seed CSR from VS or VU mode raises an illegal-instruction exception.
RULE 19: When mseccfg.SSEED is 1, a read-write access to the seed CSR from VS or VU mode raises a virtual-instruction exception.
RULE 20: When mseccfg.SSEED is 1, seed CSR access conditions from VS or VU mode other than read-write access raise an illegal-instruction exception.
RULE 21: When mseccfg.RLB is 1, locked PMP rules may be removed or modified and locked PMP rules may be edited.
RULE 22: When mseccfg.RLB is 0 and pmpcfg.L is 1 in any rule or entry including disabled entries, mseccfg.RLB remains 0 and any further modifications to mseccfg.RLB are ignored until a PMP reset.
RULE 23: mseccfg.MMWP is a sticky bit that cannot be unset once set until a PMP reset.
RULE 24: When mseccfg.MMWP is set, the default PMP policy for M-mode when accessing memory regions without a matching PMP rule is denied instead of ignored.
RULE 25: mseccfg.MML is a sticky bit that cannot be unset once set until a PMP reset.
RULE 26: When mseccfg.MML is set and pmpcfg.L is set, pmpcfg.L marks a rule as M-mode-only instead of marking the rule as locked and enforced in all modes.
RULE 27: When mseccfg.MML is set and pmpcfg.L is unset, pmpcfg.L marks a rule as S/U-mode-only.
RULE 28: When mseccfg.MML is set, the formerly reserved pmpcfg.RW=01 encoding encodes a Shared-Region.
RULE 29: When mseccfg.MML is set, the pmpcfg.LRWX=1111 encoding encodes a Shared-Region.

RULE 39: When mseccfg.MML is set and a Shared-Region rule has pmpcfg.L set and pmpcfg.X is set, M-mode also has read access on the region.
RULE 40: When mseccfg.MML is set and a Shared-Region rule has pmpcfg.L set, the rule remains locked so that further modifications to its associated configuration or address registers are ignored until a PMP reset unless mseccfg.RLB is set.

REGISTER: mstatus
RULE 1: If the TW (Timeout Wait) bit in mstatus is set, WRS.NTO is executed in any privilege mode other than M mode, and WRS.NTO does not complete within an implementation-specific bounded time limit, then WRS.NTO will cause an illegal-instruction exception.
RULE 2: If WRS.NTO is executed in VS mode, the VTW bit in hstatus is set, the TW (Timeout Wait) bit in mstatus is clear, and WRS.NTO does not complete within an implementation-specific bounded time limit, then WRS.NTO will cause a virtual-instruction exception.
RULE 3: If WRS.NTO is executed in VU mode, the VTW bit in hstatus is set, the TW (Timeout Wait) bit in mstatus is clear, and WRS.NTO does not complete within an implementation-specific bounded time limit, then WRS.NTO will cause a virtual-instruction exception.
RULE 4: For a CMO instruction, like a load or store instruction, the CMO instruction may or may not be permitted to access a cache block based on the states of the MPRV, MPV, and MPP bits in mstatus and the SUM and MXR bits in mstatus, sstatus, and vsstatus.
RULE 5: In the standard privileged architecture, the mstatus field FS is hardwired to 0 if the Zfinx extension is implemented.
RULE 6: In the standard privileged architecture, if the Zfinx extension is implemented, the mstatus field FS no longer affects the trapping behavior of floating-point instructions.
RULE 7: In the standard privileged architecture, if the Zfinx extension is implemented, the mstatus field FS no longer affects the trapping behavior of fcsr accesses.
RULE 8: The vector context status field VS is added to mstatus bits [10:9].
RULE 9: The mstatus.VS field is shadowed in sstatus bits [10:9].
RULE 10: An attempt to execute any vector instruction raises an illegal-instruction exception when mstatus.VS is set to Off.
RULE 11: An attempt to access the vector CSRs raises an illegal-instruction exception when mstatus.VS is set to Off.
RULE 12: When mstatus.VS is set to Initial, executing any instruction that changes vector state, including the vector CSRs, will change mstatus.VS to Dirty.
RULE 13: When mstatus.VS is set to Clean, executing any instruction that changes vector state, including the vector CSRs, will change mstatus.VS to Dirty.

RULE 1: satp has privilege SRW.
RULE 2: All S-mode instruction fetches implicitly read the satp CSR.
RULE 3: Unless otherwise specified, the value returned by an implicit read of the satp CSR is the same value that would have been returned by an explicit read of the satp CSR using a CSR-access instruction in a sufficient privilege mode.
RULE 4: If satp.MODE is read-only 0, SUM is read-only 0.
RULE 5: When the TVM bit is 1, an attempt to read the satp CSR while executing in S-mode will raisean illegal-instruction exception.
RULE 6: When the TVM bit is 1, an attempt to write the satp CSR while executing in S-mode will raise an illegal-instruction exception.
RULE 7: When the TVM bit is 0, an attempt to read the satp CSR while executing in S-mode is permitted.
RULE 8: When the TVM bit is 0, an attempt to write the satp CSR while executing in S-mode is permitted.
RULE 9: When satp.MODE is read-only zero, satp.MODE is always Bare.
RULE 10: The PBMTE bit controls whether the Svpbmt extension is available for use with page tables pointed to by satp.
RULE 11: When PBMTE=1, the Svpbmt extension is available for use with page tables pointed to by satp.
RULE 12: When PBMTE=0, the implementation behaves as though the Svpbmt extension were not implemented for page tables pointed to by satp.
RULE 13: If satp.MODE is read-only 0, SUM is read-only 0.
RULE 14: When satp.MODE is read-only zero, satp.MODE is always Bare.
RULE 15: The satp CSR is an SXLEN-bit read/write register.
RULE 16: The satp PPN field holds the physical page number of the root page table, which is the root page table's supervisor physical address divided by 4 KiB.
RULE 17: When SXLEN=64, satp MODE is a WARL field occupying bits 63-60.
RULE 18: When SXLEN=64, satp ASID is a WARL field occupying bits 59-44.
RULE 19: When SXLEN=64, satp PPN is a WARL field occupying bits 43-0.
RULE 20: When satp MODE is Bare, supervisor virtual addresses are equal to supervisor physical addresses.
RULE 21: When satp MODE is Bare, there is no additional memory protection beyond the physical memory protection scheme.
RULE 22: To select satp MODE=Bare when SXLEN=64, software must write zero to satp bits 59-0.
RULE 23: Attempting to select satp MODE=Bare with a nonzero pattern in the satp fields other than MODE has an UNSPECIFIED effect on the values those fields assume and an UNSPECIFIED effect on address translation and protection behavior.
RULE 24: When SXLEN=64, all satp encodings corresponding to MODE=Bare are reserved for future standard use.
RULE 25: When SXLEN=64, satp MODE value 0 is Bare and means no translation or protection.
RULE 26: When SXLEN=64, satp MODE values 1 through 7 are reserved for standard use.
RULE 27: When SXLEN=64, satp MODE value 8 is Sv39 and selects page-based 39-bit virtual addressing.
RULE 28: When SXLEN=64, satp MODE value 9 is Sv48 and selects page-based 48-bit virtual addressing.
RULE 29: When SXLEN=64, satp MODE value 10 is Sv57 and selects page-based 57-bit virtual addressing.
RULE 30: When SXLEN=64, satp MODE value 11 is Sv64 and is reserved for page-based 64-bit virtual addressing.
RULE 31: When SXLEN=64, satp MODE values 12 and 13 are reserved for standard use.
RULE 32: When SXLEN=64, satp MODE values 14 and 15 are designated for custom use.

RULE 34: The number of ASID bits in satp is UNSPECIFIED and may be zero.
RULE 35: The number of implemented ASID bits, termed ASIDLEN, may be determined by writing one to every bit position in the satp ASID field and then reading back the value in satp to see which ASID bit positions hold a one.
