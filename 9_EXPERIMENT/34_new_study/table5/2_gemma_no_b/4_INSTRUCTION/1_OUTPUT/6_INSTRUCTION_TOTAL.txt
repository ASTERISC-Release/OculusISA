INSTRUCTION: CSRRWI
FORMAT: -
RULE 1: If the CSRRWI instruction is executed, the specified CSR must be updated to the immediate value and the original value must be written to the destination register in a single atomic operation.
RULE 2: The CSRRWI instruction updates the specified CSR using an XLEN-bit value created by zero-extending the 5-bit unsigned immediate value encoded in the rs1 field.
RULE 3: The CSRRWI instruction reads the old value of the CSR, zero-extends it to XLEN bits, and writes it to integer register rd.
RULE 4: If the destination register rd is x0, the CSRRWI instruction shall not read the CSR and shall not cause any side effects that might occur on a CSR read.
RULE 5: If the destination register rd is x0, the CSRRWI instruction does not read the CSR.
RULE 6: The CSRRWI instruction always writes to the specified CSR.
RULE 7: If a CSRRWI instruction writes to a CSR, then all fields within that CSR defined to have side effects must trigger their respective architectural side effects.
RULE 8: If the rd field in the CSRRWI opcode is set to a register r other than x0, then r is the destination register and its value is updated.

INSTRUCTION: FCVT.W.D
FORMAT: -
RULE 1: FCVT.W.D converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 2: For RV64, FCVT.W.D sign-extends the 32-bit result.
RULE 3: FCVT.W.D rounds the result according to the rm field.
RULE 4: If the input to FCVT.W.D is outside the valid range for FCVT.int.S, then the destination register must contain the same result as if FCVT.int.S were executed with that input.
RULE 5: If the input operand for FCVT.W.D is an invalid input as defined for FCVT.int.S, then the destination register shall contain the same result as FCVT.int.S for that same invalid input.

INSTRUCTION: SFENCE.VMA
FORMAT: -
RULE 1: Executing an SFENCE.VMA instruction in S-mode while TVM=1 must raise an illegal-instruction exception.
RULE 2: If an SFENCE.VMA instruction is executed in S-mode while TVM=0, it shall complete without raising an exception.
RULE 3: If the value held in rs1 is not a valid virtual address, the SFENCE.VMA instruction has no effect and no exception is raised.
RULE 4: An attempt to execute the SFENCE.VMA instruction in U-mode always raises an illegal-instruction exception.
RULE 5: An attempt to execute the SFENCE.VMA instruction in VS-mode while VTVM=1 MUST raise a virtual-instruction exception.
RULE 6: Attempts to execute an SFENCE.VMA instruction in VU-mode must raise a virtual-instruction exception with code 22.
RULE 7: Attempts to execute an SFENCE.VMA instruction in VS-mode while hstatus.VTVM=1 must raise a virtual-instruction exception with code 22.

INSTRUCTION: VLE32FF.V
FORMAT: -
RULE 1: If the VLE32FF.V instruction raises a synchronous exception on element 0, the vector length vl must not be modified and the trap must be taken.
RULE 2: If the VLE32FF.V instruction raises a synchronous exception on an element greater than 0, the trap must not be taken and the vector length vl must be reduced to the index of the element that would have raised the exception.
RULE 3: If vstart = 0 and vl > 0, the VLE32FF.V instruction must process at least one element.
RULE 4: When the VLE32FF.V instruction takes a trap due to an interrupt, implementations should not reduce vl and should instead set a vstart value.
RULE 5: When the VLE32FF.V instruction would trigger a debug data-watchpoint trap on an element after the first, implementations should not reduce vl and should instead trigger the debug trap.
