INSTRUCTION: CSRRWI
RULE 1: The CSRRWI instruction atomically reads, modifies, and writes a single CSR specified by the 12-bit csr field.
RULE 2: The CSRRWI instruction updates the specified CSR using an XLEN-bit value created by zero-extending the 5-bit unsigned immediate value encoded in the rs1 field.
RULE 3: The CSRRWI instruction reads the old value of the CSR, zero-extends it to XLEN bits, and writes it to integer register rd.
RULE 4: If the destination register rd is x0, the CSRRWI instruction shall not read the CSR and shall not cause any side effects that might occur on a CSR read.
RULE 5: If the destination register rd is not x0, the CSRRWI instruction reads the CSR.
RULE 6: The CSRRWI instruction always writes to the specified CSR.
RULE 7: The CSRRWI instruction triggers action side effects for all fields within the written CSR that are defined to have side effects when written.
RULE 8: A register r other than x0 is a source register for CSRRWI if the csr field in the CSRRWI opcode is set to r and the rd field is not set to x0.
RULE 9: A register r other than x0 is a source register for CSRRWI if r is a CSR and an implicit source register for CSRRWI.
RULE 10: A register r other than x0 is a source register for CSRRWI if r is a CSR that aliases with another source register for CSRRWI.
RULE 11: A register r other than x0 is a destination register for CSRRWI if the rd field in the CSRRWI opcode is set to r.
RULE 12: A register r other than x0 is a destination register for CSRRWI if the csr field in the CSRRWI opcode is set to r.
RULE 13: A register r other than x0 is a destination register for CSRRWI if r is a CSR and an implicit destination register for CSRRWI.
RULE 14: A register r other than x0 is a destination register for CSRRWI if r is a CSR that aliases with another destination register for CSRRWI.

INSTRUCTION: FCVT.W.D
RULE 1: FCVT.W.D converts a double-precision floating-point number in floating-point register rs1 to a signed 32-bit integer in integer register rd.
RULE 2: For RV64, FCVT.W.D sign-extends the 32-bit result.
RULE 3: FCVT.W.D rounds the result according to the rm field.
RULE 4: The range of valid inputs for FCVT.W.D is the same as for FCVT.int.S.
RULE 5: The behavior for invalid inputs for FCVT.W.D is the same as for FCVT.int.S.

INSTRUCTION: SFENCE.VMA
RULE 1: The SFENCE.VMA instruction orders stores.
RULE 2: The SFENCE.VMA instruction does not order invalidate, clean, and flush operations resulting from cache-block management instructions.
RULE 3: If supervisor-level memory management data structures such as page tables remain in use across a change to SBE, M-mode software must execute an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 following that change to SBE.
RULE 4: Executing an SFENCE.VMA instruction in S-mode while TVM=1 must raise an illegal-instruction exception.
RULE 5: Executing an SFENCE.VMA instruction in S-mode while TVM=0 is permitted.
RULE 6: Executing an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 after changing menvcfg.PBMTE suffices to synchronize address-translation caches with respect to the altered interpretation of page-table entries' PBMT fields.
RULE 7: Executing an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 after changing menvcfg.ADUE suffices to synchronize address-translation caches with respect to the altered interpretation of page-table entries' A/D bits.
RULE 8: M-mode software MUST execute an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0 after PMP CSRs are written to synchronize PMP settings with the virtual memory system and any PMP or address-translation caches.
RULE 9: The SFENCE.VMA instruction must be used to ensure that updates to the address-translation data structures are observed by subsequent implicit reads to those structures by a hart.
RULE 10: Translations that began while satp was active are not required to complete or terminate when satp is no longer active, unless an SFENCE.VMA instruction matching the address and ASID is executed.
RULE 11: The SFENCE.VMA instruction synchronizes updates to in-memory memory-management data structures with current execution and invalidates entries in the address-translation cache associated with a hart.
RULE 12: If rs1 = x0 and rs2 = x0, the SFENCE.VMA instruction orders all reads and writes made to any level of the page tables for all address spaces.
RULE 13: If rs1 = x0 and rs2 = x0, the SFENCE.VMA instruction invalidates all address-translation cache entries for all address spaces.
RULE 14: If rs1 = x0 and rs2 != x0, the SFENCE.VMA instruction orders all reads and writes made to any level of the page tables only for the address space identified by integer register rs2, excluding accesses to global mappings.
RULE 15: If rs1 = x0 and rs2 != x0, the SFENCE.VMA instruction invalidates all address-translation cache entries matching the address space identified by integer register rs2, except for entries containing global mappings.
RULE 16: If rs1 != x0 and rs2 = x0, the SFENCE.VMA instruction orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 17: If rs1 != x0 and rs2 = x0, the SFENCE.VMA instruction invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 for all address spaces.
RULE 18: If rs1 != x0 and rs2 != x0, the SFENCE.VMA instruction orders only reads and writes made to leaf page table entries corresponding to the virtual address in rs1 for the address space identified by integer register rs2, excluding accesses to global mappings.
RULE 19: If rs1 != x0 and rs2 != x0, the SFENCE.VMA instruction invalidates all address-translation cache entries that contain leaf page table entries corresponding to the virtual address in rs1 and match the address space identified by integer register rs2, except for entries containing global mappings.
RULE 20: If the value held in rs1 is not a valid virtual address, the SFENCE.VMA instruction has no effect and no exception is raised.
RULE 21: When rs2 != x0, bits SXLEN-1:ASIDMAX of the value held in rs2 are reserved for future standard use and are ignored by current implementations of the SFENCE.VMA instruction.
RULE 22: When rs2 != x0 and ASIDLEN < ASIDMAX, the implementation shall ignore bits ASIDMAX-1:ASIDLEN of the value held in rs2 during the execution of the SFENCE.VMA instruction.
RULE 23: For implementations that make satp.MODE read-only zero (always Bare), attempts to execute an SFENCE.VMA instruction might raise an illegal-instruction exception.
RULE 24: Global mappings need not be flushed from local address-translation caches when an SFENCE.VMA instruction is executed with rs2 not equal to x0.
RULE 25: An SFENCE.VMA instruction must be executed after writes to memory-management tables to ensure that implicit reads observe writes to the same memory locations by flushing the relevant cached translations.
RULE 26: If a page is upgraded to a superpage without first clearing the original non-leaf PTE's valid bit and executing an SFENCE.VMA with rs1=x0, the use of the old non-leaf PTE or the new leaf PTE for subsequent implicit reads is unpredictable, though the behavior is otherwise well defined.
RULE 27: An SFENCE.VMA instruction with rs1 = x0 covers all 4 KiB regions within a range.
RULE 28: Multiple SFENCE.VMA instructions with rs1 != x0 may be used to cover all 4 KiB regions within a range.
RULE 29: If SFENCE.VMA is used incorrectly or inconsistencies exist, one of the translations will be chosen in an unpredictable manner.
RULE 30: An attempt to execute the SFENCE.VMA instruction in U-mode always raises an illegal-instruction exception.
RULE 31: An attempt to execute the SFENCE.VMA instruction in VS-mode while VTVM=1 MUST raise a virtual-instruction exception.
RULE 32: The SFENCE.VMA instruction applies only to the memory-management data structures controlled by the HS-level satp when the V bit is 0.
RULE 33: The SFENCE.VMA instruction applies only to the memory-management data structures controlled by the vsatp when the V bit is 1.
RULE 34: When the virtualization mode V is 0, the SFENCE.VMA instruction treats the virtual-address argument as an HS-level virtual address and the ASID argument as an HS-level ASID.
RULE 35: When the virtualization mode V is 0, the SFENCE.VMA instruction orders stores to HS-level address-translation structures with subsequent HS-level address translations.
RULE 36: When the virtualization mode V is 1, the SFENCE.VMA instruction treats the virtual-address argument as a guest virtual address within the current virtual machine and the ASID argument as a VS-level ASID within the current virtual machine.
RULE 37: When the virtualization mode V is 1, the SFENCE.VMA instruction considers the effective ASID to be the combination of the VS-level ASID and the VMID field of CSR hgatp.
RULE 38: When the virtualization mode V is 1, the SFENCE.VMA instruction orders stores to VS-level address-translation structures with subsequent VS-stage address translations for the same virtual machine, provided hgatp.VMID remains the same as when the SFENCE.VMA executed.
RULE 39: To synchronize PMP settings with the virtual memory system for HS-level address translation after PMP CSRs are written, M-mode software must execute an SFENCE.VMA instruction with rs1 = x0 and rs2 = x0.
RULE 40: Attempts to execute an SFENCE.VMA instruction in VU-mode must raise a virtual-instruction exception with code 22.
RULE 41: Attempts to execute an SFENCE.VMA instruction in VS-mode while hstatus.VTVM=1 must raise a virtual-instruction exception with code 22.
RULE 42: Address-translation caches do not need to be synchronized with the SFENCE.VMA instruction when changes are made to xSSE.
RULE 43: Pointer masking must not be applied to the address provided to the SFENCE.VMA instruction.

INSTRUCTION: VLE32FF.V
RULE 1: If the VLE32FF.V instruction raises a synchronous exception on element 0, the vector length vl must not be modified and the trap must be taken.
RULE 2: If the VLE32FF.V instruction raises a synchronous exception on an element greater than 0, the trap must not be taken and the vector length vl must be reduced to the index of the element that would have raised the exception.
RULE 3: The VLE32FF.V instruction may update active destination elements past the element that causes trimming of the vector length, provided these updates do not exceed the original vector length.
RULE 4: Even when no exception is raised, implementations of the VLE32FF.V instruction are permitted to process fewer than vl elements and reduce vl accordingly.
RULE 5: If vstart = 0 and vl > 0, the VLE32FF.V instruction must process at least one element.
RULE 6: When the VLE32FF.V instruction takes a trap due to an interrupt, implementations should not reduce vl and should instead set a vstart value.
RULE 7: When the VLE32FF.V instruction would trigger a debug data-watchpoint trap on an element after the first, implementations should not reduce vl and should instead trigger the debug trap.
