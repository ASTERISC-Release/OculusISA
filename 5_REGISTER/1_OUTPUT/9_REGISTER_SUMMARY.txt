REGISTER: cycle
SUMMARY: The cycle CSR (address 0xC00) is an unprivileged read‑only shadow of the machine‑mode mcycle register that returns the current processor cycle count, with the RDCYCLE pseudoinstruction delivering the full XLEN‑wide value on XLEN ≥ 64 systems. The counter increments each CPU cycle unless inhibited by the CY bit in mcountinhibit or by the appropriate INH bits in mcyclecfg, and it continues counting irrespective of mcounteren settings. Reads are always permitted in M‑mode; in S‑ and U‑mode they are allowed only when the CY field of mcounteren (and, for U‑mode, also scounteren) is set, otherwise an illegal‑instruction exception is raised. A 64‑bit wrap generates exception code 13, and any write to the cycle CSR must be ignored and must not alter its value.

REGISTER: fcsr
SUMMARY: The fcsr is a per‑hart control‑status register that combines the floating‑point rounding‑mode field (frm) and the accrued‑exception‑flags field (fflags) used by floating‑point instructions. Both sub‑fields are readable and writable from any privilege level (URW), are invisible to other harts, and accesses never generate a trap regardless of which extensions are implemented. The rounding‑mode field supplies the dynamic rounding mode for operations that request it, while the flag field records any floating‑point exceptions that have occurred since software last cleared them; these flags do not cause traps. Modifications to the FS state do not affect the stored fcsr contents, and reserved bits are ignored or read as zero.

REGISTER: fflags
SUMMARY: The fflags CSR records the five accrued floating‑point exception flags (Invalid, Divide‑by‑Zero, Overflow, Underflow, Inexact) that are set by any FP arithmetic instruction that encounters the corresponding condition and remain set until software clears them. It is part of the fcsr register but can be accessed directly with unprivileged read/write permissions, and reads or writes in any privilege mode generate no trap. The FRFLAGS instruction copies the current flag bits into an integer register, while FSFLAGS can read the flags and write a new value using the low bits of a source register, with writes updating only the five flag bits. Flag writes never cause traps, and writes larger than five bits are masked to the flag field; changing the FS field or disabling FP does not alter the stored flags.

REGISTER: frm
SUMMARY: The frm register holds the current dynamic floating‑point rounding mode as a 3‑bit field that selects RNE, RTZ, RDN, RUP, or RMM, with encodings 101‑111 causing an illegal‑instruction exception when interpreted as a rounding mode. It is accessed through the fcsr CSR (bits 7‑5) and by the FRRM and FSRM instructions, which transfer the 3‑bit value between integer registers and frm. The register is user‑read/write (URW) and can be read or written without exception in U‑, S‑, or M‑mode, even when the F, V, or related extensions are enabled. Writes are masked to the low three bits, so writing larger values does not set illegal patterns in the stored field.

REGISTER: hcounteren
SUMMARY: The hcounteren CSR (0x606) is the hypervisor counter‑enable register that controls which hardware performance counters (HPM3‑HPM18) and the cycle, timer, and instruction‑retired counters are exposed to HS‑mode. It is readable and writable in hypervisor (H) privilege and HS‑mode, and M‑mode may also access it without fault, while any access from U‑mode raises an illegal‑instruction exception. All bits written are reflected on subsequent reads, and the register remains accessible even when the H extension is active.

REGISTER: hedeleg
SUMMARY: The hedeleg CSR is a 64‑bit hypervisor‑read/write register that controls which traps are delegated from HS‑mode to lower privilege levels and is only visible in M‑ and HS‑mode. It contains a set of writable delegation fields (e.g., instruction‑, supervisor‑ and user‑level interrupt and exception enable bits) while all other bits are hard‑wired read‑only zero. Accesses from M‑ or HS‑mode succeed without exception, but any access from U‑mode or an attempt to use the XLEN‑64 alias when XLEN = 64 raises an illegal‑instruction exception (mcause = 2). Writes affect only the defined writable bits; writing an all‑ones value never results in the full 0xffffffff or 0xffffffffffffffff pattern.

REGISTER: henvcfg
SUMMARY: The henvcfg CSR configures hypervisor environment features, grouping cache‑control bits (CBIE, CBCFE, CBZE), memory‑management controls (PBMTE, ADUE, STCE, SSE) and pointer‑masking (PMM) together with a FIOM bit that mirrors menvcfg.FIOM. Access to henvcfg, henvcfgh, and senvcfg is permitted only in M‑mode and only when the ENVCFG bit in mstateen0 is set; any U‑ or S‑mode access causes an illegal‑instruction exception (mcause = 2). Fields are read‑only zero when the corresponding extensions or menvcfg bits are absent (e.g., PBMTE, ADUE, STCE, SSE, PMM) and writes to the cache‑control bits affect only henvcfg and not menvcfg or senvcfg. Cache‑maintenance instructions raise illegal‑instruction exceptions unless they are HS‑qualified and the appropriate henvcfg enable bits are set, and attempts to write read‑only bits such as STCE or PBMTE are ignored on read‑back.

REGISTER: hgatp
SUMMARY: The hgatp register provides the HS‑mode guest address‑translation and protection settings. It is writable only in HS‑mode and inaccessible to lower privilege levels. When the TVM bit in mstatus is set to 1, HS‑mode must not execute the HINVAL.GVMA instruction. This restriction governs the use of hgatp‑related translation invalidation.

REGISTER: hgeie
SUMMARY: The hgeie CSR (address 0x607) supplies per‑guest enable control for external interrupts and HSXLEN configuration in the hypervisor extension. Its GUEST_EXTERNAL_INTERRUPTS and HSXLEN bits are writable (subject to the GEILEN mask) and read back unchanged, while writes to undefined high‑order bits are ignored, preventing the register from assuming all‑ones values. Access to hgeie is permitted without exception in machine (M) and supervisor (HS) modes but causes an illegal‑instruction trap in user (U) mode. The read‑only hip.SGEIP flag is set when the bitwise AND of hgeip and hgeie is non‑zero, indicating a pending enabled guest external interrupt.

REGISTER: hgeip
SUMMARY: hgeip is an HSXLEN‑wide read‑only register defined by the hypervisor extension; when GEILEN is nonzero only bits 1…GEILEN contain meaningful data and all other bits read as zero. It can be accessed without trap in machine and supervisor (HS) privilege, but generates an illegal‑instruction exception in user mode. Although otherwise read‑only, the least‑significant WPRI bit may be set and read back in M‑mode, while writes of any other value are ignored and do not alter the register contents. Access is permitted when the H extension is implemented and active.

REGISTER: hideleg
SUMMARY: The hideleg CSR is an HSXLEN‑bit register provided to HS‑mode that controls which interrupts are delegated to HS‑mode instead of trapping to M‑mode. Its interrupt fields are WARL; a cleared bit causes the corresponding interrupt to trap to HS‑mode, while bits are read‑only zero when the matching mideleg bit is zero and bit 13 is hard‑wired zero unless the Shlcofideleg extension is implemented. The register may be read and written in M‑mode and HS‑mode without exception, but any access in U‑mode raises an illegal‑instruction exception; writes to defined writable bits (including WPRI fields) are reflected on readback and writes to undefined bits are masked. Accesses remain exception‑free even when the H or Shlcofideleg extensions are present.

REGISTER: hie
SUMMARY: The hie CSR (address 0x604) is the Hypervisor Interrupt‑Enable register that selects which hypervisor‑mode interrupts may trap when their corresponding pending bits in hip are set. It is HRW: writable bits (including reserved/vendor‑specific fields) read back as written, while non‑writable or delegated bits are hard‑wired zero and are mutually exclusive with the supervisor‑mode enable bits in sie. The register is accessible without fault in M‑mode and HS‑mode (even when H, Shlcofideleg, or Sstc extensions are present) but generates an illegal‑instruction exception in U‑mode. An interrupt becomes eligible only when both its hie and hip bits are 1; clearing the hie bit prevents the pending hip bit from causing a trap.

REGISTER: hip
SUMMARY: The hip CSR holds the set of pending hypervisor‑mode interrupts and is defined with HRW (read/write) access. Writable bits mirror the corresponding hvip bits and include virtual‑supervisor‑software (VSSIP), virtual‑supervisor‑timer (VSTIP), SGEIP and other delegated interrupt‑pending bits, while any bit not delegated (mideleg = 0) or set in sie must read as zero and bits in sip and hip are mutually exclusive. A pending interrupt can be cleared by writing a zero to its writable hip bit; if the bit is read‑only, it must be cleared via the hvip alias or another architectural mechanism, and all non‑writable bits read back as zero. Accesses to hip cause no exception in M‑ or HS‑mode (independent of extensions) but raise an illegal‑instruction exception in U‑mode.

REGISTER: hpmcounter10
SUMMARY: hpmcounter10 is a read‑only shadow of the 64‑bit machine performance‑monitoring counter mhpmcounter10 that reports events selected by the corresponding mhpmevent10 register. Its overflow status (OF) bit, controlled via mhpmevent10, is set on counter wrap‑around and triggers the standard count‑overflow interrupt (LCOFIP/LCOFIE) unless the OF bit is already set; the same mhpmevent10 bits also inhibit counting in specified privilege modes. The CSR is unprivileged‑read‑only (URO) and may be read in M‑mode without exception, while reads in S‑ or U‑mode are permitted only if the HPM10 bits are set in mcounteren (and additionally in scounteren for U‑mode); otherwise an illegal‑instruction exception occurs. Writes to hpmcounter10 have no immediate effect, are delayed until after the instruction completes, and never force the counter to the written value, and a read before any software write returns an implementation‑defined value.

REGISTER: hpmcounter11
SUMMARY: hpmcounter11 is a read‑only shadow of the machine‑mode performance counter mhpmcounter11 that increments on events selected by the mhpmevent11 CSR. Reads are always permitted in M‑mode, permitted in S‑mode only when mcounteren[11] = 1, and permitted in U‑mode only when scounteren[11] = 1 (otherwise an illegal‑instruction exception is raised). Writes to hpmcounter11 are ignored, while overflow is indicated by the OF bit in mhpmevent11, which also governs generation of count‑overflow interrupts. The counter's incrementing can be inhibited by the HPM‑11 bit in mcountinhibit or by INH bits in mhpmevent11 for specific privilege modes.

REGISTER: hpmcounter12
SUMMARY: hpmcounter12 is a read‑only CSR that provides a user‑visible shadow of the machine counter mhpmcounter12, whose increments are driven by events selected in mhpmevent12. An overflow flag (OF) in mhpmevent12 is set only on hardware wrap‑around of hpmcounter12 and, when clear, generates a standard count‑overflow interrupt (local interrupt bit 13) that eventually raises the LCOFIP pending bit. Reads are always permitted in M‑mode; in S‑mode they require the HPM12 bit in mcounteren to be set, and in U‑mode they require both the HPM12 bits in mcounteren and scounteren to be set, otherwise an illegal‑instruction exception is raised. Writes to hpmcounter12 have no effect (they take effect after the instruction completes) and attempting to write a value beyond the counter's maximum does not set the overflow flag.

REGISTER: hpmcounter13
SUMMARY: hpmcounter13 is a machine‑mode CSR that presents a 64‑bit read‑only snapshot (zero‑extended on RV32) of the hardware counter mhpmcounter13, whose increments are driven by the event selected in mhpmevent13 and can be inhibited by mcountinhibit or the event‑selector INH bits. Although defined as MRW, writes to hpmcounter13 have no effect; reads are always legal in M‑mode, but in S‑ or U‑mode they require the Zihpm extension and the corresponding enable bits in mcounteren (and scounteren/hcounteren where applicable), otherwise an illegal‑instruction exception is generated. The counter's overflow sets the OF bit in mhpmevent13 and may raise an overflow‑interrupt pending bit, which must be cleared by software before another overflow can trigger. Any access that violates these privilege or enable conditions raises an illegal‑instruction exception, while accesses with proper permission produce no exception.

REGISTER: hpmcounter14
SUMMARY: hpmcounter14 is a read‑only shadow of the machine‑mode performance counter mhpmcounter14 that reflects the number of hardware events selected by the mhpmevent14 event selector. The OF bit in mhpmevent14 flags overflow and can disable the overflow interrupt, the MINH/SINH/UINH bits can inhibit counting in M‑, S‑/HS‑, or U‑mode, and the HPM14 bit in mcountinhibit controls whether the counter increments normally. Access to the CSR is unprivileged read‑only (URO); it is always permitted in M‑mode, but in S‑ and U‑mode it requires the HPM14 bits to be set in mcounteren (and additionally in scounteren for U‑mode) and to satisfy any menvcfg.CDE or siselect constraints, otherwise an illegal‑instruction exception is raised. Prohibited reads or writes generate an illegal‑instruction exception, writes have no effect, and a hardware overflow produces a standard local overflow interrupt (LCOFIP) and sets the OF bit unless that interrupt is disabled.

REGISTER: hpmcounter15
SUMMARY: hpmcounter15 is the unprivileged read‑only CSR that mirrors the hardware performance counter mhpmcounter15 and increments when events selected by the mhpmevent15 (or mhpmevent15h if the Sscofpmf extension is implemented) occur. It may be written by software, with the write taking effect after the instruction completes, but the write does not directly set the counter value. Read access is unrestricted in M‑mode, while in S‑mode it requires the HPM15 bit in mcounteren to be set, and in U‑mode it requires both the HPM15 bits in mcounteren and scounteren to be set; otherwise an illegal‑instruction exception is raised. An unsigned overflow sets a sticky OF bit that can generate a local count‑overflow interrupt (bit 13) unless the OF bit is already set, and software clears the OF bit to re‑enable overflow interrupt generation.

REGISTER: hpmcounter16
SUMMARY: hpmcounter16 is a 64‑bit read‑only shadow of the mhpmcounter16 hardware performance counter that automatically increments and includes a sticky overflow (OF) flag which can generate a local count‑overflow interrupt. Access is always permitted in M‑mode; in S‑mode it requires the HPM16 bit in mcounteren to be set, and in U‑mode it requires both the HPM16 bits in mcounteren and scounteren to be set, otherwise a read causes an illegal‑instruction exception (writes are ignored or have no effect if the counter is hard‑wired to zero). Writes become visible only after the writing instruction retires, and if a write would exceed the counter's maximum value the register returns the written value without wrapping; the OF bit stays set after overflow until cleared by software, after which interrupt generation can occur again.

REGISTER: hpmcounter17
SUMMARY: hpmcounter17 is a read‑only CSR that mirrors the current value of the machine‑mode performance counter mhpmcounter17, which counts the event programmed in mhpmevent17 (or its legal read‑back encoding) and may be written directly. Access from lower privilege modes is gated by the HPM‑17 bits in mcounteren (and additionally scounteren for U‑mode); when these bits are clear, reads raise an illegal‑instruction exception, while M‑mode accesses are always permitted. The counter increments normally unless the corresponding HPM‑17 bit in mcountinhibit is set, and on overflow it wraps modulo the implemented width, sets an associated OF flag, and—if OF was previously zero—generates a count‑overflow interrupt that can be delegated via mideleg. The OF flag disables further overflow interrupts until cleared by software, and reading the overflow status is subject to the same privilege checks as reading hpmcounter17.

REGISTER: hpmcounter18
SUMMARY: mhpmcounter18 holds the 18th hardware performance‑monitoring count and is writable in M‑mode; hpmcounter18 is a read‑only shadow of it for lower privilege modes, while mhpmevent18 selects the counted event and contains INH bits that inhibit counting in specified privilege levels and an OF overflow flag. Access to hpmcounter18 is permitted in S‑mode only when the HPM18 bits are set in both mcounteren and scounteren, and in U‑mode only when both those bits are set; otherwise an illegal‑instruction exception occurs, and the mcountinhibit register can stop counting but does not affect accessibility. mhpmcounter18 is a WARL CSR that accepts any legal value, with writes taking effect after the writing instruction completes and cannot cause overflow, which is generated solely by hardware increments. On unsigned overflow the OF bit is set, optionally raising a count‑overflow interrupt mapped to bit 13 of the mip/mie/sip/sie registers (LCOFIP/LCOFIE), with delegation to S‑mode controlled by mideleg, and the OF flag remains readable in M‑mode.

REGISTER: hpmcounter3
SUMMARY: hpmcounter3 is a 64‑bit unprivileged hardware performance counter defined by the Zihpm extension, implemented as a read‑only shadow of the machine‑mode counter mhpmcounter3 whose value increments according to the event‑selector CSR mhpmevent3 (a zero value disables counting). Access to the CSR at address 0xC03 is always permitted in M‑mode, in S‑mode only when the HPM3 bit in mcounteren is set, and in U‑mode only when both the HPM3 bits in mcounteren and scounteren are set; any unauthorized read, an indirect CSR reference to a different address, or a write to hpmcounter3 raises an illegal‑instruction exception. The counter increments regardless of enable bits, while the HPM3 bit in mcountinhibit can inhibit counting, and the OF sticky bit signals an unsigned overflow, optionally generating a standard local overflow interrupt (LCOFIP/LCOFIE) unless the OF bit is set. The overflow interrupt can be delegated via mideleg, and the OF bit must be cleared before re‑initialising the counter to allow further overflow interrupts.

REGISTER: hpmcounter4
SUMMARY: hpmcounter4 is a read‑only shadow CSR that mirrors the mutable mhpmcounter4 hardware performance counter. Its companion mhpmevent4 CSR holds an overflow (OF) status/interrupt‑disable flag and per‑mode inhibit bits (MINH, SINH, UINH) that prevent counting in M, S/HS, or U privilege when set. Writes to hpmcounter4 cause an illegal‑instruction exception and leave the value unchanged; reads are always permitted in M‑mode but in S‑ or U‑mode require the corresponding enable bits in mcounteren and scounteren, otherwise an illegal‑instruction exception is raised. On a hardware increment that causes unsigned overflow, an overflow interrupt is generated (subject to the OF bit and mie/mip delegation) and the OF bit is set, after which the counter and OF bit must be cleared before another overflow interrupt can occur.

REGISTER: hpmcounter5
SUMMARY: hpmcounter5 is a read‑only CSR that mirrors the 64‑bit mhpmcounter5 hardware counter, whose incrementing events are selected by mhpmevent5 (including the high‑half selector when the Sscofpmf extension is present). Counting can be globally inhibited by the HPM5 bit in mcountinhibit and selectively inhibited per privilege mode by the MINH, SINH, and UINH bits in mhpmevent5, while the OF bit records overflow status. Access to hpmcounter5 is unrestricted in M‑mode, but in S‑mode it requires the HPM5 bit set in mcounteren, and in U‑mode it requires both the HPM5 bits set in mcounteren and scounteren; otherwise an illegal‑instruction exception is raised, and writes to the CSR have no effect. When the counter overflows and OF is clear, a count‑overflow interrupt is generated (bit 13 of mip/mie, with LCOFIP/LCOFIE flags), and the OF bit is set; clearing OF and reinitializing the counter is required to enable further overflow interrupts.

REGISTER: hpmcounter6
SUMMARY: hpmcounter6 is a 64‑bit hardware performance‑monitor counter whose increment source is programmed by the WARL mhpmevent6 CSR. It increments on the selected event unless the HPM6 bit in mcountinhibit or any privilege‑mode INH bit for counter 6 is set; on overflow it wraps modulo 2ᴺ and sets the OF flag. Reads and writes are unrestricted in M‑mode, in S‑mode a read is permitted only when mcounteren bit 6 is set (otherwise an illegal‑instruction exception occurs), and in U‑mode a read is allowed only when both scounteren HPM6 and mcounteren HPM6 bits are set, otherwise it returns zero or raises an illegal‑instruction exception. When the OF flag is cleared and the counter wraps, a count‑overflow interrupt is raised as local interrupt bit 13 (LCOF), controllable via the standard mip/mie bits and delegable by mideleg, and the OF flag remains set until cleared by software.

REGISTER: hpmcounter7
SUMMARY: hpmcounter7 is a 64‑bit unprivileged read‑only CSR that mirrors the machine‑mode performance counter mhpmcounter7 and increments according to the event selected in the associated mhpmevent7 register. Access to hpmcounter7 is unrestricted in M‑mode, but in S‑ and U‑mode it is permitted only when the HPM7 enable bits are set in the relevant enable CSRs (mcounteren for S‑mode, both scounteren and mcounteren for U‑mode); otherwise a read triggers an illegal‑instruction exception, though the counter continues to count. Incrementing can be globally inhibited by the HPM7 bit in mcountinhibit and further filtered by the MINH, SINH, and UINH inhibit bits in mhpmevent7, while overflow sets the OF bit and may raise a count‑overflow interrupt whose delegation is controlled by mideleg. Software may clear the OF bit and reinitialize the counter to generate further overflow interrupts, but writes to hpmcounter7 have no effect because it is read‑only.

REGISTER: hpmcounter8
SUMMARY: hpmcounter8 is a hardware performance‑monitor counter that increments on the event selected in mhpmevent8, unless the HPM8 bit in mcountinhibit disables counting. When the unsigned counter wraps, the OF flag in mhpmevent8 is set and, if the flag was previously clear, a count‑overflow interrupt is generated, reflected in the LCOFIP pending bit and controlled by the LCOFIE enable bits and possible delegation via mideleg. The register is architecturally URO: M‑mode may read and write it without exception, S‑mode reads are permitted only when the HPM8 bits in both mcounteren and scounteren are set (otherwise an illegal‑instruction exception occurs), and U‑mode reads are allowed only when the HPM8 bits in scounteren and mcounteren are set. A CSR write to hpmcounter8 takes effect after the writing instruction completes, and after an overflow the counter and its OF flag must be cleared before another overflow interrupt can be generated.

REGISTER: hpmcounter9
SUMMARY: hpmcounter9 is a read‑only CSR that mirrors the machine‑mode performance counter mhpmcounter9, which increments when the HPM9 bit in mcountinhibit is clear and continues to count regardless of accessibility. In M‑mode the register is always readable without exception; in S‑mode it is readable only if the HPM9 bit in mcounteren is set, and in U‑mode it is readable only if both the HPM9 bits in mcounteren and scounteren are set, otherwise an illegal‑instruction exception occurs. Writes to hpmcounter9 have no effect and do not raise exceptions, and an implementation may treat it as a constant‑zero register. Overflow of the counter sets the OF flag and can generate a count‑overflow interrupt (delegated by mideleg), and the overflow flag is readable under the same access controls that govern the counter itself.

REGISTER: hstateen0
SUMMARY: The hstateen0 CSR governs whether a hypervisor can enable access to the corresponding supervisor‑state enable CSR (sstateen0) and related groups such as environment‑configuration, counter, JVT, FCSR, and custom state fields. Each bit is read‑only zero unless the matching bit in mstateen0 is a read‑only one, and the register's own bit 63 is the only writable bit (which never reads back as set); bit 63 of mstateen0 also controls overall access to hstateen0. Access to hstateen0 is permitted only in machine mode—reads in M‑mode never trap, while any attempt from S‑ or U‑mode raises an illegal‑instruction exception. Writes to any hstateen0 bits have no observable effect (readback yields zero) and machine‑level software must clear hstateen0 whenever it writes non‑zero to writable mstateen0 bits.

REGISTER: hstateen1
SUMMARY: The hstateen1 CSR (address 0x60E) enables hypervisor‑level state saving/restoring and mirrors the machine‑level enable bits in mstateen1, with any bit cleared in mstateen1 appearing as a read‑only‑zero in hstateen1 and any read‑only‑one requiring the same in mstateen1. All writable bits are hardware‑initialized to zero after reset; bit 63 (SE0) is the only always‑writable field but its value does not persist on readback. Access is permitted only in machine or hypervisor privilege modes; attempts from supervisor or user mode raise an illegal‑instruction exception (mcause = 2). Machine‑mode software must keep corresponding writable bits of hstateen1 cleared when setting non‑zero bits in mstateen1, ensuring consistency between the two CSRs.

REGISTER: hstateen2
SUMMARY: hstateen2 is a hypervisor‑mode read/write CSR that enables or disables lower‑privilege access to the architectural state of optional extensions. Each bit gates the corresponding extension state, with bit 63 additionally controlling visibility of sstateen2, and any bit tied to unimplemented, reserved, or masked‑off (by mstateen2) state is hard‑wired to zero (read‑only). Writable bits are cleared on reset, writes are only permitted in M‑mode (no exception) while attempts from S‑ or U‑mode raise an illegal‑instruction trap, and bit 63, though writable, does not affect the read‑back value. A read‑only one in hstateen2 requires the same bit to be read‑only one in mstateen2.

REGISTER: hstateen3
SUMMARY: The hstateen3 CSR enables hypervisor control over the subset of machine‑state bits that are implemented, mirroring the corresponding mstateen3 bits and forcing any unimplemented or disabled bits to read‑only zero. It is accessed only with hypervisor‑read/write privilege; in M‑mode accesses succeed, while attempts in S‑ or U‑mode raise an illegal‑instruction exception. Bit 63 acts as the enable for the matching sstateen3 CSR, is always writable, and its value is not retained on readback. On reset all writable bits are cleared, and writes of all‑ones or of the SE0 bit are masked so that the register never reads back those values.

REGISTER: hstatus
SUMMARY: The hstatus CSR provides hypervisor‑mode status and control for HS‑mode, exposing fields that govern virtualization mode, trap handling, and hypervisor instruction enablement. It includes the V field (virtualization enable) together with SPV/SPVP/GVA bits written by hardware on HS‑mode traps, the HU bit that permits HLV/HLVX/HSV and other hypervisor instructions in U‑mode, VTVM that suppresses SFENCE traps, a WLRL VGEIN field selecting the guest‑external‑interrupt bit, a WARL VSXL field matching MXL, and assorted read‑only or implementation‑defined bits (e.g., HUPMM, VSBE). The register is readable and writable with HRW privilege in M‑ and HS‑mode, but any access from U‑mode generates an illegal‑instruction exception; writes to read‑only or ignored fields have no effect. On entry to HS‑mode traps the V bit is cleared, SPV is set to zero unless overridden, GVA is set according to the trap type, and subsequent SRET uses SPV and sstatus.SPP to determine the return privilege before clearing SPV.

REGISTER: htimedelta
SUMMARY: The htimedelta CSR is a hypervisor‑read/write register that holds a single 64‑bit time‑delta field and is required whenever the time CSR is implemented (no high‑half alias exists for XLEN=64). It is accessible without exception in machine mode and in supervisor (hypervisor) mode, even when the H or Sstc extensions are active. Any access from user mode generates an illegal‑instruction exception.

REGISTER: hvien
SUMMARY: The hvien CSR (address 0x608) is a machine‑mode register that controls hypervisor‑related interrupt enable bits. It contains writable fields such as WPRI and LCOFI that are reflected on readback, while all other bits are reserved and writes to them are masked (e.g., a full‑ones write does not set the register to all ones). Access is allowed only in M‑mode; attempts from S‑ or U‑mode raise an illegal‑instruction exception (mcause = 0x2), whereas M‑mode accesses never trap (mcause = 0x0). The register can be accessed without exception regardless of whether the H, Smaia, or Ssaia extensions are active.

REGISTER: hvip
SUMMARY: The hvip CSR holds the virtual pending bits for supervisor external, timer, and software interrupts (VSEIP, VSTIP, VSSIP) and, when the H extension is present together with Smcdeleg/Ssccfg, Sscofpmf, Smaia or Ssaia, also implements a writable LCOFI field. It is a readable‑writable (HRW) register that can be accessed without fault in machine mode and in HS‑mode, while any access from user mode raises an illegal‑instruction exception. Access never traps when the H extension or any of the listed security extensions (Smaia, Smcdeleg, Ssaia, Ssccfg, Sscofpmf, Sstc) are active. Writes to any defined field are reflected on subsequent reads, and writes to undefined high bits are masked rather than producing erroneous values.

REGISTER: instret
SUMMARY: The INSTRET CSR (0xc02) is a 64‑bit read‑only counter that reflects the number of instructions retired by the hart, with the full value read by RDINSTRET (or CSRRC/CSRRSI/CSRRCI) and the upper 32 bits optionally via INSTRETH. It is a URO‑privileged shadow of the machine‑mode minstret counter; reads are always permitted in M‑mode, while in S‑ or U‑mode they require the IR bit in mcounteren (and additionally scounteren for U‑mode) to be set, otherwise an illegal‑instruction exception is raised. The counter increments only for instructions that successfully retire in a non‑inhibited mode and does not increment for synchronous exceptions, xRET faults, or when counting is disabled by minstretcfg or mcountinhibit settings. Writes to INSTRET are ignored (the explicit write does not alter the counter) and no access‑related exceptions occur in M‑mode even when various extensions are active.

REGISTER: marchid
SUMMARY: marchid is a machine‑level, MXLEN‑wide read‑only CSR that encodes the base microarchitecture of the hart and must be readable in every implementation. Its value follows a global scheme: open‑source IDs are non‑zero with a zero most‑significant bit, while commercial IDs set the most‑significant bit and require all remaining bits to be non‑zero, and a commercial implementation reporting a zero MSB indicates a collision with open‑source IDs. Reads of marchid succeed without exception in M‑mode but raise an illegal‑instruction exception in S‑mode and U‑mode. Writes to marchid are ignored; the register never assumes the written value.

REGISTER: mcause
SUMMARY: The mcause CSR records the cause of the most recent trap, encoding an interrupt flag (the most‑significant bit) and a numeric cause code that identifies the specific exception or interrupt. It is an MXLEN‑bit machine‑mode read/write register; accesses from S‑ or U‑mode raise an illegal‑instruction exception, while software may write it explicitly but hardware writes only when a trap is taken into M‑mode. Hardware updates mcause only on traps taken into M‑mode, writing the appropriate flag and code according to the prioritized exception table, and does not write it when the trap is delegated to S‑mode, when a double‑trap occurs (setting code 16), or when extensions such as Smrnmi suppress the update. On reset the register reads 0, and the MSB distinguishes interrupts (1) from exceptions (0), with defined codes covering software, timer, external, page‑fault, and other standard causes; reserved or undefined codes are reported unchanged.

REGISTER: mconfigptr
SUMMARY: The mconfigptr CSR is a mandatory machine‑mode read‑only register that holds the physical address of the system configuration data structure. Its value is MXLEN‑wide and the low log₂ (n) bits are forced to zero to satisfy the required alignment (MXLEN = 8·n). Reads are allowed only in M‑mode without exception, while any access from S‑ or U‑mode or any write attempt from any privilege level raises an illegal‑instruction exception and leaves the register unchanged. Consequently, writes—including attempts to set the least‑significant address bit—never affect the value returned on readback.

REGISTER: mcontext
SUMMARY: The mcontext CSR holds machine‑mode context information and is defined as a machine‑mode read/write register. Access to mcontext is permitted only in M‑mode; any read or write from S‑ or U‑mode triggers an illegal‑instruction exception (mcause = 2). In M‑mode reads and writes succeed without exception, and setting the HCONTEXT flag is reflected on subsequent reads. Writes are masked so that writing the all‑ones value does not store that value verbatim.

REGISTER: mcounteren
SUMMARY: The mcounteren CSR is a machine‑mode register that controls which hardware performance counters (cycle, time, instruction‑retired, and the HPM counters) are readable by the next‑lower privilege level. It contains a CY bit for the cycle counter, TM for the time counter, IR for the instruction‑retired counter, and a set of HPM bits; setting a bit grants read access to that counter in S‑mode (or U‑mode if S is not implemented), while a cleared bit causes any read from the lower mode to raise an illegal‑instruction exception. Access to mcounteren itself is restricted to M‑mode—any attempt to read or write it from S‑ or U‑mode triggers an illegal‑instruction exception, and M‑mode accesses never fault regardless of extensions. The register's bits are advisory only: reading or writing mcounteren does not affect the counters, and the bits reliably round‑trip on read‑back.

REGISTER: mcountinhibit
SUMMARY: The mcountinhibit CSR controls whether hardware performance counters (mcycle, minstret, and mhpmcounter n) increment, using the CY, IR, and HPM n fields to inhibit cycle, retired‑instruction, and generic counters while leaving counter accessibility unchanged and not affecting the mtime timer. It is a machine‑read/write (MRW) register that may be accessed only in Machine mode; any read or write from Supervisor or User mode raises an illegal‑instruction exception (mcause = 2), and accesses via the scountinhibit alias are also illegal unless the counter is delegated and the menvcfg.CDE field is non‑zero. In Machine mode the bits are writable and readable, with writes taking effect immediately (including shared CY bits across harts) and reads returning the set bits, while out‑of‑range writes are masked to the defined field width. No other exceptions are generated for valid accesses, and the register does not influence the shared mtime counter.

REGISTER: mcycle
SUMMARY: The mcycle CSR is a machine‑read/write counter that reports the number of core clock cycles executed by the hart. Its value is read before the executing instruction takes effect, and a write (which takes effect after the instruction) suppresses any implicit increment, while reads or writes do not modify the underlying count. Access is privileged to M‑mode; in S‑ or U‑mode a read of the shadow cycle CSR (or mcycle) causes an illegal‑instruction exception unless the CY bit in mcounteren is set, and counting can be disabled by the CY bit in mcountinhibit or by the INH bits in mcyclecfg for the corresponding privilege mode. When counting is inhibited the counter continues to run unseen, and any disallowed access raises an illegal‑instruction exception.

REGISTER: medeleg
SUMMARY: The medeleg CSR is a 64‑bit machine‑read/write register that M‑mode uses to delegate synchronous exceptions (including user‑mode ECALL) to the S‑mode trap handler, with each bit position corresponding to the exception code returned by mcause. When a bit is set, the trapped exception is taken in S‑mode, causing scause, sepc and stval to be written and the SPP, SPIE, and SIE fields of mstatus to be updated while leaving the M‑mode fields (mcause, mepc, mtval, MPP, MPIE) unchanged. The register is accessible only in Machine mode; accesses from S‑ or U‑mode raise an illegal‑instruction exception, and bits for exceptions that cannot occur in lower privilege modes are hard‑wired zero. Writes to medeleg are reflected on readback (except for the read‑only zero bits), and the CSR must exist on any hart that implements S‑mode.

REGISTER: menvcfg
SUMMARY: menvcfg is a machine‑level read/write CSR that configures environment behavior for lower privilege modes, including cache‑block instruction enablement, address‑translation A/D handling, pointer masking, and the activation of various optional extensions. Its key field groups are the cache‑block enable bits (CBIE, CBCFE, CBZE) which gate CBO.* instructions, ADUE which controls automatic PTE A/D updates, PMM which governs pointer masking for the next‑lower mode, and control bits such as CDE, SSE, LPE that enable or disable related extensions; many of these fields are WARL and become read‑only zero when the corresponding extension is not implemented. Access to menvcfg is restricted to machine mode—any attempt to read or write it from a less‑privileged mode raises an illegal‑instruction exception (mcause = 2). When the enable bits are cleared, the associated CBO instructions and extension‑specific operations (e.g., scountinhibit, ssp, SSAMOSWAP) raise illegal‑instruction exceptions in non‑machine modes.

REGISTER: mepc
SUMMARY: mepc is a machine‑mode CSR that holds the virtual address to which control returns after a trap taken into M‑mode and is used by MRET to set the program counter. It is an MXLEN‑wide read/write register with machine read/write (MRW) permission, accessible only in M‑mode (access in S‑ or U‑mode raises an illegal‑instruction exception). On entry to an M‑mode trap the hardware writes mepc with the address of the interrupted or faulting instruction (including breakpoints, illegal instructions, access‑faults, and page‑faults); delegated traps do not modify it, and a non‑maskable interrupt overwrites it with the NMI handler address. The least‑significant bit is always zero, and on implementations with IALIGN=32 the second‑least‑significant bit is masked on reads (though still writable), making mepc a WARL register that must represent any valid virtual address.

REGISTER: mhartid
SUMMARY: The mhartid CSR holds the MXLEN‑bit integer identifier of the executing hardware thread, with at least one hart reporting zero and all IDs unique across the system. It is a machine‑read‑only register, required to be readable in any implementation and accessible only at machine privilege level. Reads succeed without exception in M‑mode, while attempts in S‑ or U‑mode raise an illegal‑instruction exception. Write attempts have no effect; the register value remains unchanged.

REGISTER: mhpmcounter10

It includes control bits that can generate a local overflow interrupt (OF) and inhibit counting while executing in machine mode, supervisor mode, user mode, and their virtual equivalents. In machine mode the register can be read or written without trapping; accesses from supervisor or user mode raise an illegal‑instruction exception, and this behavior is unchanged when the Sscofpmf extension is active. When OF is set a local counter‑overflow interrupt request is generated and eventually sets the LCOFIP bit, while a clear OF causes a standard count‑overflow interrupt on overflow.

REGISTER: mhpmevent23
SUMMARY: The mhpmevent23 CSR configures hardware performance counter 23, selecting the event to count (zero selects no event) and providing control bits for overflow handling and mode‑specific counting inhibition. Its OF bit is set on unsigned overflow of the associated hpmcounter23, serves as a count‑overflow interrupt enable/disable, and triggers a local‑counter‑overflow interrupt request (reflected in mip.lcof or sip.LCOFIP when the Sscofpmf extension is present) that can be delegated to S‑ or M‑mode via mideleg, unless the OF bit was already set. The five INH bits (M, S, U, VS, VU) inhibit counting while the processor is in the corresponding privilege mode, read as zero and read‑only for unimplemented modes, and all clear means counting occurs in all modes. Access to mhpmevent23 is permitted without exception only in M‑mode (or in any mode for reads when Sscofpmf is implemented); attempts from S‑ or U‑mode raise an illegal‑instruction exception.

REGISTER: mhpmevent24
SUMMARY: mhpmevent24 is a machine‑read/write CSR that selects a hardware performance‑monitoring event and reports overflow of its associated counter. It contains an OF status bit that stays set until cleared by software and triggers the sip.LCOFIP (or mip) overflow interrupt, and a set of INH bits (machine, supervisor, user, virtual‑supervisor, virtual‑user) that enable or inhibit counting in the corresponding privilege modes, with all zero meaning counting in all modes. Overflow interrupt delegation to S‑mode is controlled by mideleg, and overflow interrupt generation is enabled simply by clearing OF together with initializing the counter (no separate enable bits). The CSR is accessible without exception only in M‑mode (or when the required extensions are present); accesses from S‑ or U‑mode raise an illegal‑instruction exception.

REGISTER: mhpmevent25
SUMMARY: mhpmevent25 is a machine‑mode CSR that configures overflow handling for a performance counter, providing an OF bit to enable overflow generation and a set of INH bits that inhibit the overflow interrupt in the corresponding privilege modes (machine, supervisor, user, VS, VU). The register is MRW, so it is readable and writable only in M‑mode; accesses from S‑ or U‑mode raise an illegal‑instruction exception, while M‑mode accesses never trap, even when the Sscofpmf extension is active. With Sscofpmf implemented, overflow occurrences appear in mip.LCOFIP (read‑write) and are enabled via mie.LCOFIE, and the delegation of the overflow interrupt to supervisor or machine mode is controlled by mideleg.

REGISTER: mhpmevent26
SUMMARY: The mhpmevent26 CSR selects the event counted by its associated hardware performance counter (event 0 means "no event") and includes an overflow (OF) status bit that also disables overflow‑interrupt generation, together with a group of INH bits that inhibit counting in the corresponding privilege modes (machine, supervisor, user, VS, VU). It is machine‑read/write and may be accessed without fault only in M‑mode (or in any mode when the Sscofpmf extension is active); accesses from S‑ or U‑mode without that extension raise an illegal‑instruction exception. The OF bit is set automatically on an unsigned counter wrap‑around, stays set until cleared by software, and when clear at overflow triggers a count‑overflow interrupt via local interrupt bit 13, requiring software to clear OF and reinitialize the counter before another interrupt can occur. Writes to the CSR never cause a counter overflow, which can arise only from hardware increments.

REGISTER: mhpmevent27
SUMMARY: mhpmevent27 is a 64‑bit WARL register that selects the event that drives the associated hardware performance counter mhpmcounter27. It contains an overflow‑sticky OF bit and a set of inhibit bits (machine, supervisor, user, virtual‑supervisor, virtual‑user) that are read‑write and reflected on readback. The register is only accessible in M‑mode; accesses from S‑ or U‑mode raise an illegal‑instruction exception, while M‑mode accesses are always permitted, even when the Sscofpmf extension is implemented. When OF is set, counter overflow does not generate a count‑overflow interrupt, the OF bit remains set, and, if Sscofpmf is present, the local‑counter‑overflow pending bit (LCOFIP) in mip/sip is eventually asserted.

REGISTER: mhpmevent28
SUMMARY: The mhpmevent28 CSR selects the hardware event counted by performance counter 28 and provides control bits for overflow handling and mode‑inhibition of counting. The OF flag signals a counter overflow, raises the overflow interrupt, and sets the sip.LCOFIP bit, which software must clear before servicing; the five INH bits (M, S, U, VS, VU) enable or inhibit counting in the corresponding privilege modes, with all zero meaning counting in all modes. Writes become effective only after the writing instruction completes and never cause overflow, while reads and writes are allowed only in M‑mode, generating an illegal‑instruction exception in S‑ or U‑mode. Access in M‑mode incurs no exception when the Sscofpmf or Zihpm extensions are active.

REGISTER: mhpmevent29
SUMMARY: The mhpmevent29 CSR selects the hardware event counted by hpmcounter29 and contains control bits for overflow indication (OF) and counting inhibition in machine, supervisor, user, and virtualized privilege modes. It is a WARL register: writes of unsupported event codes are masked to a legal selector and do not increment the counter. Access to mhpmevent29 is permitted only in M‑mode; attempts from S‑ or U‑mode raise an illegal‑instruction exception, while M‑mode accesses never fault (including when the Sscofpmf extension is active). After a counter overflow, the OF bit and the counter must be cleared before another overflow interrupt can be generated, and the corresponding LCOFIP interrupt‑pending bit is set eventually but not necessarily immediately.

REGISTER: mhpmevent3
SUMMARY: The mhpmevent3 CSR configures the third hardware performance‑monitor event; writing zero selects "no event". It includes an overflow flag (OF) that is set on counter overflow and disables further overflow interrupts, together with inhibit bits (MINH, SINH, UINH, VSINH, VUINH) that suppress counting while the processor runs in the corresponding privilege modes. The register is machine‑read/write only—accesses in S‑ or U‑mode raise an illegal‑instruction exception, while accesses in M‑mode never fault, even when the Sscofpmf extension is active. When OF is set, the local‑counter‑overflow pending bit (LCOFIP) in mip/sip is eventually asserted, generating the standard local interrupt if its enable bit (LCOFIE) is set.

REGISTER: mhpmevent30
SUMMARY: The mhpmevent30 CSR selects the event for hardware performance counter 30 and contains an overflow flag (OF) plus privilege‑inhibit bits that can mask the event for machine, supervisor, user, virtual‑supervisor, and virtual‑user modes. The OF bit is set by a counter overflow, stays set until cleared by software, and automatically asserts the local‑counter‑overflow interrupt (LCOFIP) in the mip register; writes to the CSR become visible after the executing instruction completes. The register is fully read‑write only in M‑mode (no exception), while accesses from S‑ or U‑mode raise an illegal‑instruction exception unless the Sscofpmf extension is active, in which case M‑mode access remains legal. Any INH bit for an unimplemented privilege mode reads as zero.

REGISTER: mhpmevent31
SUMMARY: mhpmevent31 configures event 31 for the hardware performance counters, supplying an overflow flag (OF) and a set of privilege‑level inhibit bits (MINH, SINH, UINH, VSINH, VUINH) that control counting in machine, supervisor, user, and virtual modes. When the Sscofpmf extension is present, setting OF indicates a counter overflow, contributes to a local‑counter‑overflow interrupt whose enable is the LCOFIE bit in mie and whose pending status is reported in the read‑write sip.LCOFIP bit. The register is only accessible in M‑mode; any access from S‑ or U‑mode causes an illegal‑instruction exception, while M‑mode accesses never trap, even with Sscofpmf active. Writes to any of its defined fields are reflected on subsequent reads.

REGISTER: mhpmevent4
SUMMARY: mhpmevent4 is a machine‑mode CSR that selects the hardware event counted by hpmcounter4 and provides overflow status together with mode‑inhibition controls. It is readable and writable only in M‑mode (accesses in S‑ or U‑mode raise illegal‑instruction exceptions), and such accesses are allowed when the Sscofpmf or Zihpm extensions are present. The event field (0 = no event) selects a legal event, with unsupported bits silently masked; the OF bit records a counter overflow and disables further overflow‑interrupt generation until cleared by software, while the MINH, SINH, UINH, VSINH and VUINH bits optionally inhibit counting in the corresponding privilege modes. When OF is clear, an overflow of hpmcounter4 sets OF, may raise a standard local count‑overflow interrupt delegated via mideleg, and further interrupts are blocked until the counter and OF bit are re‑initialized.

REGISTER: mhpmevent5
SUMMARY: The mhpmevent5 CSR selects the event that increments the associated mhpmcounter5 and provides status and control for counter overflow. It contains an event‑code field (0 = no event), an OF bit that both records overflow and disables the overflow interrupt, and a set of INH bits that suppress counting in M‑mode, S/HS‑mode, U‑mode (and virtualized modes) when set. The register is machine‑read/write only; accesses from M‑mode succeed, while accesses from S‑mode or U‑mode raise an illegal‑instruction exception, regardless of the Sscofpmf extension. When the linked counter overflows, hardware sets OF (if not already set) and raises the local‑counter‑overflow interrupt pending bit (LCOFIP); the interrupt is suppressed if OF is 1, and both the counter and OF must be cleared before another overflow interrupt can occur.

REGISTER: mhpmevent6
SUMMARY: mhpmevent6 selects the event that increments mhpmcounter6 and includes control bits for overflow status and for inhibiting counting in specific privilege modes. The OF bit signals a counter overflow and disables further overflow interrupts when set, while a set of INH bits (M‑mode, S/HS‑mode, U‑mode and other privilege‑mode bits) suppress counting in the corresponding mode, with all clear permitting counting in every mode. The CSR is readable and writable only in machine mode; accesses from supervisor or user mode raise an illegal‑instruction exception, and accesses in machine mode never trap, even when the Sscofpmf extension is present. On unsigned counter overflow the counter wraps modulo 2ᴺ, OF is set, and, if OF is cleared, a count‑overflow interrupt is generated and reflected in sip.LCOFIP, which can be enabled via sie.LCOFIE when Sscofpmf is implemented.

REGISTER: mhpmevent7
SUMMARY: The mhpmevent7 CSR is a 64‑bit WARL register that selects the hardware event causing mhpmcounter7 to increment, with a value of zero meaning "no event". It contains a sticky overflow flag and a set of INH bits (including MINH, SINH, UINH and their virtualization equivalents) that, when set, suppress counting in the corresponding privilege modes, while all clear enables counting in all modes. The register is MRW‑accessible only in M‑mode (access in S‑ or U‑mode triggers an illegal‑instruction exception), and if the Sscofpmf extension is implemented the high half is reachable via the mhpmevent7h CSR. An overflow sets the OF bit and generates a standard local interrupt mapped to bit 13 of the mip/mie/sip/sie registers (LCOFIP/LCOFIE), which software must clear.

REGISTER: mhpmevent8
SUMMARY: mhpmevent8 selects the hardware event that increments mhpmcounter8, with an event value of 0 meaning "no event." Its OF field reports overflow status and also disables the associated overflow interrupt; clearing OF enables a count‑overflow interrupt that is reflected in the LCOFIP bit of mip/sip and can be delegated by mideleg, while setting OF suppresses that interrupt. The INH bits (MINH, SINH, UINH, VSINH, VUINH) inhibit counting in the corresponding privilege modes, and when all are zero counting occurs in every mode. Access to the CSR is privileged: it is legal in M‑mode (illegal‑instruction in S‑ or U‑mode unless the Sscofpmf extension is present), and a write takes effect after the writing instruction has completed.

REGISTER: mhpmevent9
SUMMARY: The mhpmevent9 CSR configures which hardware event is counted by performance counter 9, with a zero write disabling the counter. Its primary fields are the OF bit, which is set by hardware on an unsigned counter overflow and both flags the overflow status and optionally disables further overflow‑interrupt generation, and a set of INH bits (MINH, SINH, UINH, VSINH, VUINH) that suppress counting in the corresponding privilege modes; when all INH bits are clear, counting is enabled in every mode. When the Sscofpmf extension is implemented, the OF bit participates in the local‑counter‑overflow interrupt reflected in the LCOFIP bits of mip/sip, and such an interrupt can be taken in S‑mode only if the OF bit is set, sie.LCOFIE is enabled, and the current privilege permits it. Access to mhpmevent9 is permitted without exception only in M‑mode (including when Sscofpmf is present); attempts from S‑ or U‑mode raise an illegal‑instruction exception.

REGISTER: mideleg
SUMMARY: The mideleg CSR (address 0x303) selects which traps and interrupts that occur in S‑mode (or lower) are delegated from machine mode to the supervisor trap handler. It is an MXLEN‑wide read‑write register that exists only on harts implementing S‑mode and is accessible solely in M‑mode; any access from S‑ or U‑mode raises an illegal‑instruction exception. Writing a 1 to a delegatable bit causes that trap/interrupt to be handled in S‑mode (making it visible in sip and maskable via sie), while a cleared bit forces handling in M‑mode and forces the corresponding sip/sie bits to zero; implementations may support only a subset of bits (discoverable by a write‑ones‑read‑back test) and some bits are read‑only (e.g., fixed‑1 when the hypervisor extension is present). No other exceptions occur on reading or writing mideleg in M‑mode, irrespective of other extensions being active.

REGISTER: mie
SUMMARY: The mie CSR is a machine‑read/write register that holds the global enable bits for all interrupt causes. Each implemented interrupt has a corresponding enable bit; setting a bit allows that interrupt to trap to M‑mode, writes trigger immediate re‑evaluation of pending interrupts, non‑writable bits read as zero, and some bits (e.g., bit 1) are write‑1‑to‑clear. Access to mie is permitted only in machine mode—reads or writes from supervisor or user mode raise an illegal‑instruction exception, except when the Sscofpmf extension is active, which still permits machine‑mode access without fault. The supervisor‑level sie register mirrors the readable/writable fields of mie but shows non‑delegated interrupt bits as read‑only zero, and the count‑overflow interrupt is treated as a standard local interrupt with its enable bit (LCOFIE) shared across mie, sie, mip, and sip, with delegation governed by mideleg.

REGISTER: mimpid
SUMMARY: The mimpid CSR provides a machine‑mode read‑only identifier that must be present in every RISC‑V implementation. It can be read without fault only while executing in M‑mode; attempts to read it from S‑ or U‑mode raise an illegal‑instruction exception (mcause 0x2). Writes to the register are ignored, leaving its value unchanged regardless of the data supplied. Consequently, mimpid is an immutable, privileged‑only read‑only CSR.

REGISTER: minstret
SUMMARY: The minstret CSR (address 0xB02) holds the lower 32 bits of the machine‑mode instruction‑retired counter and can be written, with the new value taking effect after the writing instruction completes. Its counting can be globally disabled by the IR bit in mcountinhibit and selectively inhibited for S‑mode or U‑mode by the SINH and UINH bits in the minstretcfg CSR (the OF bit is read‑only zero). The counter increments for each retiring instruction except ECALL/EBREAK, synchronous exceptions, faulting loads, and any instruction whose originating privilege mode is inhibited, while xRET instructions count only when the originating mode is not inhibited. Access to minstret is unrestricted in M‑mode (no exception regardless of extensions) but illegal in S‑ or U‑mode unless the IR bit in mcounteren permits reading the instret shadow CSR; writes are not permitted outside M‑mode.

REGISTER: mip
SUMMARY: The mip CSR holds the machine‑mode pending‑interrupt status, aggregating hardware‑generated pending bits (external, timer, and software interrupts) and, where writable, software‑set bits used to signal lower‑privilege levels. Machine‑mode software may read and write mip (MRW), but only the software‑writable fields (e.g., SEIP, SSIP, and, if implemented, LCOFIP) can be changed; attempts to modify read‑only hardware bits are ignored and writing zero clears any writable pending bit. Reads in M‑mode return the logical‑OR of the hardware signal and any software‑set bit for fields like SEIP, while writes affect only the software‑controlled bits and never raise exceptions. Accessing mip from S‑ or U‑mode triggers an illegal‑instruction exception, whereas M‑mode accesses are always permitted regardless of extensions.

REGISTER: misa
SUMMARY: The misa CSR reports the ISA implemented by a hart, with a read‑only MXL field encoding XLEN and a writable‑as‑required Extensions field whose bits indicate supported standard and non‑standard extensions. It is a machine‑read/write register: reads are permitted in any privilege mode, but writes are only allowed in M‑mode; attempts to read it from S‑ or U‑mode raise an illegal‑instruction exception. The Extensions bits are WARL: at reset they contain the maximal supported set (with I preferred over E), reserved bits read as zero, and any write that violates dependency rules or unsupported combinations is automatically corrected to a legal configuration. Individual extension bits may be read‑only (e.g., E, MXL) or non‑reflecting (e.g., G, Q) depending on implementation, and attempts to modify such bits have no effect on the read‑back value.

REGISTER: miselect
SUMMARY: The miselect CSR is a machine‑mode read‑write register that selects an implemented extension via its value field. It is accessible only in M‑privilege; any access from S‑ or U‑mode triggers an illegal‑instruction exception (mcause = 0x2). Writes of any (including unimplemented) value are accepted, but a subsequent read returns a legal value after masking or truncating unsupported bits, with no exception generated. The low‑order VALUE bit written is reflected unchanged on readback.

REGISTER: mscratch
SUMMARY: mscratch is a machine‑mode CSR, MXLEN‑wide and read/write, dedicated for use by M‑mode software. On entry to M‑mode after a trap, the hardware swaps the value in mscratch with the designated user register, preserving the pre‑trap value in mscratch. Access to mscratch is allowed only in M‑mode (no exception, mcause = 0x0); any S‑mode or U‑mode access triggers an illegal‑instruction exception (mcause = 0x2).

REGISTER: mseccfg
SUMMARY: The mseccfg CSR is a 64‑bit machine‑mode register that configures security‑related features such as seed‑CSR accessibility, PMP locking and default‑policy changes, pointer‑masking, and optional Zicfilp activation. Its USEED and SSEED bits enable read‑write access to the seed CSR from user and supervisor modes respectively, otherwise accesses from those modes raise illegal‑instruction exceptions, while machine mode always has unrestricted access. The MML, RLB, MMWP, and PMM fields modify PMP semantics—MML activates a mode‑aware PMP interpretation with locked or shared regions, RLB permits unlocking of locked PMP entries, MMWP changes the default machine‑mode policy to deny, and PMM selects pointer‑masking granularity; writes to these fields follow WARL rules and are visible only in machine mode. All reads and writes to mseccfg are permitted only in machine mode; any attempt from supervisor or user mode triggers an illegal‑instruction exception, and the register resets with MMWP cleared and undefined fields zero unless the platform specifies otherwise.

REGISTER: mstateen0
SUMMARY: mstateen0 is a machine‑mode read/write CSR that governs the visibility of architectural state to less‑privileged modes. Its principal fields—SE0, ENVCFG, CSRIND and groups such as CTR, FCSR, etc.—enable access to the corresponding hstateen0/sstateen0 CSRs, environment‑configuration CSRs, CSR indirection, and specific state components; any unimplemented or reserved bits read as zero and are not writable, and all writable bits are cleared to zero on reset. The register can be accessed only in M‑mode; reads or writes in S‑ or U‑mode raise an illegal‑instruction exception, and any zero bit in mstateen0 forces the matching bit in hstateen0 and sstateen0 to be read‑only zero. When a lower‑privilege mode attempts to use state whose enable bit is zero (e.g., the CTR group), an illegal‑instruction exception is generated, and raising such an exception in M‑mode while the C bit is set but no custom state is accessed indicates non‑conforming hardware.

REGISTER: mstateen1
SUMMARY: The mstateen1 CSR (address 0x30D) is a machine‑read/write register that enables or disables access to corresponding architectural state at lower privilege levels, while machine‑level access itself is unrestricted. Its most‑significant bit controls the matching sstateen1 and hstateen1 CSRs, the upper half governs state inherently inaccessible to user mode, and the remaining defined bits gate groups of lower‑privilege state; bits not implemented for the hart read as zero and are read‑only. Access is allowed only in M‑mode, and any read or write from S‑ or U‑mode—or any operation on a bit lacking a defined counterpart in the lower‑privilege sstateen CSRs—triggers an illegal‑instruction exception. On reset all writable bits are cleared, writes are masked to the implemented bits (so writing all ones does not set undefined bits), and accesses never fault even when the Smstateen extension is active.

REGISTER: mstateen2
SUMMARY: The mstateen2 CSR (address 0x30E, MRW) lets machine‑mode software enable lower‑privilege access to the state of optional extensions, with each bit representing one extension and bit 63 controlling access to the subordinate hstateen2 and sstateen2 registers. All writable bits reset to zero, reserved or unimplemented bits read as zero, and writing a 1 in machine mode both enables the corresponding lower‑privilege access and forces the matching bits in any hstateen or sstateen CSR to be cleared (writing 1 to bit 63 also clears all hstateen bits). Access to mstateen2 is legal only in machine mode; attempts from supervisor or user mode raise an illegal‑instruction exception. Writes of arbitrary all‑ones values do not result in all‑ones read‑back because only defined, writable bits may be set.

REGISTER: mstateen3
SUMMARY: The mstateen3 CSR controls whether the matching bits of the sstateen3 and hstateen3 registers are enabled, with its most‑significant bit (SE0) governing access to those entire CSRs. It is machine‑read/write (MRW) and imposes no restriction on machine‑mode accesses, while any access from supervisor or user mode causes an illegal‑instruction exception regardless of other extensions. After reset all writable bits are cleared to zero; bits that are read‑only zero because the hart does not implement the corresponding state or because they are reserved remain immutable, and only the writable bits can be set and are reflected on readback. Access is permitted without fault in M‑mode even when the H, Smstateen, or Ssstateen extensions are present, but lower‑privilege modes are never allowed to read or write it.

REGISTER: mstatus
SUMMARY: The mstatus CSR holds the machine‑level status of the hart, including global interrupt‑enable bits, privilege‑mode fields for trap entry/return, extension‑state fields (FS, VS, XS) that track whether floating‑point, vector, or other user extensions are off, clean, initial or dirty, and a read‑only SD bit that summarises any dirty extension state. It also contains control bits for memory‑management and virtualisation (MPP, MPIE, SPP, SPIE, MPRV, MXR, SUM, TVM, TSR, TW) and endianness selectors (MBE, SBE, UBE). The register is machine‑read/write only; any access from lower privilege levels raises an illegal‑instruction exception, writes are masked to XLEN and only architecturally defined fields are retained, while read‑only or WARL fields ignore writes to undefined bits. Illegal‑instruction exceptions are also generated when VS=Off for vector operations, FS=Off for floating‑point operations, or when TVM, TSR, or TW are set and privileged instructions such as satp access, SFENCE.VMA, SRET, or WFI are attempted in disallowed modes.

REGISTER: mtinst
SUMMARY: The mtinst CSR holds a transformed instruction for debug use. If the instruction's address‑offset field is non‑zero yet the effective address is aligned, an illegal‑instruction exception is raised (mcause = 2). Encodings 0x00002003 and 0x00002023 are defined as the no‑op load‑word lw x0,0(x0), while 0x00003003 and 0x00003023 represent the 64‑bit no‑op load‑double ld x0,0(x0) and store‑double sd x0,0(x0) respectively.

REGISTER: mtval
SUMMARY: The mtval CSR supplies trap‑specific information to software, typically the faulting virtual address or, for illegal‑instruction and certain fetch faults, the offending instruction bits, and it is written by hardware when a trap is taken into M‑mode. It is a machine‑read/write (WARL) register that must hold any valid virtual address, zero, and, if the fault‑instruction feature is implemented, any value less than 2^N where N = min(MXLEN, ILEN); writes exceeding MXLEN are truncated. Access is allowed only in machine mode, with accesses from S‑ or U‑mode generating illegal‑instruction exceptions, and traps delegated to S‑mode never cause a hardware write to mtval. For defined traps (breakpoint, misaligned, access‑fault, page‑fault, guest‑page‑fault, hardware‑error, illegal‑instruction, and software‑check) mtval is written with the corresponding address or code, otherwise it is written zero.

REGISTER: mtvec
SUMMARY: The mtvec CSR (address 0x305) holds the machine‑mode trap‑vector base address (BASE) and a mode selector (MODE) that controls PC redirection on traps. BASE must be 4‑byte aligned (low two bits are zeroed when used as an address); MODE = 0 (Direct) sends all machine‑mode traps to BASE, while MODE = 1 (Vectored) sends synchronous exceptions to BASE and the timer interrupt (cause 2) to BASE + 4 × cause + 4. mtvec is readable and writable only in M‑mode; attempts to access it from S‑ or U‑mode raise an illegal‑instruction exception (mcause 0x2). Writes with unsupported MODE values, misaligned BASE, or out‑of‑range bits are silently corrected or masked so that subsequent reads return a legal, aligned BASE and a valid MODE (typically 0) without raising an exception.

REGISTER: mvendorid
SUMMARY: The mvendorid CSR holds a vendor identification value; a read of zero indicates the vendor field is unimplemented or the implementation is non‑commercial. It is a machine‑mode read‑only register that must be readable in all implementations. Access in machine mode succeeds without exception, whereas accesses from supervisor or user mode raise an illegal‑instruction exception. Writes to the register are ignored and do not change its contents.

REGISTER: mvien
SUMMARY: The mvien CSR provides enable bits for the local‑counter‑overflow interrupt (LCOFI) together with write‑preserve (WPRI) fields. It is only accessible in M‑mode; accesses from S‑ or U‑mode generate an illegal‑instruction exception, while M‑mode accesses never trap even when extensions such as Smcdeleg, Sscofpmf, Smaia, or Ssaia are present. When the Smcdeleg, Sscofpmf, and Smaia extensions are implemented, the LCOFI bit is present and writable, and the WPRI bits are writable but are masked on readback so that undefined bits are cleared. All defined bits reflect the values written, while writes of arbitrary values do not set undefined bits.

REGISTER: mvip
SUMMARY: The mvip CSR is a machine‑mode register that reports machine‑visible interrupt‑pending state and includes writable fields such as WPRI and LCOFI. In M‑mode the register can be read and written; the defined writable bits are reflected on readback while writes to undefined bits are ignored (e.g., a full‑ones write does not propagate all ones). Accesses from S‑mode or U‑mode raise an illegal‑instruction exception (mcause = 0x2). When the Smaia or Ssaia extensions are active, M‑mode accesses still succeed without exception (mcause = 0x0).

REGISTER: pmpaddr0
SUMMARY: pmpaddr0 is the address CSR for PMP entry 0, holding the high‑order bits of a physical address (bits 55‑2 on RV64) and used for TOR or NAPOT address matching. It is a WARL register: bits below the granularity G read as all zeros in TOR/OFF mode or all ones in NAPOT mode, and the top granule bit may be internally 1 while reading back as 0. The CSR is accessible only in machine mode; any access from supervisor or user mode triggers an illegal‑instruction exception (mcause = 2), and writes are ignored when the entry is locked. In machine mode a read returns the masked stored value and a write updates the underlying value unless the lock prevents it.

REGISTER: pmpaddr1
SUMMARY: pmpaddr1 is a WARL CSR that holds the upper bits of the physical address for PMP entry 1 (bits 55‑2 in RV64) and works with pmpcfg1 to define address‑matching. Together with pmpcfg1.A it selects NAPOT (where low‑order patterns determine the power‑of‑two range) or TOR (where pmpaddr0 is the inclusive lower bound and pmpaddr1 the exclusive upper bound; NA4 is unavailable when G ≥ 1). The register is readable and writable only in M‑mode (S‑ and U‑mode accesses raise illegal‑instruction), writes are ignored when the entry is locked (L bit set), and a non‑RW setting causes any M‑mode load or store within the range to fault with mcause = 12 (load) or 13 (store). The most‑significant G‑1 bit may be stored as 1 but reads as 0, CSRRC/CSRRS on other bits clears the underlying G‑1 value, and changing pmpcfg1.A can alter the read‑back value without affecting the stored bits.

REGISTER: pmpaddr10
SUMMARY: pmpaddr10 is a Machine‑level read/write CSR that holds the address component of PMP entry 10, providing the top bound for TOR ranges (with pmpaddr9 as the bottom) or the encoded NAPOT address where its low bits determine the range size. The most‑significant implemented address bit (pmpaddr10[G‑1]) may be stored as 1 but always reads as 0, and CSRRS/CSRRC can modify bits regardless of their read value; writes to any bit beyond the physical‑address width are masked on read, and if the entry's L bit is set all writes are ignored until reset. Access to pmpaddr10 is permitted without exception only in M‑mode (including when the Smepmp extension is present), while attempts from S‑ or U‑mode raise an illegal‑instruction exception. Changing the A field (e.g., between NAPOT, TOR, or OFF) alters the value seen on reads but does not affect the underlying stored bits.

REGISTER: senvcfg
SUMMARY: The senvcfg CSR defines the user‑mode execution environment, exposing fields that enable or disable cache‑block operations (CBIE, CBCFE, CBZE), pointer‑masking mode (PMM), and extensions such as Zicfiss (SSE) and Zicfilp (LPE). In U‑mode, cache‑block instructions are permitted only when the corresponding enable field is set and the instruction is also enabled for S‑mode; otherwise an illegal‑instruction exception is raised, and SSAMOSWAP.W/D likewise faults when SSE=0. The SSE bit activates the Zicfiss extension and shadow‑stack control‑flow protection, while PMM selects pointer‑masking granularity (disabled, XLEN‑57, or XLEN‑48); when SSE is cleared the field is read‑only zero and related 16‑bit instructions revert to Zcmop behavior. Access to senvcfg is SRW‑privileged: M‑mode may read/write freely, whereas S‑ and U‑mode accesses generate illegal‑instruction traps unless the ENVCFG bits in the appropriate state‑enable CSR permit it, and writes are reflected on subsequent reads with undefined bits masked out.

REGISTER: sepc
SUMMARY: The sepc CSR holds the virtual address of the instruction that caused a trap and is used by the SRET instruction to resume execution after returning from S‑mode. It is an SXLEN‑wide read/write register with Supervisor Read/Write privilege, accessible without exception in M‑mode and S‑mode but causing an illegal‑instruction fault in U‑mode. Hardware writes sepc on every trap taken to S‑mode (including delegated, double‑trap, and HS‑mode entries) with the faulting or interrupted instruction address, while software may also write it explicitly; the low bit is always zero and, when IALIGN = 32, the next low bit is masked on reads (though it can still be written). The register is WARL, constrained to hold any valid virtual address, and it is modified only by trap entry or explicit software writes.

REGISTER: sie
SUMMARY: The sie CSR holds the supervisor‑mode interrupt‑enable bits that mask interrupts delegated to S‑mode, allowing S‑mode to control whether pending delegated interrupts can trap. It contains enable bits for the standard software, timer, external, and count‑overflow interrupts, each tied to the same‑numbered pending bit and writable only if the corresponding interrupt is implemented and delegated. The register is readable and writable in S‑mode (and M‑mode without exception) but raises a privileged‑instruction/illegal‑instruction exception when accessed in U‑mode; reads mirror the SIE field of sstatus and any illegal bits written are cleared. Writes affect trap eligibility immediately, and on an SRET the SIE field is restored from SPIE while SPIE is set to 1.

REGISTER: sip
SUMMARY: The sip CSR provides the supervisor mode with a filtered view of the machine‑level interrupt‑pending register (mip), exposing only those interrupt bits that have been delegated to S‑mode via mideleg; non‑delegated bits appear as zero. It is accessible with supervisor‑read/write privilege and can be accessed without fault in M‑ and S‑mode but generates an illegal‑instruction exception in U‑mode. Writable bits such as SSIP (and, when the Sscofpmf extension is present, LCOFIP) can be cleared by writing zero, while read‑only bits like SEIP ignore writes; the register mirrors reads and writes of the corresponding mip fields. The register's behavior for the count‑overflow interrupt (bit 13, LCOFIP) and for the STIP field follows the specifications of the Sscofpmf and Sstc extensions, reverting to the base definition when those extensions are disabled.

REGISTER: siselect
SUMMARY: The siselect CSR selects an indirectly accessed CSR and contains a writable VALUE field that round‑trips on readback. It is a supervisor‑read/write register, but M‑mode can access it without fault; accesses from S‑ or U‑mode raise an illegal‑instruction exception unless the CSRIND bit in hstateen0 (or the corresponding enable bits mstateen0[60]/hstateen0[60] when the Smstateen or hypervisor extensions are present) is set, in which case the access is permitted. Writing a value greater than 0xFFF may trigger an illegal‑instruction exception, and selecting 0x41 (the mtime register) is explicitly prohibited and also raises an illegal‑instruction exception. The register is always XLEN bits wide and is not subject to VSXLEN.

REGISTER: sscratch
SUMMARY: The sscratch CSR is a supervisor‑level, SXLEN‑wide read/write register dedicated for supervisor use. It can be accessed without exception in M‑mode and S‑mode, but generates an illegal‑instruction exception in U‑mode. When the virtualization bit V = 1, writes to sscratch are ignored and the register's contents are not updated. Accesses in M‑mode remain exception‑free even when the S extension is active.

REGISTER: ssp
SUMMARY: The ssp CSR holds the shadow‑stack pointer, using its XLEN‑wide low‑order bits for push/pop operations while bits 1:0 are permanently zero (bit 2 is also zero when XLEN can never be 32). It is an unprivileged read‑write CSR, accessible in M‑mode unconditionally but in S‑ or U‑mode only when the corresponding SSE enable bits are set, otherwise an illegal‑instruction exception is raised. Push instructions decrement ssp by XLEN/8 and store the link register at the new address, generating a store/AMO access‑fault on mis‑aligned or non‑idempotent memory and performing the decrement only if the store succeeds; pop‑check instructions load from ssp, compare the loaded value to a source register (only x1 or x5 allowed), raise a software‑check exception on mismatch, and increment ssp by XLEN/8 only after a successful, fault‑free load. Direct CSR reads return the current ssp value, writes replace the low‑order bits respecting the read‑only zero constraints, and all accesses are subject to the privilege and SSE enable checks, with violations causing the appropriate exception.

REGISTER: sstateen0
SUMMARY: The sstateen0 CSR (address 0x10c) provides supervisor‑mode state‑enable bits and is a 64‑bit register whose upper 32 bits are hard‑wired to zero and has no high‑half counterpart. Each bit is masked by the corresponding bit in mstateen0 (and, when the hypervisor extension is present, hstateen0); if the higher‑privilege bit is zero, reserved, or refers to unimplemented state (including the FCSR bit when the F extension is present), the sstateen0 bit is read‑only zero and cannot be read‑only one unless the higher‑privilege bits are read‑only one. Access to sstateen0 is permitted only in M‑mode—attempts in S‑ or U‑mode raise an illegal‑instruction exception—while the SE0 bits in mstateen0/hstateen0 gate this permission. Writes in M‑mode are ignored, so reads always return zero for all defined bits regardless of any extensions that are active.

REGISTER: sstateen1
SUMMARY: The sstateen1 CSR (address 0x10d) is a supervisor‑read/write register that controls the exposure of lower‑privilege architectural state to less‑privileged modes but does not affect supervisor‑level state itself. Its upper 32 bits are hard‑wired zero, and any bit that is unimplemented, reserved, or cleared in the matching mstateen1 (or hstateen1) field reads as zero; a bit may be read‑only one only if the same bit is read‑only one in both mstateen1 and hstateen1. Writes have no effect—the hardware forces all writable bits to zero—so attempts to set bits (e.g., the DATA bit) or write all‑ones never change the read‑back value. The register can be accessed without exception only in M‑mode; any access from S‑ or U‑mode raises an illegal‑instruction exception, regardless of extension activation.

REGISTER: sstateen2
SUMMARY: sstateen2 is a supervisor‑mode read/write CSR that enables or disables trapping of specific supervisor‑level architectural states, with each bit representing a distinct state group. Any bit that corresponds to an unimplemented state, is reserved, or whose counterpart in mstateen2 is zero is hard‑wired to read‑only zero, while a read‑only one may appear only if the same bit is read‑only one in the matching mstateen2 (and hstateen2 when present); machine software must clear writable bits when mstateen2 changes. Accesses generate no exception in M‑mode but raise an illegal‑instruction exception in S‑ and U‑modes, and writes to writable bits have no observable effect (e.g., setting the DATA bit or writing all‑ones reads back zero).

REGISTER: sstateen3
SUMMARY: sstateen3 is a supervisor‑mode CSR that selects which supervisor‑state bits may be saved or restored, but all of its bits are effectively read‑only zero because they are masked by higher‑privilege enable bits, hardware implementation limits, and reserved‑zero rules. Although defined with SRW privilege, the register can only be accessed without exception in machine mode; any access from supervisor or user mode triggers an illegal‑instruction exception. Writes to sstateen3 have no effect—after reset the writable bits are zero, and any attempted write (including full‑width values) reads back as zero, with no bits becoming read‑only one unless the same bits are read‑only one in the corresponding mstateen (and hstateen, if present) registers. The upper 32 bits are permanently zero, no high‑half CSR exists, and accesses remain exception‑free in M‑mode when the Smstateen or Ssstateen extensions are active.

REGISTER: sstatus
SUMMARY: The sstatus CSR holds the supervisor‑mode view of processor state, mirroring the corresponding fields of mstatus and is readable and writable only in supervisor (or higher) privilege levels. It contains groups of bits that control interrupt enable (SIE/SPIE), previous privilege (SPP), trap delegation (SDT), floating‑point and vector status (FS/VS), user‑memory access permissions (SUM, MXR), endianness for user accesses (UBE), and debug/status flags (SD, SPELP). Accesses to sstatus in user mode raise an illegal‑instruction exception, and fields such as SUM and MXR directly govern whether supervisor loads/stores or CMO instructions may target user pages or executable pages, causing page‑fault or illegal‑instruction traps when the required permissions are not set; unimplemented extensions force related bits to read‑only zero. On taking a trap the hardware saves the prior privilege in SPP, copies SIE into SPIE and clears SIE, while an SRET instruction restores the saved privilege, reinstates SIE from SPIE, clears SPP and sets SPIE to 1.

REGISTER: stopi
SUMMARY: The stopi CSR (address 0xdb0) is a machine‑mode‑only register; reads succeed in M‑mode but cause an illegal‑instruction trap in S‑ and U‑modes (mcause = 0x2). No exception is raised for a read in M‑mode (mcause = 0x0). Writes are permitted in M‑mode, but the hardware masks or rejects the value so that writing 0xffffffffffffffff does not result in the register containing either 0xffffffff or the original value. Access to stopi is not gated by any extension‑enable bits.

REGISTER: stval
SUMMARY: The stval CSR is an SXLEN‑bit supervisor‑read/write register that holds exception‑specific information to aid trap handling. On traps delegated to S‑mode or taken into HS‑mode the hardware writes stval with the faulting virtual address (or zero) for breakpoint, misaligned, access‑fault, page‑fault, hardware‑error, and illegal‑instruction exceptions, and with the software‑check cause for software‑check traps; otherwise it is never written automatically. The register contains address fields (GVA/SPV) that convey the faulting address or, for hypervisor traps, flag values, and it must be able to hold any valid virtual address, zero, and, if implemented, instruction bits up to min(SXLEN,ILEN), with pointer masking applied to address writes. Accessing stval causes no exception in M‑ and S‑mode but raises an illegal‑instruction fault in U‑mode, and software may read or write it at supervisor privilege.

REGISTER: stvec
SUMMARY: stvec is a supervisor‑mode CSR that holds the trap‑vector configuration, consisting of a 4‑byte‑aligned base address (BASE) and a mode selector (MODE) that chooses direct or vectored handling of supervisor traps. The register is readable and writable in machine and supervisor privilege, while any access from user mode triggers an illegal‑instruction exception. Writes to BASE are WARL; the CSR stores only the upper bits of the address, implicitly zeroing the low two bits, and no pointer‑masking is applied on write or when the address is used for trap delivery. During trap delivery the PC is set to BASE (or BASE+0x14 for a supervisor timer interrupt) according to the MODE field.

REGISTER: tdata1
SUMMARY: The tdata1 CSR configures hardware triggers, encoding the trigger type (e.g., TYPE = 6 for address‑match triggers) and a select field that determines whether the trigger matches instruction fetches (select = 0) or memory accesses (select = 1). Only machine mode may read or write tdata1; any access from supervisor or user mode raises an illegal‑instruction exception, while M‑mode accesses complete without exception and reflect writable fields such as TYPE but mask others like DMODE. Writing a trigger with TYPE = 2 is prohibited and aborts with an illegal‑instruction exception without changing the CSR, and a TYPE = 6, select = 1 trigger is legal only when the Zicboz extension is present (it fires a breakpoint exception on a matching access), whereas it is illegal under Zicbom or Zicbop. When a TYPE = 6, select = 0 trigger matches an instruction address, the processor must enter debug mode; failure to do so violates the specification.

REGISTER: tdata2
SUMMARY: The tdata2 CSR is a machine‑level read/write register that stores trigger‑related data (the DATA field). It is accessible only in M‑mode; any read or write from S‑ or U‑mode triggers an illegal‑instruction exception (mcause = 0x2). In M‑mode accesses generate no exception (mcause = 0x0), and writes to the DATA field are reflected on subsequent reads.

REGISTER: tdata3
SUMMARY: The tdata3 CSR is a machine‑mode register used for trap‑related data and is only readable and writable when the processor is in M‑mode. Reads from S‑ or U‑mode raise an illegal‑instruction trap (mcause = 0x2), while reads in M‑mode never trap, even when the Zicbom, Zicbop, or Zicboz extensions are present. Writes to tdata3 are masked or otherwise transformed; for example, writing the 64‑bit value 0xffffffffffffffff does not store that exact pattern nor its 32‑bit truncation 0xffffffff. Thus, the register's contents are implementation‑defined beyond the strict privilege‑based access rules.

REGISTER: time
SUMMARY: The TIME CSR (address 0xC01) provides a read‑only, monotonically increasing 64‑bit real‑time counter that increments by one each clock tick and is kept synchronized across harts to within one tick. It is an unprivileged‑read‑only (URO) register, readable by any privilege level when the TM bit is set in the appropriate counter‑enable register (mcounteren for S‑mode, scounteren for U‑mode) and always accessible in M‑mode. Attempts to read TIME in a mode where the TM bit is cleared, or to access the high‑half CSR (timeh) on XLEN ≥ 64, raise an illegal‑instruction exception, and any write to the TIME CSR is ignored and does not modify the counter. The counter cannot be inhibited by mcountinhibit; reads may initially return a stale value after an mtime update but will converge to the updated value after a finite number of cycles.

REGISTER: tselect
SUMMARY: The tselect CSR selects the active trigger group, with its low‑order INDEX field indicating the group number. It is readable and writable only in machine mode; accesses from supervisor or user mode raise an illegal‑instruction exception. In machine mode, writes are masked to the supported width so that oversized values (e.g., 0xffff…ffff) do not appear unchanged on readback, while setting INDEX = 1 is reflected on subsequent reads. Access remains exception‑free even when the Sdtrig extension is enabled.

REGISTER: vcsr
SUMMARY: The vcsr CSR records the vector fixed‑point rounding mode and the accrued saturation flag for vector operations. It is a user‑read/write register, but any access when the vector state (VS) is Off raises an illegal‑instruction exception; otherwise reads and writes succeed in M, S, and U modes. Writes only affect the defined rounding‑mode and saturation bits, and reading back returns those bits unchanged (masked writes of undefined bits are ignored). Accesses are permitted without exception when the V extension is implemented.

REGISTER: vl
SUMMARY: The vl CSR holds the current vector length (XLEN‑wide) that limits how many vector elements a vector instruction may process. It is writable only by the vset{i}vl{i} instructions and by fault‑only‑first load variants, which compute a new vl from the AVL operand respecting VLMAX, tail‑policy rules, the "vl ≤ AVL" constraint, zero‑AVL handling, and reduction on element‑faults; unsupported vtype values force vl to zero and group‑size requirements may raise an illegal‑instruction exception. The CSR is unprivileged and read‑only from software; any privilege mode can read it with a csrr instruction without causing an exception, while any direct write or violation of its update constraints triggers an illegal‑instruction trap.

REGISTER: vlenb
SUMMARY: vlenb is a read‑only unprivileged CSR that returns the vector register length in bytes (VLEN / 8). Its value is unaffected by changes to the VS field or any other configuration. The register may be read without raising an exception in M‑mode, S‑mode, or U‑mode, regardless of whether the V extension is active.

REGISTER: vscause
SUMMARY: The vscause CSR (0x242) records virtual supervisor‑mode trap information, providing an interrupt indicator and a cause code that can be written and subsequently read back. Access to vscause is permitted only in machine mode (or when the H extension is active), and any attempt from user mode triggers an illegal‑instruction exception. Writes affect only the defined fields; attempts to write an all‑ones value do not result in those bits being retained. Reading the register in allowed modes completes without raising an exception.

REGISTER: vsctrctl
SUMMARY: The vsctrctl CSR (0x24e) is a hypervisor‑read/write control register that selects virtualization behavior, providing a CUSTOM enable, privilege‑mode bits (S/U), and a collection of inhibit flags for jumps, calls, returns, interrupts, exceptions, and freeze controls. Access requires HRW privilege; any access from a mode less privileged than M when mstateen0.CTR = 0, or from U mode, triggers an illegal‑instruction exception (mcause = 0x2), while accesses in M mode (or when the H extension is active) complete without exception (mcause = 0x0). Writes are masked so that only the defined field bits are retained (e.g., writing 0xffffffffffffffff does not store the full value). All set bits are reflected on subsequent reads of the register.

REGISTER: vsepc
SUMMARY: The vsepc CSR holds the virtual supervisor exception program counter and is readable and writable only in hypervisor mode (HRW), while accesses in M‑mode succeed silently and accesses in U‑mode raise an illegal‑instruction exception. Its least‑significant bit is hard‑wired to zero, and when IALIGN = 32 the two low bits are forced to zero and reads mask bit 1 (including the implicit read performed by SRET), although software may still write that masked bit. Writes are masked so that values such as all‑ones are not retained, yet any permitted write to the PC field is reflected on a subsequent read. Accesses are legal when the H extension is active and generate no exception.

REGISTER: vsie
SUMMARY: The vsie CSR is the virtual supervisor‑mode interrupt‑enable register, holding enable bits for the standard supervisor interrupt types (SEI, STI, SSI, LCOFI) in a virtualized context. Its fields include these enable bits plus reserved/WPRI bits, all of which retain the written XLEN‑wide value on read (with any bits above XLEN masked off) while bits for unimplemented interrupt types read as zero. The register can be accessed without exception in machine and supervisor modes, but generates an illegal‑instruction exception in user mode, and this access behavior is unchanged by the presence of extensions such as H, Shlcofideleg, Smaia, Smcdeleg, Ssaia, or Sscofpmf. The vsie bits are consulted together with sip/hip and hideleg to decide virtual interrupt delivery to higher privilege modes, and writes of values larger than the XLEN are simply masked rather than causing undefined all‑ones results.

REGISTER: vsip
SUMMARY: The vsip CSR is a hypervisor‑read/write register that aggregates virtual interrupt‑pending flags, including the standard supervisor‑interrupt bits (SEIP, SSIP, STIP) and a set of "other standard" interrupt bits, plus a reserved WPRI field. It can be read and written without fault in M‑mode, S‑mode, and when the H extension (or related extensions) is enabled, but any access from U‑mode triggers an illegal‑instruction exception. Writes to defined bits are reflected on subsequent reads, while writes to undefined or reserved bits are masked and never expose all‑ones values. No other exceptions are generated for any permitted access.

REGISTER: vsiselect
SUMMARY: The vsiselect CSR (address 0x250) contains a single controllable field (VALUE) that can be set in M‑mode and read back unchanged, while writes of out‑of‑range patterns are not simply truncated. Access to the register is unrestricted in M‑mode regardless of the state of mstateen0[60] or any of the listed extensions, and no exception is generated. In any privilege mode less privileged than M‑mode, an access is illegal when mstateen0[60] is zero (or when the Smstateen extension is present and that bit is zero), causing an illegal‑instruction exception. All other extensions (H, Smcdeleg, Smcntrpmf, Smcsrind, Smctr, Smstateen, Ssaia, Ssccfg, Sscofpmf, Sscsrind, Ssctr, Ssstateen) do not affect this access control.

REGISTER: vsscratch
SUMMARY: The vsscratch CSR (address 0x240) holds the virtual supervisor‑mode scratch value used by hypervisor and supervisor software. It can be read or written without fault in M‑mode and S‑mode, and the same permissive behavior applies when the H (hypervisor) extension is present. Any attempt to access vsscratch from U‑mode triggers an illegal‑instruction exception (mcause = 0x2).

REGISTER: vsstatus
SUMMARY: The vsstatus CSR holds the virtual‑supervisor status for hypervisor operation, exposing fields such as VS (virtualization state), SD (summary dirty flag that mirrors VS when dirty), and groups of user‑mode, privilege‑mode and extension status bits (e.g., UXL, SPELP, MXR/SUM, XS/FS, SPP, UBE, SPIE/SIE). It is readable and writable in hypervisor (HRW) privilege and can be accessed from M‑mode without exception, even when the D, H, or W extensions are present, while any access from U‑mode triggers an illegal‑instruction exception. When a hypervisor virtual‑machine load or store instruction executes, the HS‑level SUM field is ignored. Writes to individual fields are reflected on subsequent reads, but a write of all ones does not force the register to all‑ones or all‑zeros.

REGISTER: vstart
SUMMARY: The vstart CSR (address 0x008) holds the architectural index of the vector element at which a trapped vector instruction should resume; hardware writes it on a trap, software can read or write it, and it is automatically cleared to zero at the start of every vector instruction (including vsetvl). It is a URW register accessible in M‑, S‑ and U‑mode unless the VS field is disabled, in which case any access causes an illegal‑instruction exception, and writes are masked to the implemented field width. Many vector operations that cannot safely restart with a non‑zero index (e.g., reductions, mask‑logical, vmsbf/vmsif/vmsof, and most crypto instructions) raise an illegal‑instruction exception when vstart ≠ 0 or when its value is not a required multiple of the element‑group size. When a trap occurs, vstart records the faulting element index, and precise‑trap semantics require that only elements with index ≥ vstart may be modified, matching the effect of restarting the instruction at that index.

REGISTER: vstval
SUMMARY: The vstval CSR records the trap value when a trap is taken into HS‑mode. It can be read without exception in M‑mode and S‑mode (and remains accessible when the H, Ssdbltrp, or Zicfilp extensions are active), but any access from U‑mode raises an illegal‑instruction exception; in M‑mode it may also be written and the written value is reflected on readback.

REGISTER: vstvec
SUMMARY: The vstvec CSR defines the supervisor trap‑vector address and mode, with a BASE field holding a 4‑byte‑aligned virtual or physical address and a MODE field selecting vectored or non‑vectored handling of synchronous exceptions into supervisor mode. It is readable and writable in hypervisor, supervisor, and machine privilege levels (no exception on access), but accesses from user mode raise an illegal‑instruction exception. Writes to the BASE and MODE bits are reflected on readback, while undefined values are masked to a legal WARL encoding; when MODE is vectored, a synchronous supervisor‑mode exception sets the PC to the BASE address.

REGISTER: vtype
SUMMARY: The vtype CSR holds the vector configuration, encoding the selected element width (SEW) in the vsew field, the register‑group multiplier (LMUL) in the vlmul field, the tail‑aggressive (vta) and mask‑aggressive (vma) control bits, and a top‑bit vill that marks an illegal setting. It can be written only by vsetvl/vsetvli/vsetivli instructions (which also update the vl CSR); any reserved encoding or a set vill bit causes an illegal‑instruction exception, and unsupported settings force vl to zero. The CSR is unprivileged read‑only (URO) when the vector extension is active, but reads and writes are allowed in M‑, S‑, and U‑mode; if the vector unit is disabled (VS = Off) any access raises an illegal‑instruction exception. Certain LMUL values impose alignment constraints on the base register (e.g., LMUL = 2, 4, 8 require bases multiples of the group size) and all reserved encodings are illegal, while non‑zero bits above bit 8 are reserved and must be zero.

REGISTER: vxrm
SUMMARY: vxrm is a vector CSR that selects the fixed‑point rounding mode used by vector scaling and other rounding operations. It holds a two‑bit field (vxrm[1:0]) that encodes four rounding modes (round‑to‑nearest‑up, round‑to‑nearest‑even, round‑down, round‑to‑odd) and this field is mirrored in bits 2:1 of the vcsr register. The CSR is URW, allowing read and write access from user, supervisor, or machine mode with no exceptions, and any write is reflected on subsequent reads.

REGISTER: vxsat
SUMMARY: The vxsat CSR holds a single saturation flag that is set when a fixed‑point vector instruction (e.g., vnclip) would overflow the signed destination format. It is a URW register, so it can be read and written from machine, supervisor, and user modes without generating an exception. Writes are masked to the least‑significant bit (higher bits are ignored), and the flag is also reflected in the vcsr register.
